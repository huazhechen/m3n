# 五线谱原生引擎替换记录

2026-11-25，五线谱生产路径已移除VexFlow及npm依赖。当前结构与规则见[五线谱显示](STAFF_NOTATION.md)。新引擎保留音乐语义与交互身份，允许合理的字形、间距、分行和页数变化，不要求旧SVG或坐标兼容。

`staff-engine.ts` 直接准备音高、时值、升降状态、和弦错位、倚音、拍组、调拍号及时间列。任务内共用不可变描述，每个候选拥有独立的坐标和连接锚点；符干、符杠、连音组与延音线随布局重算。谱行、歌词、附件避让和分页继续使用同一数值墨迹层，最后选中结果才序列化SVG。

52个固定音乐字形从实际分发的Bravura提取度量及独立轮廓边界。网页使用Bravura字符，PNG使用同源TTF轮廓，矢量PDF嵌入实际Bravura子集；字体度量和提取脚本纳入生成摘要及提交钩子。没有保留VexFlow回退路径。

## 验证

- 五线谱专项：15个测试文件、102项通过，覆盖节奏分组、弱起、连音组、临时记号与倚音、谱表高度变化、候选隔离、歌词、分页和跨行关系。
- 独立浏览器审计：107首曲目、1份独立作品及11个专项，共119个条目全部无渲染错误、越界或实际像素碰撞。报告：`.tmp/staff-layout-audit/verification-all/report.json`。
- 五首代表曲目基本功、枫、Flower Dance、K.545和Valsentino另保留SVG及截图；与11个专项均先于全库验收完成。
- 应用单元测试3个文件、25项通过，覆盖阅读位置、语义朗读与点击定位。
- 应用端14个五线谱场景验证覆盖硬换行、分页前后横向一致、等宽不改变字形尺寸、大谱表歌词、源码定位、播放高亮、移调、资源失败恢复、小节号与反复房子，以及PNG与矢量PDF导出。PDF额外检查嵌入Bravura字体且没有栅格图像。

渲染器输出每个小节的本地墨迹边界，应用据此建立透明点击区域，避免音乐字体行框造成越界和重叠。

SVG字体的 `getBBox` 包含字体行框及位置相关取整；尺寸回归改用独立Canvas在设计字号下测量真实字形墨迹，再按实际矩阵比较，不放宽横坐标或字号断言。

## 内存与隔离

开发在独立worktree进行，应用构建输出至独立 `.tmp/` 目录。所有重型验证串行，Node堆限制384MiB，测试单worker；聚合RSS监控覆盖其他worktree中的Node、浏览器和字体进程，发现并发任务时等待，达到阈值时停止自身进程树。

审计及选宽基准先在独立子进程打包，退出后才启动浏览器，避免保留打包器及字体缓冲；Playwright使用轻量静态服务。完成的专项测试峰值约740MiB，全库浏览器审计约1196MiB，早期PNG／PDF专项约1409MiB，最终14项浏览器串行验收峰值约1699MiB；早期导出专项监控阈值1600MiB；后续按用户指示将聚合硬上限调为3GB，监控停止阈值2600MiB，继续保留余量并串行验证。使用已安装的headless shell进一步减少浏览器占用。

旧性能报告的选宽耗时仅描述当时的VexFlow版本，不作为新引擎性能结论；本次未运行全仓库完整用例，也未重做全库多轮性能基准。

## 主线整合

合入时保留主线集中字号与布局配置、1～9档自动选宽及谱集封面／目录字体优化。原生引擎的和弦、连续休止计数测量沿用集中配置；浏览器专项使用当前有效宽度档位。字体子集与摘要根据合并后的完整输入重新生成。
