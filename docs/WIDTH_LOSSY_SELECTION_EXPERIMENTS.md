# 允许12px偏差的选宽试验

验收边界：相对于当前完整6px搜索，同曲、同谱式的页数不增加，选宽绝对偏差不超过12px；单线程选宽耗时不超过600ms。宽度范围仍为528～720px，字体代价仍绑定这个范围。最终输出继续使用原有精确几何和分页。两种谱式共用试验搜索策略，没有按曲目指定宽度。

前三种近似策略均未通过验收，已撤回对应试验源码。新增的跨宽度行几何复用仍为显式试验开关，正式路径仍完整精确搜索。逐曲结果见[CSV](WIDTH_LOSSY_SELECTION_EXPERIMENTS.csv)。源代码试验补丁及完整JSON留在独立工作树的`.tmp/staged4/`、`.tmp/sampled12/`、`.tmp/staged-bounds/`；这些临时目录不属于发布产物。

## 对照方法

沿用本分支117首冻结谱源，每种谱式一个浏览器、一份字体和文字度量缓存，逐曲串行搜索。基线是`.tmp/measurement-final/{numbered,staff}.json`，使用完整网格及可证明的安全剪枝。曲库批量时间包含此前曲目对引擎的预热，不能代替单曲首次打开时间。五线谱试验同时包含小节放置工作区复用，因此总提速不能全部归因于近似策略。

`tools/compare-width-selection.mjs EXACT.json TRIAL.json`检查完整报告、曲目集合、源摘要、字体摘要、页数、12px偏差和600ms门槛；任何不通过都会返回非零退出码。它只验证这批输入的实测边界，不能证明未知乐谱也满足边界。候选报告中的空越界／重叠数组属于生产测量口径，不代表额外执行了SVG墨迹验收。

第一种策略保留所有33档的横向调查，但将其页数暂视为1。实际最优经常在分页约束下改变断行及间距档位；横向靠前的窄版方案可能占用更多页，少量精测候选不能覆盖真正适合少页的中间宽度。单独测《基本功》时简谱467.2ms、五线谱519.4ms，分别选720px与720px，相对基线720px与708px恰好通过；全量对照则有74个组合不通过，不能以单曲结果推广。

12px网格不保证赢家只偏离6px或12px。断行、分页及评分均不连续，漏掉一个6px位置可能跳到很远的次优方案。简谱《卡农》642→672px、《月亮河》546→528px；五线谱《查尔达什》570→588px、《莫扎特K545》570→612px。这个试验从720向528搜索，访问顺序也使部分短曲无法尽早获得强赢家，简谱总耗时反而变大。

最后一种策略利用现有安全核心下界排除一定不能少页的宽度，显著减少误选，但下界故意省略了未解析的关系、附件和墨迹碰撞，不能把“可能一页”视为“确实一页”。追加下界计算也消耗时间，简谱仍有9首选宽超限、4首超时，故未继续扩大到五线谱。

## 保留的精确优化

五线谱候选现在在测量任务内复用私有小节放置工作区，重写音符锚点、符杠位置和谱表坐标；延迟绘制记录保留独立坐标。普通绘制仍分配独立模型。共享完整搜索、评分、分页和曲线均未改变。

117首五线谱总耗时34,259.9→32,556.2ms，约下降5.0%；《基本功》1,559.6→1,494.1ms；超过600ms的曲目16→14首。全部1,733组赢家／候选字段在1e-8容差内一致，包括相同源文件和字体摘要。该实测只能支持保留工作区复用，不能声称已完成600ms目标。

验证包括完整score-renderer测试、工作区跨宽度／档位／低音高度复用后的延迟SVG与墨迹一致性，以及全曲目数值对照。峰值项目进程内存低于2GB；构建、测试、浏览器和字体生成串行运行。

## 新规则下的整行编译复用（显式试验）

当前试验保留33档搜索，候选阶段将同一行的完整纵向几何编译为模板：

- 模板只保留不可变分页块，不再复制不会被恢复的整行音符快照。原近似路径910组赢家／候选在1e-8容差内一致，峰值项目RSS从1453降至1321MiB；耗时收益较小，未据此声称完成性能目标。
- 普通测量也保存首次行模板。整份断行方案的模板齐全后，直接变换横向墨迹并进入共享分页，不再复制音符工作区或重复放置关系。候选模板还复用关系纵向高度，忽略随宽度变化的关系端点依赖；这只在显式试验中允许，最终精排关闭开关。
- 候选阶段直接分页，省略通常比模板分页更昂贵的静态可行性筛查；完整精确路径仍保留安全下界。保留33档枚举及共享外层评分剪枝。
- 两种谱式共享的分页早退出门槛从 `max(0.6,2×横向最优代价)` 收紧为 `max(0.6,1.5×横向最优代价)`。0.15绝对门槛也试过，但对低绝对代价的长曲增加了不必要的求解开销。

## 跨间距档位复用与包围盒修正（显式试验）

本轮保留全部33档、原评分和最终精排，增加 `--cross-tier`：同一行在紧、松两档之间复用候选纵向模板，横向约束和评分仍按当前档位计算。两种谱式使用共享的模板键策略；键仍保留音乐身份、小节片段和非间距设置。五线谱任务内的完整小节及已驻留分片使用对象身份编号，避免每行反复序列化所有事件。该近似只在 `--row-reuse --cross-tier` 下启用，最终复核和正式入口不使用它。

修复一处五线谱候选的包围盒处理：原先将整行 `ink`／`core` 总包围盒也送入12px分格，再取第一个格子，不仅截断横向边界，还为每行每档分配大量立即丢弃的盒子。现在直接仿射变换总包围盒，细分墨迹继续分格；共享测试验证分格开启时仍保留完整总边界。另将共享间隔评分合并为单次遍历，保留每个间隔独立计价、零代价参与平均以及原加法顺序，移除临时偏差数组。

基准构建新增 `--external-fonts --minify`。原Vite库模式把包括完整中文TTF在内的备用字体内联到26,548,850字节JS中，尽管实际测量安装的是三字体共享包。新模式将真实字体资源外置并保持可加载，脚本约1.4MB；继续记录并核验相同共享字体和谱源摘要，没有替换字体度量。生产网页本来就压缩脚本并外置字体，故这属于测量环境修正，不能全部计作排版算法提速。此前CPU记录开头约219ms的 `(program)` 样本发生在选宽调用之前，不属于 `searchMs`，不能据此归因为选宽内部编译耗时。

本轮同时修复延迟 `complete()` 的阶段计时：编译模板提前返回时，原计时器会将其他档位中途准备的时间重复累计到纵向分页。新测试使用仅文字测量递增的假时钟检查独立阶段之和。此前整次 `searchMs` 没有重复计时，修复不改变性能验收口径。
