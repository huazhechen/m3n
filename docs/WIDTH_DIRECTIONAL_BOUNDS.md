# 附件单向界限与精确行准备

这是独立工作树 `perf/lossless-width-v2` 中、基于 `82dfbecd` 的无损试验。宽度调度沿用显式 `--prepared-search` 基准入口，尚未把这一调度入口切入阅读器。完整单线程、两种谱式全曲库均不超过600ms的目标仍未实现。

## 安全界限

五线谱单谱表的音乐先完成横向定位。方向文字、和弦、指法、力度、速度、反复及八度文字中，能够锚定到局部音乐的附件，可在完整附件整理前提供单向界限：

- 上方附件从局部音乐上沿开始避让，后续碰撞只会将它继续向上推。因此初始上沿是最终上沿的上界。
- 下方附件从局部音乐下沿开始避让，后续碰撞只会将它继续向下推。因此初始下沿是最终下沿的下界。
- 只用固定音乐的子集锚定，会进一步放松界限。跨行的连线、歌词、重复结尾等尚未整理的图元可以省略，不能据此增加下界。

每行分别输出 `topInk` 和 `bottomInk`。相邻行碰撞只读取上一行的下沿通道和下一行的上沿通道；不能拿预测的上方附件下沿或下方附件上沿作相反方向的约束。页边界同样使用独立的乐观上、下沿。精确分页、碰撞间距和总代价比较继续使用共享实现，不增加另一套分页算法，也不改变三档动态规划断行。

上、下沿约束的水平跨度必须包含于对应的实际图元。预检查与完整整理共用附件间距规则和内联标题实际缩进计算，包含标题首尾空白处理；使用同样的水平限位。证明几何的横向区间内缩、纵向界限放松1e-7px，以覆盖坐标变换组合的浮点尾差；最终图元、曲线、间距和评分不做量化或改动。会重新换行的过宽附件不提供此约束。

共享 `scoreCorePageLowerBound` 仍默认使用原核心／页边界规则，保持原浮点计算顺序。启用单向通道后，按需读取行块，当前缀页数已经超出可胜出页数上限时停止。附件界限无法建立时，继续精确完成；异常不是淘汰证据，取消信号仍正常抛出。

## 准备与完成的生命周期

预检查与精确整理使用同一批已生成音乐图元。没有被证明淘汰的行，从歌词连接、连线和附件整理阶段继续执行，避免再次定位和绘制音乐。暂停的行拥有自己的小节模型及音符锚点，不借用可能被另一个宽度覆写的定位工作区；完成结果只生成一次。

实测短行计划的额外证明成本大于节省，因此只对至少16行的单谱表计划启用这项额外检查。该门槛只控制是否做额外证明，短计划和双谱表仍直接完成原有精确布局，不省略候选、不改变结果。简谱与五线谱共用下界／分页实现；本轮仅五线谱适配器提供新的附件单向几何。

v100中《基本功》五线谱1260.1ms，对照1585.9ms；仍有22首超过600ms。该改动只带来有限整体收益，不能声明解决性能目标。简谱复测36567.0ms、11首超过600ms；与v93的36358.7ms相比没有证明提速，不把单曲跨过阈值归因于这项五线谱优化。

两种谱式各117首赢家宽度、页数和行数不变；五线谱254个、简谱341个共同完成候选的评分在1e-8内一致。报告位于 `.tmp/lossless-v2/v100-{staff,numbered}-comparison.json`。回归直接比较暂停／继续与一次完成的SVG及逐图元几何，并在中间准备其他宽度，验证锚点隔离；还逐项检查界限图元的水平跨度及单向纵坐标确实包含于完整行，覆盖三首真实谱例、多宽度、三档间距、标题、连音组和复杂附件。随机分页检查验证单向界限不会多算页数。

最后补充了内联标题首尾空白的水平跨度检查，以及附件界限抛错后回退精确候选的检查。最终版本验证及复测结果见后续记录。

最终v102五线谱复测40585.5ms，对照41494.2ms；《基本功》1299.3ms，对照1585.9ms，仍为618px／3页／33行。仍有23首超过600ms，门槛附近的个别曲目波动不能视为算法收益。117首赢家及254个共同候选评分保持一致，报告 `.tmp/lossless-v2/v102-staff-comparison.json`。此前v101验证主动中止以修正内联标题界限，不作为完整验收。

最终验证通过：类型、架构边界、lint、字体生成物；270文件／2261项离线用例、全部工具／字体检查、23项浏览器用例和双谱式密度回归。验证串行执行，聚合RSS峰值1202MiB，日志 `.tmp/lossless-v2/v102-verification.log`。归档字体字节不变，生成结果仅更新雕版输入指纹。

## 下一步的界限强度诊断

v103在同一基本功输入上比较完整固定音乐与仅谱表线的单向约束。95次预检查，前者88次能够淘汰完整整理，后者56次；两者赢家及两个共同候选评分一致。后者仍先生成了完整音乐，因此1470.8ms不是“省掉音乐生成”的性能结果。诊断补丁已恢复，包已重建，报告 `v103-{music,rules}-caption-staff.json` 及严格对照 `v103-caption-proof-comparison.json`。

这说明继续减少界限计算成本时需要保留部分音符几何。当前 `appendStaffGlyphInk` 已经直接平移缓存的字体设计盒子，不会逐音符求解字形曲线；不能把历史路径轮廓热点直接套到当前音乐字体上。下一步可先衡量仅保留音头、符干等固定图元的界限强度，再决定是否拆开小节定位与图元发射，给存活行按需补齐完整音乐；最终曲线和排版仍须精确完成。
