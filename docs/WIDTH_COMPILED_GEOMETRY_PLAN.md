# 600ms目标：候选排版执行架构重构方案

状态：实施中，整体目标尚未完成。普通五线谱音乐的数值执行记录及首轮全量证据见[迁移实测](WIDTH_NUMERIC_RUN_PERFORMANCE.md)。简谱测量工作区的中间结果见[测量与绘图分离](WIDTH_MEASUREMENT_ARENA_PERFORMANCE.md)。按行执行及其余步骤仍待完成。2026-11-27，独立工作树 `perf/single-worker-600`。延迟投影复制已提交为 `4330103a`。

## 为什么转向结构重构

冻结117首、相同真实TTF及排版规则下，最新无采样简谱两批累计24.452／24.258秒，基本功1341.1／1324.4ms，6首超600ms；五线谱最近两批累计36.186／36.182秒，基本功1707.9／1698.8ms，17首超600ms。把基本功降到600ms，分别还需约55%和65%的削减；百分之几的局部优化不足以支撑目标。这些基线不是最新主线验收。

最新简谱CPU采样 `.tmp/deferred-basic-numbered.cpuprofile` 中，候选完成路径包含785ms，候选准备227ms，贪心页数上限测量225ms，GC145ms。包含时间互相重叠，不能相加；采样耗时不作为600ms验收。附带全量报告 `.tmp/deferred-profile/numbered.json` 的892组赢家／候选与无采样报告一致，误差阈值1e-8。五线谱既有采样显示精确行构造、附件整理和树形几何收集占主要时间，见 [既有采样及失败实验](WIDTH_COLLISION_SPLIT_PERFORMANCE.md)。

共同问题是候选搜索仍过度依赖完整、可绘制的布局对象：为获得几行精确几何，反复准备整曲对象、绑定音符身份、构造节点、遍历树并复制墨迹。现有缓存已覆盖很多相同输入；下一步应减少一次候选必需执行的工作。

## 目标执行链

谱源／字体 → 一次性不可变音乐及几何准备 → 按需行数值执行 → 共享断行／分页／评分 → 赢家绘制。

### 1. 按行执行，取消候选阶段整曲放置副本

保留现有共享求解器，先将其 `evaluate(ends)` 的几何依赖改为按行取得不可变 `ScorePageBlock`。候选只保留断行端点、行引用、页数与评分。贪心上限、乐观细化、前缀回退和最终候选共用同一行结果，重复取得不触发整曲 `complete()`。

简谱局部行几何直接从不可变准备中读取音符和关系索引，在行工作区放置目标行；不为行外小节生成私有放置对象、系统列表和控制符副本。行外关系端点通过预编译依赖提供原有精确上下文。只在最终绘图需要时组装赢家的完整布局。

须保持原有贪心页数上限及其精确测量语义；不能用更松上限、不同分页或较少候选降低耗时。

### 2. 将几何操作与SVG树分离

提供共享数值输出接口，直接写入核心、逐元素墨迹、固定附件和页边界通道。五线谱不再通过 `XmlNode → SvgGeometry.collect → 数值盒子` 获得搜索几何。简谱也使用同样输出契约。

适配器提供音乐规则及精确图元操作：字形设计轮廓、直线、实际曲线极值、文字度量和附件依赖。共享运行时负责可复用的坐标工作区与结果存储。曲线和避让规则保持现有精度；不以包络近似替代曲线，不把搜索几何改成整行矩形。

绘图和搜索必须消费同一套已求得的图元与位置，避免维护两份几何规则。允许按模块迁移，但最终生产候选路径应停止构造SVG树；旧路径仅在迁移期作差分验证，完成后删除。

### 3. 跨宽度复用执行准备，而非复用旧位置

对实际访问的小节跨度编译行执行描述，保存音符／控制符索引、间距约束、关系端点、字形模板和附件依赖。换宽只执行坐标及确实依赖宽度的避让计算，使用复用的数值工作区；避免重新建立对象图和语义索引。

不预计算所有跨度与全部宽度的笛卡尔积。精确行结果必须包含实际版宽、间距档位、断行分片、段尾继承间距及所有关系外部依赖；描述复用不意味着不同宽度共享几何结果。先保留原有浮点运算顺序及取整位置，不擅自把坐标计算代数化，以免改变临界分页。数组布局和容量应由实际分配量决定，不能只因使用TypedArray就宣称提速。

## 实施顺序与决策门槛

1. 记录各慢曲的候选完成次数、独立行数、行外复制量、树节点及墨迹分配量，建立两种谱式相同的阶段计时。选择基本功、K545及包含歌词／跨行关系的慢曲作为结构原型验证集。
2. 先打通按行数值求解与赢家组装，验证贪心／细化／回退共用行结果。验证集整次完整搜索若没有明显下降，应先核查剩余整曲路径，不继续以几毫秒局部收益扩展方案。
3. 优先迁移五线谱音符、谱表、符梁和三连音到直接数值输出，再迁移歌词、关系与附件整理。同步迁移简谱行工作区。每一模块保留精确图元差分测试及真实字体结果对照。
4. 完成执行准备复用后，对全库两种谱式各跑完整批次及复测。消除仍走旧候选路径的热点。只有实测支持才保留更复杂的数据结构；如求解器本身成为主要耗时，再针对共享状态展开做结构调整。

阶段预算暂按准备75ms、行几何300ms、共享求解及评分175ms、其余50ms倒推，总计600ms。这是设计约束，不是收益预测；各阶段必须采用互斥计时，最终以整次选宽计时为准。

## 不可改变的验收条件

- 单Worker，完整528～720px的33个6px档位与已有严格安全剪枝；不重新引入局部搜索或搜索数量上限。
- 共享选宽、断行、分页求解和评分；谱式适配器只提供音乐规则与精确几何。
- 同源、同字体、同规则下，两种谱式全部赢家及共同候选的宽度、页数、断行和评分一致；数值误差门槛保持既有1e-8，另验证原语及完整SVG几何。
- 完整真实字体批次无额外预热、无profiler，不以分位数或平均数替代逐曲600ms。最终同步已提交主线规则和谱源后重新全量验收。
- 全部项目进程内存低于2GB，重任务串行，持续聚合内存守卫。缓存限制只限制存储，不能丢弃尚可能胜出的候选。

在这些条件被实际证明之前，600ms目标保持未完成。
