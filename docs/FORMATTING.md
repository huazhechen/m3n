# 格式化器

格式化只整理等价写法与文本布局，不改变谱面中的音符划分、延音、休止符、手动换行或文字内容。入口为 `packages/notation/src/m3n-format.ts` 的 `formatM3N(source, context?)`，编辑器与批量工具共用该入口。

## 模块职责

| 模块 | 职责 |
| --- | --- |
| `formatting/groups.ts` | 保持逐个事件的音高、实际时值和延音关系，抵消冗余括号与增时符，按拍组织纯音符括号 |
| `formatting/layout.ts` | 行标签、指令以外的空白、空行与冗余小节线整理 |
| `formatting/lyrics.ts` | 根据旋律对位目标重建歌词小节线，整理占位符 |
| `formatting/text.ts` | 识别行尾注释，保护指令值和括号内歌词文字 |
| `formatting/shared.ts` | 源码范围编辑、书写小节遍历、拍组计算与单个事件的等价时值拼写 |

音乐整理以 `ScoreDocument` 的事件时值、拍号和源码范围为依据；行范围来自 `M3NSyntaxTree`。旋律、低音和替代旋律使用同一套规则。调用方可传入与原文一致的分析上下文。

## 处理顺序

1. 将换行统一为 LF。
2. 整理等价括号与时值写法，保持每个事件的时值与延音关系。
3. 统一行标签与指令以外的空白，整理冗余小节线，保留 `{br}`。
4. 根据旋律重建歌词小节线。

格式化不再拆分跨强拍的长音，也不合并同音延音或连续休止符。例如 `3 (4) 5. 3`、`1~ 1` 和 `0 0` 均保留原有事件划分。发声相同不足以证明谱面相同：拆音或合并会改变可见音符、延音线和间距，因此不属于格式化职责。

## 规则与边界

- 括号每层的减时效果必须计入实际时值。例如 `(1^)` 和 `((1^^))` 可简化为 `1`。
- 四分音符以下保留所需括号；同拍相邻短音可以合并括号，如 `((1)) ((2)) ((3)) ((4))` 变为 `((1 2 3 4))`，仍是四个事件。
- 普通拍子按分母单位分组；6/8、9/8、12/8 按三个分母单位分组，读取当前拍号与小节内实际偏移。例如 6/8 的 `(1 2 3 4 5 6)` 变为 `(1 2 3) (4 5 6)`。
- 含复杂标记、无法整体解释的括号保留整个作用域；和音、连音组和倚音不参与纯音符括号重建。
- 标题、注释与指令值中的连续空格、`|`、`{br}` 保留为原始文字；实际的 `{br}` 同样保留。
- 歌词保留英文单词分隔与括号内文字，保留无歌词目标的空小节，如 `甲乙 | | 丙丁`。只有真正的占位符 token 才展开。
- 重建歌词小节线前先归一化其移除后留下的空白，保留英文词界并消除中文间的多余空格；行标签后的空白固定处理，避免空歌词首小节在重复格式化时累积空格。

格式化不会补写缺失音符、修复反复结构或重写歌曲内容。非法或无法安全改写的片段应交给诊断与作者处理。

## 验证

`packages/notation/src/m3n-format.test.ts` 检查具体规则、逐个事件保持和重复格式化稳定性。`src/lib/score-formatting.test.ts` 对全部内置曲谱检查诊断、逐个事件及标记、手动换行、歌词和演奏结构，同时比较 MEI；不再通过合并发声片段掩盖音符划分变化。

`node tools/verify-format-rendering.mjs` 使用真实浏览器，在当前 jpFun 与自研引擎中分别比较原文和格式化结果。覆盖全部内置曲谱以及回归用例、320/600/800/1000px、连续与分页模式，要求同引擎输出的 SVG 完全一致，报告写入 `.tmp/format-rendering/report.json`。它直接读取当前曲谱，不冻结曲谱或修改渲染坐标断言。

批量工具 `npm run build -w @m3n/notation && npx tsx tools/format-m3n-sources.mts` 在写入前检查 MEI 不变、诊断不增加、结果稳定。需保留教学源码写法的谱例仍可使用 `<!-- m3n-format: preserve — 保留原因 -->`，但手动换行与延音语法本身无需豁免。
