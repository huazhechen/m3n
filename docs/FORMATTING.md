# 格式化器

格式化的目的，是让等价的音乐采用清楚、稳定的写法：简化括号、按拍分组、统一时值表示、清理冗余，再整理文本布局。入口为 `packages/notation/src/m3n-format.ts` 的 `formatM3N(source, context?)`，编辑器与批量格式化工具共用该入口。

## 模块职责

| 模块 | 职责 |
| --- | --- |
| `formatting/groups.ts` | 在保持实际时值的前提下抵消括号与增时符，并按拍重新组织纯音符、休止符的括号 |
| `formatting/rhythm.ts` | 独立的强拍拆分与冗余合并规则，处理延音和连续休止符 |
| `formatting/layout.ts` | 行标签、空白、空行、小节线与手动换行标记的整理 |
| `formatting/lyrics.ts` | 根据旋律对位目标重建歌词小节线，并展开、重压缩占位符 |
| `formatting/text.ts` | 识别行尾注释，保护指令值和括号内歌词文字，供其他模块共享 |
| `formatting/shared.ts` | 源码范围编辑、书写小节遍历、拍组计算与统一时值拼写 |

音乐改写以 `ScoreDocument` 的事件时值、拍号、区间端点和源码范围为依据；行范围与括号深度来自 `M3NSyntaxTree`。旋律、低音和替代旋律使用同一套规则。调用方可以传入与原文一致的分析上下文；任何改写使源码位置变化后，后续阶段都重新解析。

## 处理顺序

1. 将换行统一为 LF。
2. 简化既有括号与时值写法，让后续规则看到一致的音符深度。
3. 拆分跨越强拍的弱位长音，用延音保留原始发声。
4. 简化拆分产生的括号，供合并规则使用。
5. 合并不遮蔽节拍、可用单个时值表示的延音或连续休止符。
6. 重新按拍组织括号，消除合并产生的冗余层级。
7. 统一行与空白，清理音乐行中的冗余小节线和实际 `{br}` 指令。
8. 根据最终旋律重建歌词小节线。

拆分先于合并，使一次格式化就能得到稳定结果。例如长音拆到小节中点后，其后半段与紧随的同音延音可以在本次调用中合并。分组规则是可重复使用的独立阶段，不依靠反复运行整个格式化器直至收敛。

## 规则与边界

- 括号每层的减时效果必须计入实际时值。例如 `(1^)` 简化为 `1`，`((1^^))` 同样简化为 `1`；不能直接删除括号而保留增时符。
- 四分音符以下的时值保留所需括号；同一拍内的相邻短音合并书写。例如 4/4 中 `((1)) ((2)) ((3)) ((4))` 变为 `((1 2 3 4))`。
- 普通拍子按分母单位分组；6/8、9/8、12/8 等复拍子按三个分母单位分组。分组读取当前拍号和小节内实际偏移，行内变拍、低音行与替代旋律也如此。例如 6/8 的 `(1 2 3 4 5 6)` 变为 `(1 2 3) (4 5 6)`。
- 偶数普通拍子的弱位长音跨越小节中点时拆分；复拍子的弱位长音跨越下一个附点拍边界时拆分。已经从强位开始的长音保留。所有拆分都相对于当前括号深度计算时值。
- 合并不能跨小节。普通偶数拍保持小节中点可辨，复拍子保持附点拍边界可辨；总时值不能准确拼写时保留原文。
- 区间端点上的事件保留，防止连奏、渐强等区间缩成单个事件。带标记的事件不通过裸音符替换吞掉标记；含 `+` 强制延音歌词的文档保留延音事件划分。
- 含复杂标记、无法整体解释的括号保留整个作用域；不单独改写内层而丢失外层的减时效果。和音、连音组和倚音不参与纯音符括号重建。
- 注释和指令值中的 `|`、`{br}` 等字样作为文字保留。延续原有约定，普通指令值中的连续空格会压为一个；括号歌词中的文字空白保留。
- 歌词小节线重建时保留英文单词分隔，保留无歌词目标的空小节，如 `甲乙 | | 丙丁`。只有真正的占位符 token 才展开，括号歌词和注释中的 `%` 保留。

格式化不会补写缺失音符、修复反复结构或重写歌曲内容。非法或无法安全改写的片段应交给诊断与作者处理。

## 验证

`packages/notation/src/m3n-format.test.ts` 覆盖具体规则、已复现缺陷和多种拍号下的组合节奏，检查时值与重复格式化的稳定性。`src/lib/score-formatting.test.ts` 对全部内置 `.m3n` 乐谱逐一验证：诊断不增加、音高与发声时值一致、歌词及演奏结构保留、再次格式化结果不变。持续扩充规则时，应同时加入具体反例和整库检查。
