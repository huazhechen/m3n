# 不可变墨迹复用与直接收集分页图元

2026-11-27，在独立 worktree `perf/single-worker-600` 中，以 `0e04b5a6` 为基线。包含当前7px五线谱谱间、0.6／1.8谱间双档及房子线普通跨行净空修复。两种谱式仍完整覆盖528～720px的33个6px档位，只保留有证明的安全剪枝；单Worker、评分、精确曲线和分页规则不变。

共享几何层对明确声明不可变、且已在零基线坐标系中的行块，复用图元对象；排序仍使用私有数组。默认可变查询继续复制图元，非零基线仍按原运算平移。边界碰撞的图元集合去除重复对象引用，重复图元不会加强最大净空约束。

五线谱候选行仍使用数值绘制，但立即收集完整分页图元。这些行随即用于精确分页，延迟收集会先额外遍历一次墨迹求边界；没有附件的行还会先进入延迟路径，随后重新进入完整放置。现在直接执行原完整放置与收集。其他延迟绘制调用保持原有默认行为。没有新增搜索或分页算法。

## 全量实测

每批117份谱源，一个新Chromium和真实归档TTF；批内共享字体、文字度量，不预热、不采样、不生成最终SVG。基线与优化批次字体摘要和逐曲谱源一致。重任务串行，Node堆384MiB、浏览器堆256MiB、1700MiB聚合RSS守卫；四批最高峰值1483MiB。

| 谱式 | 基线累计 | 本轮累计 | 基本功基线／本轮 | 超600ms基线／本轮 |
|---|---:|---:|---:|---:|
| 简谱 | 25.216秒 | 25.143秒 | 1409.4／1428.3ms | 7／7 |
| 五线谱 | 46.370秒 | 45.588秒 | 2125.9／2000.8ms | 30／29 |

五线谱累计降低约1.7%，基本功降低约5.9%；简谱变化很小，不能据此认定提速。单批结果包含正常测量波动，不能声称每首均加速。**所有曲目、所有谱式600ms目标仍未达成。** 超时曲目及逐曲数据见[CSV](WIDTH_INK_REUSE_PERFORMANCE.csv)。

简谱892组、五线谱1922组赢家／共同候选的宽度、页数、行数、物理间距统计及各评分分量保持一致，绝对误差阈值1e-8。原始报告位于此工作树 `.tmp/baseline/{numbered,staff}.json` 与 `.tmp/borrow-eager/{numbered,staff}.json`。

五线谱24个文件237项、共享布局12个文件75项通过，包括新增的即时／延迟图元收集精确几何及SVG一致性回归，覆盖普通音符、低音、歌词、三连音与渐强。共享碰撞回归核对随机图元的穷举结果、点状规则、无限谱头、可变输入隔离和不可变对象复用。

## 后续瓶颈

五线谱基本功CPU采样中，行绘制、几何遍历、实际分页和GC仍占主要部分；本轮没有用较少候选或简化图形换取速度。下一步需要继续减少候选行的完整雕版及分页重复工作，同时保持所有可能获胜方案与精确墨迹。

复现先运行 `python3 tools/run-low-memory.py npm run build:packages`，再串行运行：

```sh
python3 tools/run-low-memory.py node tools/benchmark-numbered-spacing.mjs --numeric-layout --prune --output=.tmp/borrow-eager/numbered.json
python3 tools/run-low-memory.py node tools/benchmark-numbered-spacing.mjs --staff --prune --output=.tmp/borrow-eager/staff.json
```
