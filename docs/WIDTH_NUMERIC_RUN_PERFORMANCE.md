# 五线谱候选音乐改为数值执行记录

2026-11-27，独立工作树 `perf/single-worker-600`，基于 `572da13b`，开始落实[执行架构重构方案](WIDTH_COMPILED_GEOMETRY_PLAN.md)的数值几何部分。冻结117首谱源、真实归档TTF、同一排版规则，单Worker、528～720px全部6px档位及严格安全剪枝不变。共享断行、分页和评分没有改动。

## 执行路径变化

普通音符直接通过一个输出器追加精确字形、符干、加线及奏法墨迹，不再为每个音符分配数值节点、绘图闭包和音符对象快照。连续事件共用一份数值执行记录，保存坐标与事件／子音符索引；仅输出赢家时生成事件包装和实际图元，保留原SVG顺序、ID、rendition与交互属性。

同一音符几何函数负责数值与绘图输出，不复制音乐几何规则。紧凑坐标记录使原绘图模型即使换宽复用，旧候选仍能输出原来的精确图形。逐元素墨迹及原有0.001px直线路径取整保持不变。

显式按音符ID、音符／休止类别过滤时，才按需产生语义几何子节点；静态编译后的过滤也检查这些真实后代。生产的附件／歌词排除查询可直接读取整段精确墨迹，不构造语义树。

这只是执行架构迁移的第一段。三连音标签、谱头、关系与附件整理仍使用原有流程；含临时调号、倚音或琶音的事件仍沿用既有完整绘图路径。简谱整曲放置副本尚未在此修改中移除，不能称作已完成整套无树候选架构。

## 两轮全库实测

每批新建Chromium，不额外预热、不开profiler、不生成最终SVG；批内共享字体度量。所有重任务串行，通过1700MiB聚合RSS守卫，Node堆384MiB、浏览器堆256MiB。

|---|---:|---:|---:|---:|
| 117首累计选宽 | 36.186秒 | 36.182秒 | 33.894秒 | 34.287秒 |
| 基本功 | 1707.9ms | 1698.8ms | 1530.1ms | 1543.7ms |
| 超600ms曲目 | 17 | 17 | 16 | 16 |

两批累计均值降低约5.8%，基本功均值降低约9.8%。这些差值是整个数值执行修改的结果，不能分别归因于某种数组或输出器。内存峰值本次较低，但仍需更多场景验证，不能推断普遍内存保证。逐曲数据见[CSV](WIDTH_NUMERIC_RUN_PERFORMANCE.csv)。

两批各1733组赢家／候选与基线在1e-8以内一致，包含实际请求宽度集合、页数、行数、物理间距及全部评分字段；谱源与字体摘要相同。原始报告为 `.tmp/direct-line-ink/staff.json`、`.tmp/direct-line-ink-repeat/staff.json`、`.tmp/numeric-run/staff.json` 和 `.tmp/numeric-run-repeat/staff.json`。
