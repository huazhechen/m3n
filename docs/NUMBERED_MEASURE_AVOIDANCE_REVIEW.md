# 简谱小节矩形避让选宽试验

同一份9f17a64e谱源、117份简谱、8／16px双档、字体系数4、生产宽度剪枝及6px局部细搜。整行与小节模式均改用最小间距独立测高，并保留实际行上下界校正。单浏览器与共享字体／文字度量；不执行截图、碰撞或越界审计。

| 模式 | 搜索耗时 | 整批耗时 | 总页数 | 总行数 |
|---|---:|---:|---:|---:|
| 整行 | 27.673秒 | 32.675秒 | 124 | 1187 |
| 小节矩形（含预测失配后的实际分页重解） | 45.113秒 | 50.344秒 | 124 | 1187 |

116份最优宽度不变；只有示例《欢乐颂》从600px到594px，仍1页5行。全部曲目的最优页数、行数不变。小节模式搜索慢约63%。完整逐曲结果见 [CSV](NUMBERED_MEASURE_AVOIDANCE_REVIEW.csv)。报告保存在 `.tmp/numbered-measure-whole/current.json` 和 `.tmp/numbered-measure-final/current.json`。

小节模式对每个候选行按横向实际分配求小节矩形，缓存高度围绕音乐中心对齐，核心上下取最大值。非核心仅对横向相交的小节矩形施加0.3倍核心间距；此前所有行均参与约束。跨小节曲线和文字会扩展被其覆盖的小节矩形。外置连接符等归入最近小节，不能丢失。

整行完整包络不能用作小节模式拒绝剪枝的下界，试验改用纯核心下界。独立小节完整高度仍是近似值；最终矩形以实际行内排版为准。预测与实排页数不同时，重新以实际几何求解该档的贪心页数约束。19个宽度／档位触发此修正，涉及14份谱源。实际重解可能改变横向代价，实验模式停用依赖原计划代价排序的提前跳档及横向质量拒绝，保留安全字体剪枝和局部搜索；因此耗时差也包含这些变化，不能全归于矩形分页本身。

初版未复核时，《星星点灯》出现558px预测2页、实排3页，错误退选552px。加入实际分页复核后恢复558px。具体原因主要是歌词整行对齐：紧档第10行的第25小节独排音乐下沿4.20px，合入第27小节后整行下沿变13.08px；第25小节两层歌词基线均下移8.88px，底边70.28→79.16px。缓存缺少歌词行级基线重算。最小间距测高不能消除这种依赖。应拆分缓存音乐下沿与各歌词层字形上下界，合行时用标量重算；本试验没有改歌词对齐规则。

《欢乐颂》594px在小节模型及实际复核下可使用松档5行1页，间距代价0.433491、字体代价0.3025、总分0.735991；整行模式600px的对应值0.411843、0.36、0.771843。它不是减少行数或页面的收益。

此处整行对照已包含最小间距测高和实际上下界修正，与更早 `.tmp/font4-tail-production/current.json` 不同；不能把这两个修正造成的历史宽度变化算成小节避让收益。Fly Me to the Moon谱源也已包含Coda修正。

默认仍为整行。小节模式显式使用 `measureAvoidance:true`（自动启用高度缓存），命令：

```sh
python3 tools/run-low-memory.py node tools/benchmark-numbered-spacing.mjs --prune --local-refine --row-envelope --output=.tmp/numbered-measure-whole/current.json
python3 tools/run-low-memory.py node tools/benchmark-numbered-spacing.mjs --prune --local-refine --measure-avoidance --baseline=.tmp/numbered-measure-whole/current.json --output=.tmp/numbered-measure-final/current.json
```

验证：包构建通过，新高度包络／首行文字净空／跨宽度缓存／错开矩形测试6项通过。附加两份旧测试有5项失败，已在未改动的master复现相同数值（隐藏小节号测量计数4项、器乐括号占宽1项），未修改这些旧断言。完整简谱测试运行已中止，不能声明全套通过。此前五线谱迁移的394项测试通过，见迁移报告。
