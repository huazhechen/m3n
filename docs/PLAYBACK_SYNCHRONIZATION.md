# 播放跳转与节拍器同步

## 时间基准

MIDI 和节拍器使用同一份 MIDI 速度图；调度读取 `Sequencer.currentTime`（音频时钟），`currentHighResolutionTime` 仅用于进度与高亮的平滑显示。节拍器每次排程重新读取音频位置与播放倍率，不长期依赖首次启动时的独立时间锚点。

## 点击声音量

节拍器的正弦点击声直接输出至AudioContext，不经过乐器的压缩及增益链。点击声振幅同步提高约6dB：强拍峰值0.28、弱拍0.18，均为原值两倍；保持强弱比例、2ms起音、45ms衰减及原有排程时刻。

## 进度拖动

SpessaSynth 的 `currentTime` 赋值向 AudioWorklet 异步发送跳转指令，赋值后立即读取仍可能得到旧位置。此前播放器在此时重启节拍器，造成歌曲跳转后点击声保持旧相位。

现在拖动提交立即停止节拍器并取消已排程的点击声。播放器等待 `timeChange` 确认，才从已生效的新位置恢复点击声。一次最多有一个在途跳转；后续拖动合并为最新目标，中间确认不会启动节拍器。等待期间进度显示最新目标，不被旧位置覆盖。暂停、切换节拍器或变速也不能绕过这个确认过程；恢复播放等待在途跳转结束。

初始化等待初始位置确认后才返回播放器。预备拍只调度负时间拍点，正文点击声等 MIDI 实际开始后调度；在预备拍期间拖动会结束预备拍，等待目标位置确认后从该处开始。暂停、销毁和曲终均取消点击声排程，旧异步任务不能重新启动播放。

## 验证

- `spessa-player-sync.test.ts` 模拟赋值后仍返回旧时间的真实异步行为，覆盖前后快速跳转合并、暂停恢复、等待期间变速与切换、预备拍中跳转，以及销毁和曲终。
- `metronome.test.ts` 检查 Web Audio 的实际排程时刻、非拍点跳转、播放倍率和预备拍边界。
- `tests/e2e/metronome-sync.spec.ts` 在浏览器记录音频线程跳转确认和振荡器排程，跨 MIDI 变速区间前后拖动，并改变全局播放倍率。SpessaSynth 原始处理器计数器从 Worklet 创建时开始，先换算到 AudioContext 的时间原点，再逐次检查确认后全部新点击声的拍点误差，门限 20ms；报告保留原始记录与各次测量。
