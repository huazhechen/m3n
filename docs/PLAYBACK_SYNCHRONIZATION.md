# 播放跳转与节拍器同步

## 时间基准

MIDI 和节拍器使用同一份 MIDI 速度图；调度读取 `Sequencer.currentTime`（音频时钟），`currentHighResolutionTime` 仅用于进度与高亮的平滑显示。节拍器每次排程重新读取音频位置与播放倍率，不长期依赖首次启动时的独立时间锚点。

## 连音组高亮

三连音等连音组按组内每个音符的起止时间更新高亮，音符与其对应歌词共享组内位置标识；休止也独立占用一个位置。简谱与五线谱均只高亮当前子音符及当前演唱遍次的对应歌词，不给整组父节点着色。组内同音延音保持原有声音连接，暂停后续播跳过当前持续音。

## 点击声音量

节拍器采用正弦点击声，强拍峰值0.90、弱拍0.65；2ms线性起音，保持至8ms后指数衰减至60ms，65ms结束。短暂保持段提高点击声的实际能量，避免只有瞬时峰值却听不清。点击声在乐器的音色补偿、压缩及增益之后混入同一个峰值限幅器，合成输出不超过0.94；音色切换不改变节拍器响度。共用限幅器增加约3ms延迟，排程仍沿用原有音频时钟。

## 谱面点击

点击谱面不启动或恢复播放；开始与恢复播放只通过播放按钮操作。播放中点击音符、歌词或小节内留白，统一跳转到该小节开头；跨行、跨页片段也回到原小节起点。跳转时间在首事件前保留1ms余量，避免MIDI累加时钟与谱面时间的浮点误差让定位过程提前消费首音的note-on；首音会正常完整演奏。编辑定位同步选择该小节首事件的源码。

红、黄、绿预备拍期间，播放按钮显示为可操作的“暂停”。点击后立即取消预备拍、清除高亮并撤销待启动请求；原请求完成时不能重新启动播放。资源尚未准备完成且还未进入预备拍时，播放按钮保持加载状态。

## 进度拖动

播放条分离视觉进度与无障碍进度滑条：视觉滑条随音频更新，对读屏隐藏且不参与 Tab 导航；无障碍滑条默认不占视觉布局，键盘聚焦时显示。播放期间不自动改写无障碍滑条的值，避免旁白连续接收值变化而打断阅读；聚焦、主动调整与暂停时同步位置。读屏调整直接提交跳转，不依赖键盘或指针事件。

SpessaSynth 的 `currentTime` 赋值向 AudioWorklet 异步发送跳转指令，赋值后立即读取仍可能得到旧位置。

拖动提交立即停止节拍器并取消已排程的点击声。播放器等待 `timeChange` 确认，才从已生效的新位置恢复点击声。一次最多有一个在途跳转；后续拖动合并为最新目标，中间确认不会启动节拍器。等待期间进度显示最新目标，不被旧位置覆盖。暂停、切换节拍器或变速也不能绕过这个确认过程；恢复播放等待在途跳转结束。

初始化等待初始位置确认后才返回播放器。预备拍只调度负时间拍点，正文点击声等 MIDI 实际开始后调度；在预备拍期间拖动会结束预备拍，等待目标位置确认后从该处开始。暂停、销毁和曲终均取消点击声排程，旧异步任务不能重新启动播放。

## 验证

- `spessa-player-sync.test.ts` 模拟赋值后仍返回旧时间的真实异步行为，覆盖前后快速跳转合并、暂停恢复、等待期间变速与切换、预备拍中跳转，以及销毁和曲终。
- `metronome.test.ts` 检查 Web Audio 的实际排程时刻、非拍点跳转、播放倍率和预备拍边界。
- `tests/e2e/metronome-sync.spec.ts` 在浏览器记录音频线程跳转确认和振荡器排程，跨 MIDI 变速区间前后拖动，并改变全局播放倍率。SpessaSynth 原始处理器计数器从 Worklet 创建时开始，先换算到 AudioContext 的时间原点，再逐次检查确认后全部新点击声的拍点误差，门限 20ms；报告保留原始记录与各次测量。
