# 跳房子分支延音线

## 背景

以下写法中，公共部分末尾的 `4~` 应分别连接到一房子和二房子开头的 `4`：

```m3n
1234~ | [1: 4567 |] [2: 4321 |||]
```

其中跳房子在内部 MEI 中表示为相邻的 `<ending>`，而同音延音线表示为 `<tie startid="..." endid="..."/>`。

目标是让二房子开头显示与正常换行后行首一致的短圆弧线，而不是从公共 `4` 横跨一房子绘制一条长延音线。

## 已确认的行为

- 当前 `m3nToMei` 的延音收集是线性的：一个 `4~` 只会自动连接到书写顺序中的第一个后继音符，即一房子的 `4`。
- Verovio 6.2 能加载两个同起点的 `<tie>`；但将公共 `4` 同时连接到二房子 `4` 时，会按两音符的实际横坐标绘制跨越一房子的长弧，不符合预期。
- 仅输出 `<tie endid="#second-ending-note"/>` 会被 Verovio 接受，但 SVG 中只有空的 `tie` 容器，不会产生行首短弧。
- 因此，标准 MEI/Verovio 的 tie 关系不能表示“没有实际起点、只在二房子开头显示续线”的分支延音。

## 方案选择

采用布局专用的 Ghost Note 锚点，不采用 SVG 后处理。

SVG 后处理虽然可以手工插入圆弧，但无法复用 Verovio 的延音线方向选择、避让、符干关系、歌词和其他延音线冲突处理。在窄小节、多声部或记号密集处，无法保证与 Verovio 一致，视觉风险高于其语义收益。

Ghost Note 已验证可使 Verovio 按正常换行续线的规则绘制二房子行首短弧。关键是将其隔离为布局投影的内部锚点，不改变规范乐谱语义。

## 实施计划

在当前重构完成后实施：

1. 保持规范 MEI 和播放/导出语义不变：公共 `4~` 仍连接到一房子的真实 `4`。
2. 在传给 Verovio 排版的 MEI 副本中，识别以下条件：
   - 公共小节末尾存在延音起点；
   - 紧随其后有多个跳房子；
   - 某个后续房子的首个可延音事件与该起点同音高；
3. 仅为后续房子插入不可见的 Ghost Note 锚点，并以它建立使 Verovio 产生行首短弧的延音关系。
4. 将锚点排除在源码映射、歌词对位、播放、选中/高亮、时值统计和对外导出的规范 MEI 之外。
5. 让屏幕 SVG、SVG 导出和 PDF 导出共用这一布局投影，避免导出结果与屏幕不一致。

## 验收

- 示例能在二房子首小节线后显示短圆弧，且不出现跨越一房子的长弧。
- 正常跨小节和正常换行的延音线不回归。
- 二房子 Ghost Note 不发声、不产生可见音头/符干、不占歌词或高亮位置。
- MIDI、歌词对位、诊断和源码映射与未加入布局锚点前一致。
- 屏幕、SVG 导出、PDF 导出的视觉结果一致。
