# M3N 重构记录

本文件记录以 `MANUAL.md` 为规范来源进行的结构性调整、兼容性判断与验证结果。

## 2026-08-04: 切换到 M3N v0.3 乐句结构

### 变更

- 新增 v0.3 文档结构层，统一解析 `N:`、`B:`、`C:`、`L:`、`---`、`===` 与 `{form=...}`，并将音符内核、校验和 MEI 转换接到同一结构结果。
- 歌词改为逐乐句、逐实际演奏遍次严格校验；每遍必须完整对位，支持后续编号行通过 `{LN}` 引用同乐句中更早的歌词行。
- 81 份内置曲谱全部迁移到 v0.3；源码映射同步回映到各乐句行。`00021` 与 `00045` 保留完整歌词并标记为歌词诊断，等待人工调整对位。
- 删除 Happi123 转换页面、实现、文档和测试；删除额外和弦伴奏与渐变速度 MIDI 修补层，播放器直接消费 Verovio MIDI。

### 判断

v0.3 是断代语法，不维护 v0.2 文本兼容契约。结构解析必须先于音乐原子解析，才能让乐段编排、逐乐句补充行和严格歌词遍次成为校验、渲染与源码映射的共同事实来源。无法自动证明正确的歌词迁移不得删除或改写原始歌词项，应保留诊断交由人工处理。

### 验证

- `npm run check`：189 tests passed；lint、TypeScript 检查与生产构建通过。

## 2026-08-02: 提取统一播放计划

### 变更

- 新增 `lib/notation/repeats.ts`，集中反复次数、跳房子、D.S./D.C. 回跳和小节演奏轮次计算。
- `m3n-mei.ts` 仅将纯播放计划序列化为 MEI `<expansion>`，不再维护第二套播放状态机。
- `m3n-direct.ts` 保留兼容导出，歌词对位与 H123 转换继续得到相同的小节轮次语义。
- 新增纯状态机、MEI 转换与 Verovio MIDI 回归覆盖，包含显式/隐式反复、顺序房子、跳房子和 D.S. 回跳。

### 判断

反复与导航是演奏语义，不属于 MEI 字符串拼接或单一解析器的私有实现。此前三处分别计算反复次数或展开序列，修复一种边界情况时容易让歌词、渲染和 MIDI 再次偏离。将状态机置于无 UI、无序列化依赖的 notation 层，使各消费者仅处理各自的适配职责。

### 验证

- 相关单元、转换和 Verovio MIDI 测试：92 tests passed。
- `npm run lint`、`npm run build`：通过。
- 全量 `npm run check` 仍被既有的内置样本难度排序断言阻塞，与本次播放计划改动无关。

## 2026-08-01: 固化速度区间的后续状态

### 变更

- `{accel=N}...{/}` 与 `{rit=N}...{/}` 关闭时，直接解析器将目标速度写入后续事件，并将其作为主谱表设置事件同步给低音谱表。
- 校验器以相同的状态迁移处理区间关闭；非法的速度目标只产生诊断，不会污染后续速度状态。
- 新增直接解析和播放时间轴回归测试，覆盖区间结束后的旋律、低音谱表与 MIDI 速度点。

### 判断

手册规定速度区间在关闭后保持目标速度。这是语言的持续状态，而不仅是 MEI 上的连续速度标记。先前转换器只更新当前解析上下文，导致低音谱表在区间结束后继续使用旧速度；校验器也缺少等价的状态更新。以手册为准同步两条路径，能使渲染、播放和双谱表时间轴共享同一解释。

### 验证

- `npm run check`: 99 tests passed；lint、TypeScript 检查与生产构建通过。

## 2026-08-01: 明确默认速度

### 变更

- 手册将默认速度定义为 `120qpm`，省略速度声明时采用这一确定的初始状态。
- 新增直接解析器回归测试，锁定未声明速度的事件速度。

### 判断

可交换的语法规范必须使未显式指定速度的文档仍有确定的播放语义。原表述把该状态留给实现，无法保证不同 M3N 实现生成相同的播放结果；120 qpm 是中性的常用默认值，并已是转换与播放链路的实际初始状态，因此应提升为语言规范。

## 2026-08-01: 统一源文本词法边界

### 变更

- 新增 `src/lib/notation/m3n-tokens.ts`，集中定义 M3N 的空白、注释、指令、小节线、圆括号、音符分组、音符与未知文本的词法边界，并保留行号和源码偏移。
- `m3n-validate.ts` 与 `m3n-direct.ts` 改为共同消费该 token 流。校验器继续负责规范约束；直解析器继续负责生成事件模型，不在词法阶段混入语义判断。
- 文档示例回归测试覆盖 `README.md`、`GUIDE.md` 与 `MANUAL.md` 中全部 `m3n` 代码块；每个示例都必须同时通过校验和 MEI 转换诊断。

### 判断

手册规定语法错误不得静默忽略。此前校验器与直解析器分别扫描源码，二者对 token 边界的细微差别会导致同一文本出现“能转换但不能校验”或相反的漂移。共享无状态词法层比复制正则更符合该规范，也保留了转换器的源码映射能力。

### 验证

- `npm test`: 93 tests passed。
- `npm run build`: TypeScript 检查与生产构建通过。

## 2026-08-01: 同步双谱表设置时间轴

### 变更

- 直解析器把正文的调号、拍号和速度变更记录为带书写时间位置的事件。
- 低音谱表在处理每个音乐原子前应用已到达的正文设置事件，使转换路径与校验器共享同一时间轴。
- 新增双谱表回归测试，覆盖中途改变调号、拍号和速度。

### 判断

低音谱表不是独立乐曲，而是同一乐曲的第二谱表。只继承初始设置会使合法输入在校验与转换之间产生不同的音高和节拍解释；按音乐原子位置同步是唯一能保持两条谱表一致的语义。

## 2026-08-01: 重组规范手册

### 变更

- 将 `MANUAL.md` 从按功能累积的长篇说明重组为七个规范章节：文档与栈、设置、音乐原子、结构、演奏标记、补充块、错误分类。
- 将可执行语法集中为产生式、表格和局部约束；将引导性曲例留给 `GUIDE.md`，手册仅保留消除语义歧义的最小合法例子。
- 明确了状态、前置、后置、位置、区间和补充块的作用域，及其与匿名/具名关闭指令的统一栈规则。
- 将小节完整性、弱起、延音目标、反复/volta、具名乐段、歌词对位和低音谱表时间轴的约束放在各自语法对象之后，避免读者在章节之间来回查找。

### 判断

规范的首要目标是让同一输入能被独立实现作出同一合法性判断。原手册将语法、渲染效果和教学叙述交错陈列，且多次复述同一规则，增加了遗漏条件的风险。重组后，语言接受条件由本手册完整定义；显示与播放的具体实现不再作为语法成立的前提。

### 验证

- `npm test`: 94 tests passed，包括全部文档中的 `m3n` 代码块。

## 2026-08-01: 隔离具名乐段设置

### 变更

- 直解析器将正文公共的调号、拍号和速度与当前乐段的局部设置分开保存。
- 打开或关闭 `part` 时恢复公共设置，防止一个乐段内的设置污染下一乐段。
- 新增直接事件模型测试，锁定两个相邻乐段拥有不同局部/公共设置时的事件属性。

### 判断

具名乐段可按 `parts` 声明顺序引用，定义文本的排列顺序不应成为隐式状态传递机制。因此乐段局部设置不跨乐段传播更符合语法模型；校验器原有行为也采用这一规则，现已与转换器一致。

### 验证

- `npm test`: 95 tests passed。
- `npm run build`: TypeScript 检查与生产构建通过。
