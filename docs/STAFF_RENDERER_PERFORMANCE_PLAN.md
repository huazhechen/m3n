# 五线谱选宽进入60秒以内的路线

## 目标与证据

目标是同机全量逐曲选宽墙钟之和低于60秒，保留480～720px、20px粗选及相邻10px细化、综合质量评分、全部间距尝试与内部避让。浏览器隔离启动、最终SVG／PDF生成、独立SVG审计继续分别计时。只允许当前任务内复用，不保留跨任务文字、排版或选宽结果。

当前主线 `33eb34cc` 已完成全分支整合、全量检查与两轮复测：107首、1,565个候选，逐曲选宽墙钟分别56.656／56.540秒，中位数 **56.598秒**，达到60秒以内的目标。两轮全部候选的页数、行数、质量指标和选宽一致，失败候选0。浏览器启动等独立测试开销另计；详细记录见[整合后的全库性能验收](STAFF_WIDTH_MEASUREMENT_PERFORMANCE.md#整合后的全库性能验收)。

以下保留路线制定时的历史分析。分析以 `73ee725b` 的实现和107首固定谱源快照为依据，当时没有修改渲染实现。最近两个正常轮为161.239／148.985秒，中位数155.112秒；进入60秒需要再减少61.32%，约2.59倍速度。全部候选1,563个、间距尝试3,673次，诊断中的谱行绘制／整理遍次40,454次、绘制模型147,987次。完整数据及验证见[性能记录](STAFF_WIDTH_MEASUREMENT_PERFORMANCE.md#三项优化后的统一复测)。

最新独立诊断墙钟151.404秒：

| 互不包含的主要阶段 | 耗时 |
| --- | ---: |
| 规划用VexFlow小节模型 | 6.463秒 |
| 绘制用VexFlow小节模型 | 38.363秒 |
| VexFlow绘制及节点捕获 | 42.328秒 |
| 附件避让、歌词与几何整理 | 41.078秒 |
| 其余工作及阶段外开销 | 23.171秒 |

以上只用于分析作用范围，不把诊断轮替代正常轮。即使假定绘制模型和VexFlow绘图成本全部消失，诊断轮仍剩70.713秒；连规划模型也消除仍剩64.249秒。这不是实现可达到的耗时下界：替代算法必然还有成本，其余阶段也可以优化。它说明必须同时减少几何整理和避让的基础开销，不能仅替换VexFlow最后输出字形的函数。

简谱历史优化的固定105首／1,365候选为46.543秒，输入及细化策略与当前五线谱不同；它支持数值墨迹路线的可行性，不用于计算两种记谱法的精确速度差。60秒作为五线谱自身在固定工作量下的独立验收目标。

## 当前结构中可以直接改变的部分

- `vexflow-engine.ts:createVexMeasure` 每次重建Stave、StaveNote、Voice、Formatter、ModifierContext、TickContext、修饰符、符杠和连音组。上一轮只共用不可变描述及规划列度量，147,987次绘制模型仍完整重建。`spacing` 在这个函数中主要改变列间附加空隙，`bassY`改变低音谱表位置；二者都不应迫使语义、字形和全部固定度量重新准备，但连接几何仍需依新位置计算。
- `drawVexMeasure` 在每次试排绘制谱线、每个音符、修饰符、符杠及连音组，生成内部XmlNode和路径字符串。生产已不挂载最终SVG DOM，也不调用完整页面序列化；因此只推迟 `render(true)` 或关闭独立审计不会省掉这42秒。需进一步消除候选内的路径命令、属性字符串和XML树构造。
- `staff-system.ts` 每行最多尝试8次低音／歌词间距；净空不足会重新构建并绘制全行。应保留收敛与净空判定，改为移动声部数值图元、重新计算受影响的连接和避让，避免无关音符重建。当前报告没有重试次数分布，先增加专门计数，不宣称可直接省下多少时间。
- `system-layout.ts` 多次通过 `findAll`、`pieces`、`without`、`selected`提取同一音乐主体、歌词、房子和核心谱线。当前已共用单路径局部墨迹，却仍重复遍历树和变换整个图元集合。应在图元建立时分类，直接维护音乐、歌词、附件、核心和房子边缘的数值集合；移动附件只更新其集合。横向区间索引可继续减少无关障碍比较。
- 已安装VexFlow的 `Glyph.cache` 和 `cached_outline` 本来就保存已解析字形，热点不是每次都从原始字体重新解析。仍重复执行轮廓坐标展开、舍入、路径拼接、属性处理和节点分配。字符字体能减少这部分工作，但不能自动消除音符模型与Formatter成本。
- 不应直接全局缓存 `getGlyphProps` 的返回对象：VexFlow的StaveNote会改写休止符 `position`，NoteHead会改写 `code_head`。当前任务内只能共享不变的描述或度量，不能让可变对象互相污染。

## 推荐：逐步自研数值排版与渲染

先建立统一的数值图元层，让候选测量和最终屏幕／PNG／PDF消费同一套布局结果。过渡期允许VexFlow在任务准备阶段提供局部度量和对照，逐步移除候选热循环中的VexFlow对象；不先重写已经归一的选宽规则。

```text
ScoreDocument
  → 单任务准备：音高／时值／升降状态／拍组／字形度量与锚点
  → 每档版宽及间距：数值时间列、谱行、符杠／曲线和附件位置
  → 精确数值墨迹：内部避让、大谱表净空、分页与质量评分
  → 最优版宽的同一布局结果
  → SVG输出 → 页面／PNG／矢量PDF
```

图元至少区分固定字形实例、直线／矩形、曲线和文字块，包含语义身份、声部、局部墨迹、变换与连接锚点。固定字形使用任务内不变模板；位置和附件状态属于当前候选。避让继续使用原有独立子路径／笔画粒度，不能用一个整音符或整行外框替代，否则会把括线内部的空白误判为障碍并改变页数。

1. **先分离数值布局与SVG生成。** 候选直接生成墨迹及锚点，按类型维护集合，完成全部真实避让后分页评分；选中宽度才输出SVG节点和路径／文字。最终输出调用相同图元的绘制器，避免另写一套近似测量引擎。先选取无符杠简单谱例打通，再覆盖复杂用例；不能通过关掉避让或减少间距档得到收益。
2. **将固定字形改为字体实例，并减少模型构建。** 符号是否存在以实际分发Bravura字体为准；复用其精确局部墨迹、尺度和锚点，以字形实例替代反复展开轮廓。准备阶段解出音高到谱线位置、休止符、升降号状态、和弦符头错位、符干方向、附点及修饰符占位；候选只计算列坐标和受宽度影响的布局。先保留VexFlow作参考，逐项替换模型职责。
3. **最后接管宽度相关的连接几何。** 符杠斜率与符干长度、倚音连接、连音组、延音／连奏线、跨行续接及大谱表连接随锚点重算。保持现有规则和数值精度；字体没有的符号及随端点改变的图形继续绘制几何。大谱表净空调整只移动需要移动的声部与附件，再重算连接和实际避让。

字体字符和当前VexFlow内嵌轮廓不能假定完全同度量；需核对基线、符头边缘、符干／符尾连接点、变音记号间距和真实墨迹。字符方案改变SVG表达，验收改为核对图元、锚点、实际墨迹及导出，而不能要求字符SVG和原路径SVG逐字节一致。发现字体／规则导致的版面差异须单独记录原因，不能默许全部差异。适用字形清单见[音乐符号清单](MUSIC_SYMBOL_RENDERING.md#五线谱的字符替换范围核对)。

完全不用VexFlow是这条路线的可选终点。最主要的新增工作是复现局部雕版规则；分行、时间列、中文歌词、附件、导航、房子、分页和共用导出接口已经由本项目负责，不需要从头开发整套乐谱系统。过渡期间必须让数值布局成为唯一生产依据，不能长期维持“自研测量、VexFlow另行排版输出”两套结果。

## 目标预算与决策门槛

以下为进入60秒的工程预算，不是已测收益或保证：

| 阶段 | 验收预算 |
| --- | ---: |
| 准备及音符／连接图元计算，覆盖原三项VexFlow模型与绘图成本 | ≤20秒 |
| 几何分类、歌词和附件避让 | ≤15秒 |
| 其余准备、规划、分页与外层开销 | ≤25秒 |
| 全库逐曲墙钟合计 | **≤60秒** |

先在基本功、枫、Flower Dance、K545、Valsentino五首建立原型，并补全休止、和弦、倚音、非常规连音组、换调、跨行连线和多层歌词样例。补充分段：准备模型、固定字形／动态连接、图元分配、音乐主体收集、歌词、附件避让、低音净空重试及其重做的小节数。将原型新增准备成本计入逐曲总耗时，不能只报告候选热循环。

每个替换点先核对参考实现的时间列、锚点、真实墨迹、符干／符杠连接和分页，再做无埋点子集计时；取得明显净收益后跑固定107首全库两轮正常测量。通过后继续扩展，暂不为未覆盖符号静默降级。

最终验收保留全部候选及间距档，比较所有候选的页数、行数、质量指标和选宽，审计全库及复杂专项的越界／碰撞；覆盖移调、低音开关、小节号、连续／分页横坐标、播放身份／逐音高亮、PNG与矢量PDF文字／音乐字体。性能测试与构建、审计、CPU采样串行运行，只有完整且同源的正常轮进入中位数统计。

暂不把跨任务缓存、减少候选、假设页数单调、关闭内部避让、并行跑多浏览器或单独优化字体下载作为达到60秒的办法。小型VexFlow查表优化可以作为补充，但现有作用范围不足以支持61%的整体降幅。


## 实施检查点

数值图元、固定音符模板、任务内私有绘制模型、直接符干／符杠／谱线／歌词墨迹已进入实现；动态或无法记录为固定模板的符号仍保留VexFlow绘制。模型以同步谱行租借方式隔离，重算当前坐标、符杠及全部避让；最终SVG从相同数值图元输出。小节号白底等并行功能修正已随主线整合一起验收。

整合前完整编译版曾测得78.340秒，后续8首子集为7.932秒，对照9.357秒；这些是历史检查点。全部修改及剩余分支现已合入主线，完成全量用例、代码检查与推送；整合后两轮全库中位数56.598秒，已达成性能目标。新谱源快照有1,565个候选，与历史1,563个候选的快照不同，不据此计算跨快照提升百分比。

本轮到达性能目标后停止扩大实现变更。VexFlow尚未彻底替换；若继续推进自研替代，应逐项迁移局部度量、音符准备和连接几何，每一步保持同一套测量／输出结果及实际内部避让，不通过减少候选或关闭避让提速。
