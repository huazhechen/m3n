# M3N 简谱渲染

简谱采用纯浏览器链路：`ScoreDocument → @m3n/numbered-notation → @m3n/jpfun → SVG`。jpFun 的 TypeScript 核心源码已保存在 `packages/jpfun`，固定上游版本与本地补丁；旧的自绘 `core/` 和字形 JSON 已移除。源码来源、Apache-2.0 许可和维护记录见 [UPSTREAM.md](../packages/jpfun/UPSTREAM.md) 与 [CHANGES.md](../packages/jpfun/CHANGES.md)。选型背景见[历史整改方案](NUMBERED_NOTATION_REMEDIATION.md)。

## 调用与职责

```ts
await prepareNumberedNotationFonts()
const score = NumberedNotationScore.create(document)
const pages = score.render({ width: 800, paged: true, includeBass: true })
// score.diagnostics 包含投影与引擎诊断。
```

唯一音乐输入是 `ScoreDocument`；适配器不读取 `document.source`、MEI、Verovio SVG 或 MIDI。`projection.ts` 负责领域语义到 jpFun 脚本的投影，`lyrics.ts` 负责歌词槽位与遍次，`svg.ts` 只添加交互分组和属性，不移动或重新绘制音符与关系线。

简谱显示与导出不初始化 Verovio。播放时才按需加载 Verovio 与 SpessaSynth，继续沿用现有 MIDI、反复与导航时间轴。`@m3n/score-renderer/view` 提供轻量页面工具，`/verovio` 和 `/player` 是独立的动态入口；生产打包不再把 Vite 的共享加载助手放入手工指定的 Verovio 块。渲染库、WASM、字体和音源必须来自本站构建产物，禁止使用第三方运行时资源外链。

应用为当前输入与布局设置分别缓存简谱和五线谱快照，重复切换可直接恢复；修改乐谱、版宽或分页等设置会使缓存失效。文档页切换通过 Context 更新谱例，保留已有组件。

`scoreEventIds(document)` 是 MEI 与简谱共享的事件身份映射。唯一 DOM `id` 与可以重复的 `data-m3n-id` 分开：连音组子音符、长音增时线和长休止保留父事件身份，各自拥有唯一的可视 ID。小节跨系统或跨页时保留逻辑小节 ID，避免重复 DOM ID。歌词另带 `data-m3n-rendition` 和 `data-m3n-passes`，支持点击定位与反复遍次高亮。低音谱表共享旋律的反复小节线，避免并行声部的锚点错位。

## 语义支持

| 范围 | 行为 |
| --- | --- |
| 音高、变音、八度、八度区间 | 投影为 jpFun 数字音符及上下点；每个和音成员应用相同规则 |
| 时值、附点、延音、休止 | 保留精确时值；长音拆为首音与增时线，同小节内可表达为整拍增时线的同音延续自动使用横线；仍需弧线时从首音数字起弧，跨行时分段。长休止使用多个 0；多小节休止显示小节数 |
| 和音、低音、多声部 | 交给 jpFun 排列与对齐；导出可排除低音而不改变旋律事件 ID |
| 连音组、倚音、琶音 | 使用原生连音组、复合倚音和琶音；长/短倚音的演奏区别仍由 Verovio MIDI 处理 |
| 延音线、连奏、发夹 | 原生关系附件处理跨行；合并相邻连奏；支持单事件短发夹及文字形式 |
| 装饰、指法、力度 | 延长号、跳音、重音、保持音、断音、换气、颤音、指法与力度均有投影 |
| 调号、拍号、速度 | 显示页头和谱中变化；渐快/渐慢显示文字及目标速度，播放使用现有时间轴 |
| 反复、跳房子、导航 | 反复线、次数、房子括线及 D.S./D.C./Fine/Segno；播放由领域计划与 Verovio 负责 |
| 歌词与文字 | 中文标点、英文词、多行、共享遍次、空槽、延音与间奏跳过；括号词组保留下划线；文字、和弦、段落标题 |
| 器乐区间 | `{inst}…{/}` 投影为原生区间圆括号；按谱行分段，支持换行、分页，保留休止符与长音增时线 |

适配器对未映射的后缀产生 `NUMBERED_UNSUPPORTED_MARK`，应用显示提示；引擎错误会终止本次渲染并显示原因。领域层未表达的功能不会通过重新扫描源码补猜。引擎拍号警告仅作参考，M3N 的领域校验继续负责弱起、跨乐句小节和双谱表规则。

自动减时线连接读取当前拍号：6/8、9/8、12/8 等复拍子每三个八分音符分组，例如 6/8 的六个连续八分音符分成 3＋3；谱中变拍从新小节起生效。双声部分别连接，小节线重置拍组，已知拍号的小节在行内拆分后仍保留原拍组位置。显式连梁和单个分割作用域保留指定的连接范围。五线谱 MEI 同样按复拍子的三个分母单位自动连梁；这不改变音符时值或播放速度。

### 同音延续的简谱表达

同一小节中，`~` 连接的同音音符或和音，如果后续音符落在完整四分音符拍的位置、时值为整数个四分音符，且没有独立歌词、奏法、说明、调号／拍号／速度／力度变化或连奏区间起点，则后续音符显示为增时线。连奏区间在此结束不阻止转换。同音判断与领域校验共用 `resolveScorePitches`，包含临时变音继承、调号和八度。例如 `6~ 6~ 6~ 6` 显示为 `6 — — —`，`[135:h]^~ [135:h]^` 显示为和音后接三根增时线。未用 `~` 相连的重复音保留数字，避免将重新发音误写为延续。

跨小节、切分位置、短于四分音符或含连音组的延音保留同音连线；连音组取最后一个有音高的子音符作为起点。增时线之后若仍需跨小节连线，弧线从原始数字或和音起弧。此规则只改变简谱投影，不修改 M3N、MEI 或播放时间轴；每个原始事件保留自己的 SVG 身份和点击位置，增时线组带 `data-m3n-role="sustain"`。引擎增时线不消费歌词槽位，后续各段歌词仍与原音符对齐。

连奏线的末端落在区间内最后一个实际数字音符或和音上；区间末尾是普通长音时取其首个数字，是同音延续增时线时回溯到对应的原始数字，是连音组时取最后一个有音高的子音符。渐强、渐弱线仍延伸至完整时值末端。例如《后来》两处“一旦错过就不再”的 `1e~ 1e^` 显示为 `1 — —`，连奏线收在该高音 `1` 上。

连奏线与仍需保留的同音连线重叠时，连奏线排在外层，按完整弧带留出间隙，包括共用起止音、换行及分页的情况。弧线的高度和音乐端点保持原有含义，外层弧线整体上移并计入行高；只在一个音上首尾相接的相邻弧线不因此抬高。

显式关闭后重新开始的连奏区间分别保留，不因音符相邻而合并；嵌套连奏线由内到外投影，避免短弧反而浮到长弧外侧。渐强、渐弱发夹通过原生 `@dyn(...,below=true)` 排在音符及低八度点下方，与上方连线分开，各自预留谱行空间；跨行继续保留方向和开口进度，不改变领域区间或播放。

本轮逐曲扫描在 41 首内置曲目中识别并转换 315 处整拍延续，含《ANDY》《后来》《天空之城》《黄昏》《菊次郎的夏天》等。记录中的次数按原始后续事件计数，一个事件可以产生多根增时线。

## 排版与字体

支持至少 320px 的版宽。分页使用 A4 去掉四边 10mm 后的内容比例 `277 / 190`，连续模式按实际内容扩展高度。页头与正文均由 jpFun 渲染。

渲染选项 `pageMargin` 与 `systemGap` 分别控制四边页边距和谱行间最小留白（px），默认仍为 32 和 24，必须是非负有限数值。电子谱集在纸张外侧留24px边距、谱内留8px页边距；全册额外谱行留白最低为字号的0.5倍，由同一引擎重新排版，不压扁音符、歌词或关系线；网页默认显示不受影响。

谱头`{equal-measures=true}`启用行内小节等宽，省略或显式`false`时关闭。领域层解析为布尔配置，经适配器传入jpFun横向求解：每行划分相同宽度的小节单元，先保留完整行的歌词、括号和并行声部约束，再在各单元内用原生弹簧求解音符。小节线锚点等距，音乐附件在此之后计算，最终SVG不再移位。自动换行按候选行的最密小节乘以小节数计算容量，单个过密小节继续使用原生分拍规则；显式换行、播放、反复及事件身份不变。数字字号不变，不影响五线谱。当前内置谱仅每日基本功启用等宽小节。

未设置成对间距时，等宽模式在完整小节线字形两侧各预留线高的0.55倍（22px音符时约15.13px），单线及反复线均参与。设置最小／自然成对间距时，安全净空已计入音符与小节线的物理宽度，不再叠加这份额外预留，避免小节线两侧留白远大于音符分组间隔。渲染选项 `wrap: "compact"` 在自然小节宽度下允许自动换行容纳更多小节，由原生弹簧求解器重新分配音符间距，歌词、变音及关系仍参与布局；不压缩字形。等宽模式仍只对稀疏小节收紧容量：每小节不超过4个有时值节点、各节点至少一拍，且无宽歌词约束；等宽快速音型和宽歌词保留正常容量。默认 `wrap: "normal"`；未显式指定间距时统一使用下述最小／自然间距策略。此选项调整换行容量，不承诺固定的最小净空；紧凑导出需检查实际字形、歌词重叠与裁切。该选项是渲染选项，不是新增M3N语法。

渲染选项 `noteGapEm` 设置有时值音符之间的基础自然间距，单位为正文数字字号的倍数，必须为非负有限数值。`0.3` 在22px正文中对应四分音符的6.6px基础间距（每侧3.3px），短音符和长音符按时值平方根缩放，并保留连梁对组内弹簧的收紧；默认省略时与 `minimumNoteGapEm: 0.4` 配对使用自然间距 `0.6`。此参数在自然测量和最终求解中同时生效，保留歌词及装饰约束，不缩小字形或改变演奏时值；它不是固定的最终字形净空，歌词、装饰、整行撑满及行宽约束会改变实际间隔。局部装饰内部排列保持原样。

配对使用 `minimumNoteGapEm: 0.4` 和 `noteGapEm: 0.6` 时，引擎分别测量最小／自然两套布局。前者决定候选行能否容纳小节，后者用于比较候选的疏密；不再以自然宽度乘固定比例排除候选。最小预留纳入最终求解占位，自然值与最小值之差作为可压缩余量。两档都同比缩放音符、休止、增时线、小节线和其他零时值控制对象的原生横向弹簧，保留时值平方根与连梁比例；不改变字形、歌词尺寸或竖向间距。歌词／装饰继续按实际占位参与约束，谱行仍撑满；整曲采用全局行间平衡，不采用单行贪心塞满。两值必须为非负有限值且最小值不大于自然值；只有自然值时兼容原单参数行为。配对模式下普通与紧凑换行共用实际最小宽度判定，不再使用旧容量比例。

`uniformSystemHeight: true` 启用段内分档等行高。共享范围来自 `ScoreDocument.paragraphs` 的原谱乐句区间（`===`、`---` 分段），由领域解析器提供，适配器不回读源码。自动换行、`{br}` 与分页不改变所属段落；同一谱行包含多个段落时，取这些段落预留的并集。引擎通过原生 `@spacing({音乐},group="段落标识")` 分组，在每段内按各轨道的音符、八度点、奏法和关系记号分别统一音乐基础预留，其他段的高八度或装饰不再撑高本段。没有乐句信息的文档保持整曲共享的兼容行为。

每段保留普通/房子两档：只有房子实际经过的谱行（含跨行中间行）使用较高上沿。歌词不参与音乐最大值，按各行实际可见行数从音乐下沿另加空间。乐段名及练习说明采用 `@text(...,above=目标,local=true)`，只在所在行避让并预留实际高度，不计入本段最低音乐行高；标题保留，和弦名称仍参与音乐预留。跨页沿用本段档位，不将整页空白额外分摊到行间，页头独立排版。

谱集可用全局或条目 `systemGapCandidates` 指定额外行距候选，条目设置优先；`pageCount` 则保留既定页数。实际字形、附件及标题间距仍须通过浏览器检查；所有行距候选都必须通过相交与安全切页验证。

谱集可设置 `layoutPriority: "font"`，按字号、页数、留白选择候选；省略时沿用页数优先。独立曲与合页都优先保留最大合格字号，同字号再减少页数，最后选接近18px的额外行距。全局 `page.minimumNotePx` 可由条目 `minimumNotePx` 覆盖。`page.minimumFillPercent: 0` 取消正文高度利用率下限，几何与安全切页检查仍生效；不会为填满页面缩小音符或拉大行距。

局部标题与本行音乐预留的内部间隔为标题字号的0.4倍（普通非局部文字仍为0.5倍）；与上一行的距离由 `systemGap` 另行保障。

该模式保留事件身份、时值和原生关系几何，不移动最终 SVG 图元。SVG 谱行以 `data-m3n-paragraph` 和 `data-m3n-volta` 标记段落及房子分类；谱集布局记录的 `paragraphSystems`、`voltaSystems` 与 `baselineSteps` 保存对应信息及实际节距。核对节距时需同时考虑相邻两行的段落、房子档位、实际歌词行数，以及仅在所在行出现的标题。网页默认仍按自然高度排版。

独立电子谱集的构建工具读取 `scorebook/editorial-plan.json`：全局 `showCredits: false` 在排版前清空临时文档的作词、作曲、编曲和演唱字段，收回署名占用的页头空间；单曲 `includeBass: false` 通过现有渲染选项隐藏低音谱表。两项设置均纳入布局缓存键并写入布局记录，原始文件中的署名和低音保留。

适配器在每个`g.system`输出`data-m3n-top`、`data-m3n-bottom`，边界包含引擎记录的本行音乐对象及关系区域。房子线等关系保留全局坐标和原来的绘制层；谱集分页取原生边界与实际图形边界的并集，避免只按最近距离把下一行房子线留在上一页。此元数据不改变音乐图元或交互身份。

谱行统一撑满版心，包括显式换行前的短行和最后一行。适配器通过 `@page(fillRatio=0)` 启用引擎原生的行宽分配，长音练习等自然宽度较短的行也与其他行右端对齐。

同一声部内连续的同类关系记号按谱行对齐：三连音等连音组的括线、相邻房子线分别取组内能避让全部内容的共同高度；相邻自动连音线统一弧高。同一谱行上的弧线两端取较高音符（含高八度点）的高度，绘成水平对称的弧带；同时检查中间音符，若弧带下沿会碰到高音点或数字，则只整体上移所需的距离。跨行弧线各段也检查本行中间音符。普通音符间隔会断开对齐组，跨行、跨声部与嵌套层级分别处理；不同种类的记号不共用高度，显式指定的弧高保持原值。适配器启用 `compileScore({alignRelations:true})`，引擎默认仍保留局部高度布局。

连音线连接折叠音符或和弦时，端点取最上方的实际音符；`tr` 等零时值标记置于弧线外侧并预留空间，避免弧线连到标记上。

旋律与低音同时显示时，每个谱表系统左侧都显示连接两声部的括号，包括显式换行、自动换行和分页后的系统。适配器启用 jpFun 的 `@voices(...,repeatconnect=true)`，由引擎在每组左侧预留连接符列并绘制；隐藏低音后不显示连接符。

通用 `autoWrap` 先以自然宽度布局，再根据包含歌词的实际横向占位平衡小节。自然小节的紧凑模式对超过版心的自然宽度使用较低的压缩代价：自然宽度包含可收紧空隙，不能与不可压缩的字形占位等同；最终仍由原生求解器处理歌词和图形约束，全部谱行保持撑满。普通模式及等宽模式的压缩代价保持。。具名乐段投影为 `@br(soft=true)` 优先分行边界；引擎兼顾分段与行内留白，允许短引子与下一乐段同行，例如《超级玛丽》在 800/1000px 下首行包含 P 的一小节和 A 的两小节。`{br}` 仍强制换行，平行声部共享分行结果。密集小节需要拆行时平衡各行长度，优先在完整四分音符拍点换行，避免拆散节拍并留下很短的尾行。连音组内部不主动拆分，组首换行放在整个连音组之外。同一时刻的调号、拍号和速度只在每个声部插入一次换行，跟随后续音符。

谱集导出在字号和页数选定后增加页面余量反馈：读取每行主音符列的平均横向间隔，密度定义为字号除以平均音符列间隔，用最大密度与密度超过1部分的均方根之和评分；对平均间隔小于一倍字号的谱面尝试收窄换行参考宽度。渲染选项 `wrapWidthRatio`（0 < 值 ≤ 1，默认1）只影响自动断点，最终谱行仍按完整版心撑满，字形、音符间距参数与行距不缩放。工具试排0.98至0.76、步长0.02的候选；仅采用拥挤评分至少改善5%、每首最多增加与原页数相同数量的谱行、实际几何安全且原页数不变的结果。共页曲目按已拼好的整页剩余高度检查，字号及原有共页关系保持。原谱显式换行继续生效，不写入曲目专用换行；分页容量不足或没有明显改善时保留原方案。`layout-record.json` 记录最终 `wrapWidthRatio` 与逐行 `systemDensities`。此机制用于谱集生成，连续滚动谱面没有页面高度预算，不自动启用。

前反复线归属后一个小节。同一系统内，它替代同一边界上没有导航记号或反复次数标注的普通线、双小节线。自动或显式换行将边界分开时，上一行保留结束小节线，下一行保留前反复线；合并的双向反复号也拆为上一行的后反复号和下一行的前反复号。自动插入的记号不改变音乐时值、播放顺序或原始事件源码范围。字形、歌词、连线、装饰和分页由引擎处理，适配器不再对最终横坐标做压缩补偿。

同一乐句出现共享遍次标记时，全部歌词行都显示各自的遍次，例如 `1.`、`2.4.`、`3.`。相邻乐句的歌词行与遍次对应关系保持一致时，连续段落中每行只标一次，`---`、换行和分页不重复标记；对应关系变化、无歌词乐句、新乐段或新反复开始时重新标记。标记由引擎独立排在各行首个可见歌词的左侧并预留空间，歌词正文仍与音符居中对齐；跳过的空槽不提前消耗标记，整句为空时顺延到后续乐句的首个可见歌词。

歌词高度按每个谱行、每条轨道的实际可见歌词行计算。适配器启用引擎的 `@voice(...,compactlyrics=true)`，整行为空的歌词段不再预留行高，例如《国际歌》后半段共用一行歌词时收起第二、三行的空白；同一谱行的不同房子段可分别收起不存在的歌词行：例如左侧第一房子只有第一段、右侧第二三房子只有第二三段时，两处均从第一条可见歌词基线开始。显式零宽占位保留对应行距。空槽继续保留原始歌词段号与播放遍次，视觉收起不改变反复播放时的对应关系。

器乐标记 `{inst}…{/}` 使用 jpFun 的 `@paren(from,to)` 在音符两侧绘制普通圆括号；跨行、跨页时每个含该区间音符的谱行片段各显示一对。括号使用数字字体和字号，与所在声部的数字行对齐，不随八度点、减时线、和音或装饰拉伸。两端按括号字形的实际宽度预留横向空间，并保留紧凑间隔。嵌套及相邻器乐区间合并，单音符、休止符、和音、连音组和长音都保留；没有 `{inst}` 的纯器乐谱不自动加括号。括号不改变事件身份、时值、歌词对位或播放顺序。

Segno 从小节级导航信息读取，固定排在该小节开头，与音符行的视觉轴对齐，并随首个音符或休止符换行、分页；谱中变调、变拍、变速、连音组及多小节休止均保留该目标符号。兼容事件级导航信息时，同一小节只显示一次 Segno。

Fine、D.C.、D.S. 排在末音或休止符之后、小节线之前，与音符行的视觉轴对齐。引擎通过小节线的 `before` 内容预留完整横向占位，导航记号跟随末尾小节线换行、分页，不额外抬高房子线；原生反复和跳转语义仍由记号保留。反复次数继续显示在小节线上方，房子线仍避让音符、高低八度点、连奏线和上方标注。

上方标注从外向内依次为乐段名、位置文字（如练习说明）、和弦名称、音乐记号、音符。乐段名采用 700 粗体，练习说明和和弦名称保持常规字重，三者字号均为 14px。前三级文字通过引擎的 `@text(...,above=标签)` 附件定位，在连音括线、连奏线及渐强渐弱等关系排好后按层避让；文字随宿主音符换行、分页，不改变时值或事件身份，点击文字仍可定位对应音符。奏法符号继续贴近音符，普通行内文字和歌词不受此规则影响。

音符自身的八度点保持完整；其外侧由近到远依次排奏法符号（跳音、保持音、顿音、重音）、装饰与指法、力度与渐强渐弱等说明文字。简谱中的 `{tip}` 跳音统一显示为 7px 实心楔形，与高音八度圆点区分；`{str}` 重音仍显示为 `>`。力度或说明文字不会插在跳音与八度点之间；后置标记的书写顺序不改变这几类标记的内外层次。此显示约定不改变 M3N 奏法语义、五线谱记号或播放。

有前倚音时，奏法先附在主音上，再由引擎 `@grace` 包裹。倚音按主音数字的肩线定位在左上侧；顿音与无倚音的同音高主音保持相同相对高度，不因横向分离的倚音额外抬高。装饰、指法与力度等外层标注继续由 `@up` 避让整个倚音组合；高八度点、和音、原始事件分组及播放保留。

主标题与副标题分别按自身文字宽度居中，对准页面内容区中线，不受彼此长度和两侧署名、调号、拍号、拍速宽度影响。署名按“作词、作曲、编曲、演唱”顺序分成标签和姓名两列：各列按最长内容预留宽度，标签统一左对齐、姓名统一右对齐，两列间留 16px；缺失角色不占行，同名不同角色分别保留。署名、调号、拍号和拍速始终置于完整标题区下方；调号、拍号、拍速各项之间固定留 16px 间隔。版宽小于 600px 时，调拍速单独置于署名下方，避免左右信息相交。预览与导出共用该布局。

拍速记号统一使用拍号分母对应的音符，不使用附点；数值按 `qpm × 分母 ÷ 4` 换算，谱中变速也遵循此规则。例如《我和我的祖国》的 `6/8`、`80qpm` 显示八分音符 = 160，实际播放仍为 80 qpm。五线谱与简谱共用这一换算规则。

浏览器加载字体后使用 `CanvasTextMeasurer`，离线测试可注入 `textMeasurer`。音符、调号、拍号及拍速数字（包括谱中变速）统一使用原样嵌入的 Barlow Semi Condensed Medium（SIL OFL 1.1），字形比原先的 Liberation Mono 更窄高、笔画更清晰。同一资源用于测量、显示和 SVG 导出，无 CDN 字体请求；固定来源、文件校验和及许可见 `public/licenses/barlow`。CSS 家族别名保持 `M3N Numbers`，静态 Medium 字体映射为引擎使用的普通字重，避免合成加粗。阅读时中文及普通文字使用系统 serif 字体，因此不同系统的文字度量可能不同；下载时文字统一转为本站 Noto Serif CJK SC 字形轮廓。

## 导出与验证

预览与最终导出调用相同接口、版宽和字体准备流程。两种谱式均提供 SVG 矢量图、PNG 连续图和 A4 多页矢量 PDF。导出时数字沿用内嵌字体，中文使用本站按需加载的 Noto Serif CJK SC，文字转成路径，不依赖接收设备字体；文字不可选择或搜索。轮廓坐标先对齐到 0.001px，避免 opentype.js 2 将接近整数的小数舍入为 NaN、造成字形笔画缺失；导出遇到无效坐标会明确失败。PDF 经 svg2pdf.js 写入矢量路径，不嵌入 Canvas 图片。字体许可与重建方法见 `public/licenses/noto-serif/`。

`npm run build:scorebook` 默认只生成精简PDF，直接使用 `outputPdf` 文件名；不生成大体积轮廓PDF。`exportOutlinePdf: true` 可显式恢复轮廓PDF，此时再运行精简命令会另外生成 `-精简.pdf`。`npm run compact:scorebook` 可从最近一次构建保存的 `unoutlined-pages.json` 单独重建精简PDF。命令校验版次、渲染器摘要和全部谱源摘要，拒绝过期布局。导出先按原轮廓流程解析SVG的可寻址字符，处理空白、tspan、UTF-16索引和旋转，将每个字形固定到原来的基线位置；常规字形由Chromium嵌入并共用字体子集，粗体沿用原轮廓版的0.015倍字号描边，不另换粗体字体。使用同一Noto Serif CJK SC和Barlow字体资源，不重新排谱、缩小字号或转为图片。

当前精简PDF共87页、4,722,523字节，纸张558 × 850.08 pt；未生成轮廓PDF。构建逐字检查基线误差不超过0.001px、逐页检查实际纸张边界，并用`pdfinfo`、`pdffonts`、`pdfimages`核实页数、纸张、字体Unicode映射及无栅格图片。本版有120个嵌入字体子集和30,954个定位字形；PDF摘要和逐页字形数量保存在`scorebook/PDF体积记录.json`。设置 `exportOutlinePdf: true` 可显式恢复轮廓PDF流程。
