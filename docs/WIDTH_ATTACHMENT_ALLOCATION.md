# 五线谱附件整理的计算与分配采样

在独立工作树 `perf/lossless-width-v2` 使用归档设计字体、单线程、完整528～720px的6px网格及精确安全剪枝，对《基本功》进行同输入采样。候选准备与精确完成分离，保持三档断行、完整曲线、逐元素避让和最终评分。CPU及堆采样同时开启，本节耗时用于定位，不能作为600ms验收。

## 热点具体在做什么

`arrangeStaffSystem` 的范围包含歌词基线、连音组标记、文字及渐强的避让、谱表间距和最终图元分区，并非只计算附件的位移。它反复读取图元树、筛选音乐／歌词／装饰、合成坐标变换，再把候选图元转换为分页器所需的最终坐标。

当前对照采样中，附件路径约702ms，其中最终几何分区256ms、不可变音乐准备81ms。全次CPU采样约2125ms，GC约207ms；GC不能直接归属到某个附件函数。图元收集 `collect` 约383ms（含多条调用路径），包括树遍历、类过滤、坐标变换和对象构建。上述包含时间互有重叠，不能相加。

分配采样同时纳入已被小回收及大回收释放的对象，因此记录的是累计分配量，而非峰值存活堆：

| 范围 | 原路径 | 直接分区输出 |
| --- | ---: | ---: |
| 全次搜索累计分配 | 685.7MiB | 652.3MiB |
| 附件路径累计分配 | 291.9MiB | 255.3MiB |
| 其中最终分区 | 147.2MiB | 113.9MiB |
| GC采样时间 | 206.5ms | 179.0ms |
| 整次搜索（带双采样） | 2028.6ms | 2059.7ms |

内存分配确实可以减少，但这一次采样没有证明整次提速。不能从分配减少推断附件处理主要耗时在内存，也不能把GC差值当成稳定收益。

## 本轮实现

原最终分区先复制完整边界对象，再按绘制尺度生成另一份对象。新路径通过收集器直接输出最终坐标，保留包含／排除通道，每一次图元出现都独立拥有最终边界；输入仍可借用不可变几何。公开原分区接口继续保留防御复制语义。

不能简单让旧分区借用所有边界：被排除的节点与普通音乐可能引用同一个不可变对象，旧代码用引用身份区分通道，会产生误判。新路径只在最终输出层建立每次出现的独立身份，测试覆盖这一情况、祖先变换、重复测量及输出修改后的隔离。

报告：`.tmp/lossless-v2/v94-{before,after}-profile-staff.json`、对应 `.cpuprofile`／`.heapprofile` 和 `v94-profile-summary.json`。两份采样的赢家／页数／行数、两个共同完成候选的全部评分在1e-8内一致。归档字体与谱源摘要相同。51项相关几何／测量测试通过；完整双谱式600ms目标仍未完成。

## 不带采样的全库复测

117首逐曲新建浏览器、真实归档字体、生产压缩bundle，串行执行。直接分区前后累计选宽41888.5→41596.6ms，均有23首超过600ms；《基本功》1536.2→1545.0ms。因此仅能确认减少累计分配，不能宣称稳定的整体加速。117首赢家、页数、行数及254个共同完成候选的全部评分在1e-8内一致；采样内存守卫峰值808MiB，全库复测813MiB。

全库报告 `v93-layered-all-staff.json`、`v94-stream-all-staff.json`，严格对比 `v94-stream-staff-comparison.json`。上述是相同候选策略下只改变最终几何分区的对照，没有将搜索策略变化混算成附件优化收益。

本轮相关包类型检查通过，269个文件2251项离线用例及全部工具／字体检查通过，23项浏览器回归通过；验证批次聚合RSS峰值1059MiB。未部署该候选调度试验，未将当前结果声明为600ms达标。

## 最新主线的符梁重试与准备复用（v105）

基于已同步主线 `d7153d2a` 的 `a0f7c89c`，重新采集基本功CPU／堆双采样。主线柔性符梁方向策略会逐组重新执行完整行，比较实际整理后的高度。这增加了每次方向试算的准备工作：扫描文档入连线、小节音符／符号准备、水平间距模型生成。它与最终附件避让是两层开销，不能都称为附件整理。

新准备上下文保留一个任务内的入连线集合、歌词设计数据以及小节描述。每次方向试算共享上下文，仅对本小节柔性符梁的实际方向组合生成新的描述；其他小节继续借用不可变准备结果。方向组合缓存每小节、首行状态／谱表模式最多16份，超出时只重算，不省略试算。定位锚点和最终几何仍由各次执行独立持有，完整避让、所有方向比较和最终绘制保持原算法。回归遍历五组符梁的32种组合，往返触发缓存淘汰，比较新准备与独立准备的逐图元和SVG，同时检查原描述不被绘制改写。

上述包含时间重叠，累计分配不是峰值驻留内存，GC无法精确归属某个调用者；双采样计时不用于600ms验收。新的数据支持“重复准备既增加计算也增加分配”，而附件整理本体仍有约640ms的包含时间，单纯减少准备分配没有消除它。采样原始数据为 `.tmp/lossless-v2/v105-{before,after}-basic.{cpuprofile,heapprofile}`，摘要 `v105-profile-summary.json`。

不带采样的生产压缩bundle初测：基本功3097.4→2159.3ms，均选624px／3页／33行，两个共同完成候选全部评分在1e-8内一致。这是当前主线规则下的对照，不能与此前618px的旧版几何结果混合计算收益；仍明显超过600ms，需继续减少重复行执行及几何转换。

117首全库冷测完成：五线谱累计81749.5→61371.3ms（约下降24.9%），基本功3047.4→2136.4ms，超过600ms仍有38首（对照40首）。简谱累计36440.7ms，基本功1234.2ms，仍有11首超600ms；与前一简谱对照36567.0ms相比没有证明本项带来简谱加速。双谱式各117首选宽／页数／行数全部一致，五线谱249、简谱341个共同完成候选的全部评分在1e-8内一致。报告 `v105-all-{staff,numbered}.json`，对照 `v105-{staff,numbered}-comparison.json`。

验证包含272文件2273项全套离线测试、工具／字体检查、23项浏览器回归、密度回归、类型、lint和边界检查，聚合RSS峰值1103MiB。随后补齐未绑定文档或其他文档准备上下文的回退：此时重新准备本次文档的入连线信息，不能借用不匹配上下文；31项针对性回归通过，包含确实因入连线而取消柔性资格的例子。该回退不改变已测生产路径的准备复用，方向试算仍与主线一致。

## 一次分区收集边缘几何与数值音乐类别摘要（v111／v112）

基于 `ace3207f` 的同输入优化，不改变避让顺序、墨迹、评分或搜索范围。把可选预检查门槛从16行降到8行的试验没有保留：117首五线谱累计58417.5→58965.0ms，选宽／页数／行数和249个共同候选评分保持一致，无法证明收益。报告 `v110-eight-all-staff.json`。

最终几何分区原本已经遍历并缩放所有墨迹，随后又递归筛选谱号、复制祖先树、重新收集并缩放谱号几何。现在在同一次分区遍历中收集谱号通道，仍建立独立的最终边缘对象，保持原间距参数和输出顺序。嵌套匹配只收集一次；祖先变换、文字样式及被排除通道保持原语义。v111单项全库五线谱58417.5→57471.3ms，仍37首超过600ms；117首赢家／页数／行数及249个共同完成候选评分在1e-8内一致。基本功单测1654.1ms，不能据此声称大幅加速。

进一步检查发现，静态音乐块遇到未获提前排除的类过滤器时，会先展开数值音乐的虚拟事件／音符节点，再保存所有后代、拆分类名并创建集合。仅为证明某块没有谱号，也会触发此过程。现在类过滤查询直接累计类别集合；内部数值音乐利用已有的完整语义类别摘要，避免虚拟树展开。摘要只能证明过滤器不匹配；可能匹配时仍精确遍历，任意谓词也保留原有后代检查。公开读取器不信任内部摘要，不改变防御复制语义。

新增回归覆盖直接收集与原祖先树筛选路径的逐图元对比、嵌套匹配、动态祖先变换、借用／复制模式、静态缓存、输出修改隔离，以及数值音乐在不相关过滤器下不展开、匹配类和任意谓词仍精确展开。v112五线谱全库55478.9ms（比v109少5.0%），基本功1567.7ms，仍37首超过600ms。117首赢家／页数／行数及249个共同完成候选评分保持一致。
