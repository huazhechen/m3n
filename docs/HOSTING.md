# Code Shell 托管

当前工作区由相邻的 Code Shell 项目将本项目的 `dist/` 挂载到 `/score/`。该目录直接用于提供页面，不是独立的测试输出目录。

构建托管版本（包括在这个工作区验证完整构建）时，使用：

```sh
VITE_BASE_URL=/score/ VITE_SUBMIT_MODE=remote npm run build
```

默认 `npm run build` 会生成根路径 `/assets/` 的资源引用，覆盖托管目录后会导致页面白屏或脚本 MIME 错误。不要在托管目录上用默认参数覆盖构建。只需验证构建时也可使用单独的输出目录，避免影响正在访问的页面。

Code Shell 的 `codesh-sites-sync.service` 监测源码与入口产物变化，并自动按 `/score/` 重建。排查时先检查 `dist/index.html` 是否引用 `/score/assets/`，再检查同步日志：

```sh
systemctl is-active codesh-sites-sync.service
journalctl -u codesh-sites-sync.service -n 30 --no-pager
```

按需仅重建这个托管站点，可在相邻 Code Shell 项目中运行 `node scripts/build-sites.mjs /score`。普通静态页面更新不需要启动开发服务器。

恢复后用真实浏览器打开托管地址，检查首页、资源响应和脚本错误；若页面在更新前已打开，刷新以加载新的入口和资源。

生产构建使用 Vite 默认的按需分包：HTML 只加载应用入口，页面、曲谱正文、播放和导出代码在需要时加载。发布时先生成完整构建，再更新资源与 HTML 入口，最后清理已退役满72小时的哈希资源。超过保留期的旧页面可能仍引用已清理的旧分包；刷新即可获取当前版本。音源和播放模块均按需加载；内置曲库进入时全量加载谱源和三字体TTF共享包，其他页面可按需加载单曲子集。PNG与PDF使用相同字形；字体失败不退回其他字体。

托管构建先在 `.tmp/` 完整生成新版本，再发布资源、最后替换HTML入口，随后清理退役已满72小时的旧资源。这样在构建期间继续提供当前版本，避免资源被提前清空后由CDN缓存404；旧哈希资源从首次不再被当前构建引用时起保留72小时，清理在后续成功构建时执行。

其余独立资源使用Vite默认的内容哈希命名，不追加每次发布的随机版本后缀；相同内容沿用相同URL。入口引用外部哈希脚本和样式，资源先发布，HTML最后原子替换。


Cloudflare 根域名部署保留 SPA 页面回退，但 `/assets/*` 必须先经过 Worker：`wrangler.jsonc` 的 `assets.run_worker_first` 指定该路径。Worker 对不存在的资源以及静态绑定误回退的 HTML 返回 `404 text/plain` 和 `Cache-Control: no-store`，防止旧哈希脚本地址得到带一年 immutable 缓存的 HTML，触发 JavaScript MIME 错误。正常脚本保留原有内容类型和缓存，`/scores/<id>` 等页面仍可直接访问。已打开的旧页面仍需刷新以取得最新资源引用；这项修复需要发布 Cloudflare Worker 配置和代码后才会在线上生效。


此前 HTTPS 浏览器可能已经把 `/assets/<哈希>.js` 的错误 HTML 按 immutable 长期缓存，服务器修复无法直接删除客户端旧缓存。静态资源现统一迁移到稳定的 `/assets/v2/` 命名空间，入口、动态模块、Worker 和音源由 Vite 一起更新引用，绕开原 URL；仍按内容哈希命名，不增加每次构建的随机参数。根首页和 `/scores/*` 页面显式使用 `Cache-Control: no-store`，避免重新打开 PDF 深链接时复用旧 HTML。无需更改 PDF 的 HTTPS 链接。

## 曲库与代码缓存隔离

生产构建将曲库元数据及两个共享资源包的地址、大小写入固定地址 `score-catalog.json`，响应使用 `Cache-Control: no-cache`，浏览器每次启动重新验证目录。应用先读取目录再显示界面；加载失败可点击“重新加载”。进入 `/scores` 后并行下载全量谱源包和三字体 TTF 包，复用到阅读、PNG 和 PDF；两个包分别按内容摘要命名，位于 `assets/v2/`，使用一年 immutable 缓存。新增／修改谱源或分类不再将变化传入应用 JS。普通构建仅校验归档字体并打包，无需 Python；格式、缓存和生成方式见 [共享资源](LIBRARY_RESOURCES.md)。

独立作品目录继续使用逐曲 `fontPreloads`，与谱源并行按需下载 WOFF2，PNG／PDF 使用对应 TTF。内置曲库不再发出这些逐曲字体请求，统一安装共享包中的 TTF，字体失败会阻止排版并允许重试。

简谱的“正在准备字体”阶段等待所需字体完成加载与安装；完成后切换到“正在排版乐谱”，让浏览器先绘制提示再执行同步排版。共享字体安装后在同一页面内复用；切换内置曲目直接读取谱源及字体缓存。刷新后重新解包和安装，通常可复用 HTTP 缓存。

所有常规构建（包括根路径Cloudflare部署和 `/score/` 托管）都先在 `.tmp/` 构建，再发布到 `dist/`。`dist.asset-history.json` 在输出目录之外记录旧资源首次退役时间，不部署到站点；资源重新被当前构建引用会撤销退役。JS、CSS、Worker、音源、字体与谱源等 `assets/` 内文件统一保留72小时，当前构建引用的资源永不因年龄被删除。清理仅在构建成功后执行，不定时唤醒，低频发布时可能保留超过72小时。

本地连续构建应保存 **`dist/` 和 `dist.asset-history.json`**；全新CI检出使用下述线上资源清单恢复机制，或从构建制品恢复这两者。发布工具必须上传保留下来的整个 `dist/`。已有旧资源但缺失记录时，从首次观察到退役开始计时，避免提前删除。`--outDir` 用于隔离验证，不合并历史版本。72小时是源站可用期，浏览器和CDN已有的immutable副本可能缓存更久；超过期限的旧页面仍可能需要刷新。勿在每次发布时全站清空CDN缓存。

## Cloudflare Pages 关联 Git 自动发布

不将 `dist/` 提交到 Git。Pages构建环境（`CF_PAGES=1`）默认从代码中固定的 `https://score.cheesefans.com/` 恢复上一版资源，无需配置环境变量。保持构建命令 `npm run build`、输出目录 `dist`，根域部署不设置 `/score/` 专用环境参数。

需要更换恢复地址时可设置 `M3N_PREVIOUS_DEPLOY_URL` 覆盖默认值，必须填写稳定的已发布站点地址，不能填写本次构建的临时预览URL。本地构建默认只使用本地资源；显式设置该变量也可验证线上恢复。

构建成功后，发布脚本读取上次正式部署的 `asset-history.json`，下载仍需保留的旧资源，并按SHA256及文件长度核验，再与新资源一起发布。清单包含当前资源及尚未过期的旧资源，使用 `no-cache`；下一次构建可在干净工作区重新恢复，不依赖Pages构建缓存。资源首次退出当前构建时开始72小时计时，后续构建保留原退役时间。Pages预览构建也只读取正式站点的历史，预览部署不会写回正式站点或影响后续正式构建的历史。

首次迁移时线上没有清单（404或SPA的HTML回退），允许启动新历史；这次发布之前的旧分包不能自动恢复。后续读取清单、下载或校验失败时构建失败，避免发布缺失历史资源的版本。需要允许构建环境匿名读取正式站点的清单及资源；启用Cloudflare Access时应改用持久构建制品或独立资源存储。本机制假设同一正式分支串行发布；不要同时发布不同正式构建或在控制台直接回滚后立即发布，以免历史清单分叉。

这提供的是“在后续发布中保留退役不足72小时的资源”：没有新发布时旧文件不会在满72小时瞬间删除。Pages上保留的旧部署快照不能替代这一步，因为正式域名指向新部署，旧页面仍会向正式域名请求旧哈希地址。
