# 门禁与测试去重

## 修复的门禁契约

真实字体密度门禁把《玛丽有只小羔羊》的历史两行排版、《基本功》的整句同排当成硬约束。普通 `---` 是可自动换行的乐句分隔，不能固定历史分行。现在保留原来的高度、行数上限、字号、事件数和墨迹检查；《基本功》额外验证谱源 `{br}` 指定的小节26必须位于行末。密度统计中的非有限数及空布局也会失败。

## 共用基础设施

`tools/verify-project.mjs` 编排完整、本地工具、浏览器、端到端和CI检查，记录每阶段及总耗时到 `.tmp/verification-<mode>.json`。报告同时记录120秒目标是否达成，失败不会标为完整。完整入口只构建包一次，包构建本身执行严格类型检查；网页构建复用这些结果。

所有 Chromium 启动选项集中在 `tools/lib/chromium-options.mjs`，本地及CI均使用Playwright配套浏览器，允许显式 `CHROMIUM_PATH`，不再使用容易崩溃的单进程模式。`browser-pages.mjs` 在小批量内复用浏览器，每个输入仍使用全新的上下文，批次结束释放原生字体缓存。

完整集成阶段复用同一函数，可在离线阶段通过后单独重跑。两套全库SVG审计脚本及重复截图入口已删除，统一使用已有的双谱式密度／墨迹回归；`test:numbered-layout` 和 `test:staff-layout` 保留为兼容入口。全库视觉诊断需要时手动运行密度工具的 `--all`，不纳入常规门禁。

单测配置集中在 `tools/vitest-settings.ts`，各包只声明自己的文件入口和超时。

宽度候选排序与谱集赢家缓存共用 `compareWidthMeasurements`，不改变搜索、评分或几何算法。

## 内存和性能验收

重检查串行执行，单worker，Node堆384MiB，聚合内存守卫默认1700MiB停止，低于项目2GB上限。网页构建写入隔离目录，避免覆盖托管的 `/score/` 产物。

120秒目标适用于完整 `npm run check`，包含离线、布局、浏览器和端到端检查。不能仅凭单元测试通过或缓存命中声明达标。直接关闭文件隔离会污染字体缓存及DOM原型，未采用。Vitest统一使用一个线程并复用环境，每文件通过 `test-file-setup.ts` 重置生产模块、全局替身、环境变量、计时器和DOM；弹窗测试共用可恢复原型描述符的替身。两种谱式及应用均需全量和打乱顺序验证。测试必须恢复自定义原型修改及事件监听，不能依赖新建进程隐式清理。VM池的跨上下文比较试验未采用。

## 本地实测（2026-11-28）

单worker、受限堆和聚合内存守卫下，完整入口的离线阶段 `npm test` 最新为101.18秒（2453项测试），包含包构建；本轮多次实测99.82～101.18秒，此前同环境约195.53秒。简谱1118项约46秒、五线444项约15秒、根应用488项约19秒。三组同时通过固定种子20261128的打乱顺序验证，用于检查复用环境后的状态泄漏。CI同等入口 `CI=1 npm run check:ci` 为33.65秒。

**120秒完整目标仍未达成。** 离线入口或CI门禁低于120秒，不代表包含真实字体、完整字形及全部页面端到端的完整检查已达标。耗时报告明确区分测试完成和120秒目标。

最终 `npm run check` 串行一次跑通，报告 `complete=true`、`code=0`、`withinTarget=false`；191项端到端全部通过。聚合RSS峰值1656MiB，低于2GB上限。
