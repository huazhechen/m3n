# 谱集与网页统一渲染

当前全量生成与一键刷新流程见[第七十五版](SCOREBOOK_V75.md)，行距规则见[第七十四版](SCOREBOOK_V74.md)；组合算法沿用[第六十九版：疏密均衡与精确合页](SCOREBOOK_V69.md)。下文保留此前版本的生成记录。

第六十版起，本说明取代 `NUMBERED_NOTATION.md` 中第五十五版等历史谱集排版记录。谱集没有独立的排谱策略，只在网页渲染结果之间选择宽度，然后缩放到A4。

## 渲染与页面

`tools/scorebook-layout.mjs` 直接调用 `src/lib/render-score.ts` 的 `renderScoreInto`，传谱面文档、版宽和分页模式；合页容量检查采用各曲最小核心净空（默认1.2em，即26.4px，谱头 `{leading=…}` 可覆盖）的最大值。不改临时文档，不注入文字测量器，不注入逐曲间距、不隐藏署名或低音，不重新分行或切页。合页复用同一引擎测量的完整谱行，在整页统一提高核心净空后输出各曲连续SVG。基本功也使用同一入口，其等宽小节来自谱头 `{equal-measures=true}`。

统一应用入口的谱内页边距为0，留白由A4纸张或外部画布提供；行尾小节号按实测文字右边缘对齐小节线，标签越界时向内收回；底层引擎仍允许调用方显式指定边距。谱行核心区按音符横向占宽加权，包含圆滑线、延音线和三连音数字／括线的局部边界；歌词保留完整实际占位，详细规则见[简谱渲染](NUMBERED_NOTATION.md)。默认连续模式相邻两行核心区之间至少留1.2em（26.4px）；默认分页模式按此下限判断分页，再逐页统一提高核心净空参数至26.4～32px内可容纳的最大值（包含末页），每处仍取核心要求和碰撞要求的最大值，碰撞净空随核心参数取一半（13.2～16px），碰撞主导的间距也随之调整；表情、奏法、倚音、发夹及其他核心区外图形超出核心区时，按实际横向碰撞保留核心参数一半的净空，只增加必要距离。行内具名段落的12px段间距继续额外保留，页首不叠加；独立段落标题按装饰参与核心参数一半的局部碰撞避让，与当前核心净空所需距离取最大值，不额外叠加段间距。所有距离与音符、歌词、线条一起等比缩放，分页和合页默认采用26.4～32px核心参数规则，各曲可通过谱头 `{leading=…}` 设置最小核心净空，参数单位为音乐字号的em，当前仅基本功设置为0.8em（17.6px），分页在17.6～32px内拟合，连续模式为17.6px。网页、打印预览与谱集使用同一设置。

分页沿用网页的A4内容比例273/186。每个原生SVG页通过网页导出的 `a4ImagePlacement` 等比放入210×297mm纸张，四边至少12mm；内容顶部对齐，水平方向居中。只修改最外层SVG的位置与尺寸，不移动内部图元。长曲自然分为多页，每首独立起页；同一篇内相邻短曲允许合页，不跨篇、不拆曲。封面、目录和章节顺序属于谱集装订信息。

## 最佳宽度

独立曲目遍历540～720px，步长10px，共19个候选；每个候选验证W−5／W／W＋5三个宽度，页数必须一致，内部断行不要求一致。相邻候选复用重复宽度，57个验证位置只渲染39个独立宽度。浏览器完成字体加载后检查实际图形边界、音符和歌词重叠；渲染失败或检查不合格的候选不参与选择。所有候选均失败时构建报错，不静默放宽几何标准或使用旧宽度。

选择顺序明确为：

1. 全谱集总页数最少，包括相邻短曲合页。
2. 同页数时所有曲目版宽之和最小，使A4中的音符尽量大。
3. 两者相同时优先让前页容纳更多完整曲目。

`tools/scorebook-packing.mjs` 按原顺序动态规划。独立曲目仍按原生页数、版宽选择；组合页固定使用640px，不参与宽度搜索；合页中每首曲目必须在640px下通过分页和连续模式的安全检查，且原生只有一页。按谱头最小核心净空（默认1.2em，即26.4px）得到的完整连续SVG高度加曲间最小32px留白须能装入A4版心；合页确定后复用各曲测量结果，为整页共同寻找26.4～32px的最大可容纳核心净空参数，再将剩余高度按曲数平均分配为各曲的额外段后距，末曲后也保留同样一份，首曲顶部对齐版心，曲间原有最小32px留白另计；保留每首的标题、署名和低音，谱内边距为0。所有曲目使用640px逻辑宽度和同一缩放比例，不分别缩小来凑页；另检查635／645px下同一组合仍能合页。组合页成员的单曲最佳宽度按约定直接设为540px，报告以 `width` 记录单曲建议、`bookWidth` 记录实际谱集版宽。`sharePage: false` 禁止该曲合页，`breakBefore: true` 强制曲首换页。报告的 `sharedPages` 记录合页宽度、成员和纵向位置。

“最佳”指满足上述规则的候选，不是全整数宽度或人工审美判断。试排不修改源码中的显式换行和等宽标记，也不为减少页数改变音乐内容。

PDF生成并验证成功后，独立曲目的稳定候选宽度、合页成员的固定540px写回每首谱源的 `{preferred-width=…}`，并提交Git。网页解析器、曲库元数据和渲染入口统一读取该字段，缺省720；显式传入的阅读版宽优先。字段只允许在谱头声明一次，值为320～2560之间的整数，单位为逻辑px。更改源谱和渲染器后重新构建可更新最佳宽度，完整候选与拒绝原因保存在本地报告。回写前核验全部源文件摘要，拒绝覆盖试排期间的修改。

## 构建和检查

### 在线导出

乐谱库顶部的“导出谱集”在浏览器中生成全部内置曲目的谱集，不受当前搜索、排序或本地作品影响。使用各谱源已保存的建议版宽作为独立曲目宽度，不做540～720px搜索或±5px稳定性检查；额外只测量合页固定宽度640px。前端不执行逐图形的边界、碰撞复查，也不在测量阶段生成SVG。每首仅解析一次，每个所需宽度创建一个 `PreparedNumberedNotationScore`，从引擎已测量的谱行直接取得页数和连续高度；最终独立页和合页复用这些布局。合页仍按引擎共同核心行距规则拟合，A4放置规则保持一致，分组复用 `tools/scorebook-packing.mjs` 的章内动态规划／精确子集算法。后台脚本保留 `tools/scorebook-layout.mjs` 的完整图形校验。读取同一份 `config/scorebook/editorial-plan.json`，保留前两章顺序、后四章可重排设置、禁止合页和强制换页约束。曲间留白至少32px；先拟合统一谱行净空，再把版心剩余高度按曲数均分为每曲的额外段后距，包含最后一曲；曲间原有最小32px留白保留，页首不加留白；只在整首曲目安全装入同一页时合页，不拆曲。前置页面与脚本使用相同的封面和28行双栏目录规则（行距由37px缩至35px，曲名字号16px、页码14px保持不变，当前97首及六章标题共两页；参数统一读取 `editorial-plan.json` 的 `contents`），按实际合页结果计算页码。

进度对话框区分排版计算、合页优化和最终页面生成，显示已完成曲数、总曲数和当前曲名，测量与逐页排版之间让出浏览器主线程，可取消或失败后重试；取消与离开页面会终止后续排版并清理临时容器。全部完成后点击“保存PDF”，与单曲共用矢量生成器直接下载，与单曲复用 `PdfDownloadPanel`，显示模块加载、分页准备、音乐字体、逐页生成及打包阶段；生成中可取消，失败可重试。打开单曲预览或开始谱集排版时即预加载PDF模块，重复音符和文字在单次生成中复用编码，保留网站链接，不添加浏览器页眉页脚。嵌入谱面已有的Barlow音乐数字字体子集；普通文字下载预置字体并检查整份文档覆盖，全覆盖时嵌入，缺字或下载／解析失败时整份回退到未嵌入的STSong-Light与Times系列声明。不请求后台生成接口。回退时普通文字的跨设备外观与罕见字符覆盖不作保证。生成模块及曲谱正文按需加载，失败不导出不完整谱集。

每次导出重新读取曲谱并生成谱集，不缓存整本结果，也不跨次保留布局。单次生成中的解析与布局对象在完成、失败或取消后释放；只把最终SVG页面交给共享PDF生成器；离开页面会取消后续PDF生成，不触发下载。在线导出不写入谱源、建议版宽或用户设置。建议版宽的重新搜索、±5px稳定性检查与回写由以下独立脚本负责。在线版省略宽度搜索和扰动检查，排版使用设备字体，PDF普通文字由阅读器替换；更换设备或谱源宽度后不保证页数与某个既有发布PDF完全相同。

当前97首全量浏览器验收为81页、17个合页，逐页曲目组合与顺序均与第七十五版后台布局记录一致；A4与无栅格图片检查通过。单元测试额外验证在线版只测量优选宽度和640px、同一曲目共用一次解析、独立曲目不会被合页候选宽度替换，以及重新导出、取消、排版失败和禁止合页设置。引擎测试比较复用布局与独立新排版的分页、连续、共同行距SVG完全一致。

本机同一浏览器下，移除前端逐图形复查并复用单次布局后，97首生成耗时从约57秒降至约20秒；最终页面生成阶段从约10秒降至约1.7秒，均不含后续PDF生成和下载时间。这是当前设备与曲库下的测量结果。优化前后81页的曲目组合与顺序一致，逐页按72dpi转为图片比较无像素差异；全量导出和移动端取消测试通过。

### 独立脚本

一次执行全量刷新与版宽回写：

```sh
node tools/refresh-score-pdfs.mjs
```

脚本可从任意工作目录调用，依次构建渲染包、搜索全库稳定版宽并生成和校验整册PDF、回写谱头建议宽度、刷新全部单曲PDF和现有校验稿。使用 `config/scorebook/editorial-plan.json` 中的版本和输出路径，重复执行会刷新该版本；需要新版时先修改配置。任一步失败立即停止，后续步骤不会执行。依赖已安装的项目npm包、Chromium和Poppler命令（`pdfinfo`、`pdffonts`、`pdfimages`）；不启动开发服务器。PDF与详细报告仍按下述规则作为本地生成物保存，谱头回写需要提交Git。

运行 `npm run build:scorebook`。`node tools/build-scorebook.mjs --probe-only` 仅完成全库宽度试排，在临时目录保存 `width-probes.json`，不输出PDF、不回写。调整目录和分类后，可用 `--reuse-widths=报告路径` 复用试排；先核验渲染器与字体摘要，再逐曲核验源文件摘要，变化的谱源自动重新试排。无需开发服务器：Vite只构建离线浏览器包，Playwright通过本地路由提供资源，不访问外网。构建先保存原生页面，再共用导出字体子集打包矢量PDF；打包只保持已排字形的基线，不重新排谱。PDF使用真实A4尺寸，检查页数、嵌入字体、无栅格图片及导出越界。只有PDF成功生成后才回写谱头建议宽度。

`npm run test:scorebook` 检查共同宽度合页、顺序与篇章边界、容量和宽度选择规则、网页与谱集SVG一致、A4只缩放外层、署名／低音／替代声部保留及长曲原生分页。生产构建验证网页能够直接读取谱头的建议宽度。`.tmp/scorebook-v63-web/index.html` 和 `pages/` 提供本地逐页预览。

PDF封面标题和显示的网站地址链接到 `https://score.cheesefans.com/`；正文每首曲目的标题链接到该站的 `/scores/<谱源文件名去掉.m3n>`，不使用谱集内部的短ID。合页中的每首标题分别定位链接，多行标题逐行覆盖；目录保持原样。链接在最终PDF中作为透明注释区域添加，不改变标题外观、谱面排版或最佳宽度搜索。打包后使用 `pdfinfo -url` 核验首页和全部曲目的链接均实际存在。

运行 `npm run export:score-pdfs` 可在整册生成和宽度回写后刷新全部单曲PDF及现有校验稿；它使用已验证的同版渲染器，逐份检查页数、A4、矢量、嵌入字体和链接，全部成功后再发布。

PDF、布局和体积报告、排序CSV仍为本地生成物，不提交Git。`npm run compact:scorebook` 可以根据最近构建的页面重新打包PDF；旧逐曲字号保留和谱集回流逻辑已删除。

## SVG与PNG留白

网页连续渲染在SVG外四边各留谱面宽度6%的白底留白，谱内边距为0。容器总宽为谱面宽度的112%，CSS内边距按容器宽度的6/112计算，手机与桌面一致；不改变SVG内部排版或导出内容。网页分页模式展示完整210×297比例的A4纸张，SVG放入四边12mm的版心，顶部对齐、水平居中；桌面适屏计算也按整张A4纸的比例进行。

图片导出在所有已渲染页面外添加一层白底SVG画布，四边各留原谱最大宽度的6%。例如640px谱面四边各留38.4px，总宽716.8px。内部SVG只平移，不重新排版；多页先按原高度纵向拼接，再为整图加一次外框。SVG和PNG共用 `frameScoreImage`，PNG按带框后的尺寸栅格化。PDF直接使用12mm纸张边距，不叠加这层6%外框。

## 在线PDF预置文字字体

网页、预览和PNG继续使用系统文字字体。所有PDF导出（内置、本地、分享单曲及全谱集）开始生成时才下载预置字体；整份PDF普通文字全部覆盖时才嵌入并进一步按文档裁子集，任一字符缺失或字体下载／解析失败时，整份PDF回退到现有的不内嵌文字字体方案。音乐数字仍单独嵌入Barlow。预置文字字体不注册到浏览器，不影响SVG排版坐标；标题粗体使用模拟加粗。

预置子集为 `src/assets/builtin-pdf-text.ttf`，包含当前曲库及谱集标题、目录、排版文字的保守字符集合。生成后记录1,794个字符、604,488字节，摘要见同目录JSON。完整16MB字体仍只留在 `tools/fonts/`。Vite为子集生成带内容哈希的资源URL，兼容 `/score/`；只在PDF生成时请求，浏览器可正常缓存该资源。

离线／构建机生成方式：

```sh
python3 -m venv .tmp/font-subset-env
.tmp/font-subset-env/bin/pip install fonttools==4.68.0
M3N_FONT_PYTHON=.tmp/font-subset-env/bin/python node tools/prepare-builtin-pdf-font.mjs
```

生成脚本将CFF轮廓转换为TrueType，以兼容浏览器中的PDF子集处理；读取当前全部谱源、谱集配置和渲染文字字符，按完整Noto字体可覆盖的字符裁切并验证结果。生成的TTF及JSON提交Git，普通 `npm run build` 仅校验字符集与字体摘要，无需Python依赖。曲库新增字符后先运行生成脚本；构建遇到过期子集会报错，避免发布遗漏。也可用 `node tools/prepare-builtin-pdf-font.mjs --check` 单独检查。字体许可证为SIL OFL 1.1，见 `public/licenses/noto-serif/`。
