# 自研音乐引擎迁移

## 目标与边界

替换 Verovio 的 MEI → MIDI / 时间查询链路，以及 jpFun 的脚本解析、布局和 SVG 绘制。音乐输入统一为 `ScoreDocument`，不复制、改名或重新授权第三方引擎源码。React、编辑器、音频合成器、字体及 PDF 库继续承担各自职责；“自研”指音乐语义、演奏编译和简谱排版，不意味着重新实现浏览器或通用库。

已有未提交的应用和排版改动继续保留；迁移提交只包含本次增量。

## 设计

- 领域层：纯 TypeScript 演奏编译器，复用领域反复计划、绝对音高解析、稳定事件身份。输出音符、速度、拍号和源码事件的演奏遍次；不依赖 XML、DOM、WASM 或音频设备。
- 播放层：标准 MIDI 文件写入器及索引，同一份量化时间轴驱动 MIDI、播放高亮和音符定位。SpessaSynth 只消费 MIDI，不再解释乐谱。
- 简谱层：直接将领域事件转换成有类型的排版对象；分别完成文字测量、声部共享时间列、小节与行分配、关系避让、分页和 SVG 绘制。不引入第二套脚本语言。
- 交互：逻辑事件 ID 与视觉片段 ID 分开；连音组、增时线、反复歌词和替代旋律继续映射到原领域事件。

## 验收

1. 演奏覆盖绝对音高、变音作用域、休止、多小节休止、和音、连音组、延音、倚音、琶音、变速、反复、房子、导航、顺序、替代旋律和双声部。
2. 简谱覆盖现有文档的全部音乐记号、歌词、关系、标题、排版选项、窄屏及分页；曲库实际浏览器检查边界和相交，屏幕与导出使用同一引擎。
3. 生产依赖与产物不包含 Verovio、jpFun 或其派生引擎；旧实现仅在迁移期间充当对照，不能作为最终运行时回退。
4. 更新架构、资源和构建文档，运行完整质量门禁，按已验证阶段提交。阶段通过不代表整体完成。

## 演奏兼容策略

旧 Verovio 默认输出的多数普通音符力度为 90，部分力度／奏法仅有视觉表达。替换优先保持已有演奏；增强奏法应有明确的独立行为测试，不能把旧引擎恰好忽略的功能当成已实现。MIDI 量化及倚音处理的差异必须记录并验证；测试不能通过更新指纹掩盖未解释的差异。

### 本次明确的行为差异

- 倚音统一采用拍内借时：短倚音每个占四分音符的 1/16，长倚音组占主音一半，多个组总计最多占一半；主音开始相应后移。原版会根据前音和速度将部分短倚音提前到拍点之前，已不作为新引擎的隐式规则。琶音相邻音相差 1/16 四分拍，并限制在主音前半段内。
- 延音按实际演奏顺序且按书写目标连接。《黄昏》第三遍 187.5–188.5 拍、《青鸟》第三遍 359.5–362 拍、《三步》第三遍 331.75–336 拍保留完整延音，不沿用原版在末段再次起音的行为；这些起止点有独立回归断言。
- 《Besame Mucho》最后的三个四拍 `6^^~ | 6^^~ | 6^^` 演奏到第 320 拍；原版 MIDI 最后四拍提前结束。新引擎按领域总时值保留尾音。
- MIDI 使用 960 PPQ，时刻查询使用相同量化和速度积分。普通音符保留 1/120 四分拍的释放间隙；文件末尾发送静音通道消息，让 SpessaSynth 保留谱中末尾休止，纯休止谱也有正确总时长。
- 上述差异解释了 88 首对照中 9 首的差异；其余 79 首的音符起点、音高与通道在 0.03 四分拍容差内一致。该对照不等同于逐字节 MIDI 相同，也不证明所有演奏效果已实现。
