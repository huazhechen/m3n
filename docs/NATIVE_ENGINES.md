# 自研音乐引擎迁移

## 目标与边界

替换 Verovio 的 MEI → MIDI / 时间查询链路，以及 jpFun 的脚本解析、布局和 SVG 绘制。音乐输入统一为 `ScoreDocument`，不复制、改名或重新授权第三方引擎源码。React、编辑器、音频合成器、字体及 PDF 库继续承担各自职责；“自研”指音乐语义、演奏编译和简谱排版，不意味着重新实现浏览器或通用库。

已有未提交的应用和排版改动继续保留；迁移提交只包含本次增量。

## 设计

- 领域层：纯 TypeScript 演奏编译器，复用领域反复计划、绝对音高解析、稳定事件身份。输出音符、速度、拍号和源码事件的演奏遍次；不依赖 XML、DOM、WASM 或音频设备。
- 播放层：标准 MIDI 文件写入器及索引，同一份量化时间轴驱动 MIDI、播放高亮和音符定位。SpessaSynth 只消费 MIDI，不再解释乐谱。
- 简谱层：直接将领域事件转换成有类型的排版对象；分别完成文字测量、声部共享时间列、小节与行分配、关系避让、分页和 SVG 绘制。不引入第二套脚本语言。
- 交互：逻辑事件 ID 与视觉片段 ID 分开；连音组、增时线、反复歌词和替代旋律继续映射到原领域事件。

## 验收

1. 演奏覆盖绝对音高、变音作用域、休止、多小节休止、和音、连音组、延音、倚音、琶音、变速、反复、房子、导航、顺序、替代旋律和双声部。
2. 简谱覆盖现有文档的全部音乐记号、歌词、关系、标题、排版选项、窄屏及分页；曲库实际浏览器检查边界和相交，屏幕与导出使用同一引擎。
3. 生产依赖与产物不包含 Verovio、jpFun 或其派生引擎；旧实现仅在迁移期间充当对照，不能作为最终运行时回退。
4. 更新架构、资源和构建文档，运行完整质量门禁，按已验证阶段提交。阶段通过不代表整体完成。

## 演奏兼容策略

旧 Verovio 默认输出的多数普通音符力度为 90，部分力度／奏法仅有视觉表达。替换优先保持已有演奏；增强奏法应有明确的独立行为测试，不能把旧引擎恰好忽略的功能当成已实现。MIDI 量化及倚音处理的差异必须记录并验证；测试不能通过更新指纹掩盖未解释的差异。

### 本次明确的行为差异

- 倚音统一采用拍内借时：短倚音每个占四分音符的 1/16，长倚音组占主音一半，多个组总计最多占一半；主音开始相应后移。原版会根据前音和速度将部分短倚音提前到拍点之前，已不作为新引擎的隐式规则。琶音相邻音相差 1/16 四分拍，并限制在主音前半段内。
- 延音按实际演奏顺序且按书写目标连接。《黄昏》第三遍 187.5–188.5 拍、《青鸟》第三遍 359.5–362 拍、《三步》第三遍 331.75–336 拍保留完整延音，不沿用原版在末段再次起音的行为；这些起止点有独立回归断言。
- 《Besame Mucho》最后的三个四拍 `6^^~ | 6^^~ | 6^^` 演奏到第 320 拍；原版 MIDI 最后四拍提前结束。新引擎按领域总时值保留尾音。
- MIDI 使用 960 PPQ，时刻查询使用相同量化和速度积分。普通音符保留 1/120 四分拍的释放间隙；文件末尾发送静音通道消息，让 SpessaSynth 保留谱中末尾休止，纯休止谱也有正确总时长。
- 上述差异解释了 88 首对照中 9 首的差异；其余 79 首的音符起点、音高与通道在 0.03 四分拍容差内一致。该对照不等同于逐字节 MIDI 相同，也不证明所有演奏效果已实现。

## 视觉一致性验收修正

初次候选曾切换应用，但只完成语义、边界与碰撞验证，缺少与 jpFun 的逐曲几何及截图对照。用户指出所有曲目的行距和音符间距偏差后，已恢复 jpFun 为默认显示与导出；自研播放保持接入。候选排版不得宣称完成或与 jpFun 一致。

主要缺口：候选按固定图元留白及每行独立比例分配宽度，未复现原版的左右弹簧约束；纵向使用固定上／下包络和累加预留，未复现原版局部附件范围与轴间距求解。这会同时改变音符间距、换行、行距及分页。调整单个全局常数不足以证明修复。

对照工具 `tools/compare-numbered-engines.mjs` 从固定 Git 版本 `dbfda72` 读取基准实现，在同一浏览器和字体下，比较整个内置曲库的逐事件坐标、行内事件分配、谱行基线与页数，可生成左右并列截图；`--all-widths` 覆盖 320/600/800/1000px 及连续／分页。`--pixels` 增加相同浏览器下的逐通道像素检查及差异图；`--require-parity` 强制启用像素检查，在几何或像素任一组不一致时失败。坐标容差 0.5px，像素要求同尺寸且零差异；不能用更新基准消除差异。报告按运行时间独立保存，不引用历史截图。

表情演奏扩展暂停，优先处理视觉一致性。强弱、连续变速、装饰音展开仍是待实现增强，不应在本次恢复显示后宣称已完成。

首轮记录：88 首 × 4 个版宽 × 2 种分页模式，共 704 组均有几何差异；800px 连续布局已保存全部曲目的并列截图。基准与自身比较的 88 组全部一致，校验对照管线。恢复默认 jpFun 后，完整单元／类型／生产构建与 728 组几何检查通过；端到端测试使用独立构建目录，38 项通过。

### 第一轮间距修正（2026-11-16）

候选已改用共享时间列的弹簧约束，区分物理占位、最小留白与弹性余量；修正普通八分音符误留附点空间、变音左右占位、低八度和音叠放、声部净空、歌词字号及谱头高度。标题布局与绘制共用测量结果，等行高的歌词增量也使用实际行高。新增 9 项约束及基准坐标回归，简谱包全部 527 项测试通过，类型检查和 lint 通过（仍有既有警告）。

完整 704 组几何对照由 0 组通过提升到 88 组通过，仍有 616 组差异；800px 连续布局的 88 首中 14 首通过几何检查。《欢乐颂》该版宽下的换行分配、逐音纵坐标、行距与总高度对齐，最大横坐标差约 0.26px。逐像素检查仍有 7015 个像素差异（画布的 1.403%），包括声部括号、弧线及谱头符号；不得据此宣布复刻完成。基准与自身的该曲像素检查为零差异。

后续继续处理局部附件约束、连线包络、等宽小节、窄屏断行与分页留白，并扩大像素审计。默认显示和导出继续使用 jpFun，候选不接入生产入口。

### 分页兼容规则

候选将谱头和正文作为已测量的块分页，完整页的余量按 jpFun 现有规则参与行间分配，末页保留自然行距，段落额外间距不带到页首。等行高模式继续保留固定节距。新增 4 项分页回归，简谱包 531 项测试通过；全矩阵几何通过数为 100/704，仍有 604 组差异。

余量分配是兼容基准行为，不应直接视为理想产品默认：它会使相同乐句的行距随页容量改变。候选提供独立的 `justifyPages` 开关，与音乐包络是否等高分开控制。默认显示与导出仍是原 jpFun；用户已选择最终自研引擎默认自然行距，因此候选默认 `justifyPages: false`，显式设为 `true` 才启用 jpFun 兼容的完整页余量分配（等行高仍保持固定节距）。对照工具显式传入该兼容选项，并在报告中记录和标明，不能为了几何通过而掩盖此选择。

### 连梁与跨行连线修正

八分休止符继续参与所在拍组的连梁及横向弹簧；小节线相邻两侧使用边界碰撞约束，避免在压缩行中按普通音符的软约束处理。跨行连线使用 0.45em 弧高，不再按同行的 0.5em 上限预留，从而消除逐行累积的 1.1px 差异。《虫儿飞》四版宽、连续／分页的 8 组几何检查全部通过，横向与跨行纵向结果已固定为回归用例。连梁修正后的全量几何检查为 136/704；这一轮全矩阵尚未包含随后补上的跨行弧高修正，不据单曲结果推算全曲库通过数。像素验收仍未通过。

双声部连接符已由共享列计入测量，断行容量不再额外扣除 22px，避免重复预留。《欢乐颂》600px 连续布局恢复为 4/4/4/5 小节，四版宽及两种分页模式的 8 组几何对照全部通过；新增断行回归及候选曲库测试共 171 项通过。包含以上修正的最新完整矩阵为 146/704 组几何通过，仍有 558 组差异，尚未达到视觉复刻要求。
