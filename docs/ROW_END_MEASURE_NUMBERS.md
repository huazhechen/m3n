# 行末小节编号与不可见占位

2026-11-18，真实浏览器的选项组合审计发现：开启小节编号后，八份输入四宽／连续分页64组只有42组几何通过、40组图元通过。秋樱、凉凉、第二圆舞曲出现整体行距及连线差异；默认不编号的完整矩阵不能替代这个选项的验收。修前报告 `.tmp/numbered-parity/2026-11-17T16-12-30.026Z-2430230/`。

原因位于jpFun适配器：投影给每个小节线都生成编号，排版完成后SVG层才删除行内编号。不可见的编号仍是宿主高度与连线避让障碍。两位数又使用文字默认的首字锚点，整段墨迹偏离小节线；共享反复起点在自动换行后，会把前一小节编号带到下一行。自研仅为行末小节生成编号且使用整体居中，这三项不应通过拟合自研来保留。

参考适配器现在仅在开启编号时分两步处理：先用无编号投影求横向断行，从音乐宿主的行、时刻与小节身份确定实际行末；再只对这些小节生成编号，并将已确定的完整小节边界写入本次临时投影的换行。跨行拆分的小节只有包含其最后音乐宿主的行可以编号。共享反复边界在换行时分别保留前行结束线与后行起始线，编号留在前行。第二次编译让可见编号的实测墨迹正常参与弧线及行距；不再留下被绘制层删掉的障碍。

这里的换行只属于每次渲染临时生成的jpFun输入，不修改、冻结或恢复编辑器里的M3N。未开启编号的渲染仍按原路径编译一次。编号使用整段墨迹居中，字号和层间净空不变；不调整小节编号的边距、占宽或外伸策略，用户已采用的0.5em内边距继续负责页面余量。自研排版与用户负责的导出代码均未修改。

## 全库后续发现的小节内部断行

原因是第二次投影把已编号的完整小节边界变为临时强制换行，却没有保留原先小节内部的分行。分段测量后再次优化会改变窄行。只限制反复起点也不充分，104组对照仍有6组失败，报告`.tmp/numbered-parity/2026-11-17T16-52-19.858Z-2476106/`。

现在第二次编译复用第一次无编号排版的所有音乐行起点，以精确拍数分数字符串传入jpFun的`resolvedLineStarts`。流水线在当前投影中按拍数与声部找到插入位置，零时值控制与后续音符共同行首，已有显式换行不重复插入；共享反复拆分仍用原有通用边界逻辑。未提供该选项时按原先自动优化路径运行。编号分支不再优化第二遍断行，每次渲染仍重新读取当前领域文档、计算无编号排版，不保存跨渲染结果或更改谱源。
