# 五线谱选宽性能

## 测量口径

2026-11-24，固定实现版本 `91deccbb`，覆盖 `src/scores` 的106首曲库乐曲和 `src/works` 的1首独立作品。每首遍历480～720逻辑px、步长20，共13档、全库1,391个候选。使用生产 `measureStaffWidth` 和共享择宽流程：最少页数优先，再按综合质量评分选优。

正常基线不安装诊断埋点或CPU采样，不运行独立SVG越界／碰撞审计，仍完整执行引擎内部避让。计时包括候选布局内的字体准备、投影、谱头、间距试排、谱行绘制、避让、分页及评分，不含最终SVG输出转换、PDF或整本合页。页面交互的候选间让出绘制时间不计入此计算基线。

每首开启新浏览器，避免模块状态跨任务复用；浏览器启动、加载测量包的时间单独记录。字体资源由本机提供，不包含公网下载延迟。本轮未增加缓存或修改排版实现。主工作区有其他任务，使用独立工作树固定源码及构建产物；同机仍有其他进程，因此观测值不代表独占机器的上限。

## 复测

```sh
npm run build:packages
node tools/benchmark-staff-widths.mjs --output=.tmp/staff-baseline/round-1.json
node tools/benchmark-staff-widths.mjs --instrument --output=.tmp/staff-baseline/instrumented.json
node tools/benchmark-staff-widths.mjs --profile --score=mei_li_de_shen_hua,mozart_k545,flower_dance,ban_yin_jie_kou_qin_ji_ben_gong,man_man_xi_huan_ni --output=.tmp/staff-baseline/profile.json
node tools/summarize-staff-width-benchmarks.mjs .tmp/staff-baseline/round-1.json --instrument=.tmp/staff-baseline/instrumented.json --profile=.tmp/staff-baseline/profile.json --output=.tmp/staff-baseline/summary.json
```

工具直接构建并拦截本地资源，不启动开发服务器。可用 `--scope=scores` 排除独立作品，`--score=` 接受逗号分隔的文件名子串，`--limit=` 用于试跑。报告逐首原子保存检查点；只有 `complete:true` 才可汇总。生产基线可传入多轮报告，汇总器核对源码／渲染包摘要及全部候选语义结果，输出中位数。不能把诊断耗时当作生产基线。

诊断通过构建插件包装阶段调用，不修改生产源文件。分段时间包含子阶段，不能将父子阶段相加。CPU采样与阶段诊断分开运行；采样只覆盖选定曲目，其百分比不是全库墙钟占比。汇总器核对诊断全库和采样子集的每个候选及最终选宽。

原始报告及CPU采样保存在 `.tmp/staff-baseline/`，不提交临时生成物。

## 正常基线结果

环境：Intel Core i5-8400 @ 2.80GHz，Node v26.13.1，Chromium 157.0.8103.38。两轮使用相同源码快照及渲染包；1,391个候选和107首最终选宽全部一致，失败候选为0。

| 项目 | 首轮（同机有其他高负载任务） | 复测（其他高负载任务结束后） |
| --- | ---: | ---: |
| 逐曲选宽墙钟之和 | 492.617秒 | **336.871秒** |
| 浏览器内搜索 | 491.428秒 | 336.247秒 |
| 候选布局之和 | 487.972秒 | **333.917秒** |
| 每首新浏览器启动及加载测量包之和 | 178.955秒 | 130.130秒 |
| 整轮流程 | 691.059秒 | 480.589秒 |

当前性能参考取复测的336.871秒，约5分37秒，平均每首3.15秒。布局占逐曲选宽99.1%，搜索遍历和外部调用并非主要瓶颈。此处没有实现前后对照，不能把两轮差值算作代码优化收益；也不把两种机器负载下的中位数当成稳定基线。首轮《美丽的神话》640px布局曾耗时25.389秒，复测同候选0.191秒，诊断轮0.213秒，说明首轮的极慢曲目不能直接用作热点排名。

复测最慢的五首为基本功练习12.400秒、Flower Dance 12.266秒、K545 11.031秒、《枫》9.154秒、《快速圆舞曲》（Valsentino）7.495秒。此前简谱基线的曲目数量、浏览器协议及实现快照不同，不用两个总耗时直接计算谱种速度比。

源码快照SHA-256：`0a78c22001e9dfbdca956ef6a9558b4a7e677d17fa701aedec7401aad01fbf0d`；全部候选语义摘要：`51a8d68dbf4c64f576f178785c7188674271faad7111afb92edba7eb59570361`。

独立诊断轮的逐曲选宽累计362.822秒；这是带埋点且负载不同的运行，不能与正常轮相减计算优化收益。全部1,391个候选的排版指标、页数、评分、最终选宽与正常运行一致。

| └ VexFlow绘制（包含DOM序列化／XML解析） | 90.534秒 | 25.0% | 123,371 |

| └ 规划用小节模型构建 | 56.314秒 | 15.5% | 246,752 |

表中父项包含子项，不能全部相加。刻绘还包含附件创建、连线与大谱表处理等未单列工作。规划和绘制的模型构建合计90.027秒，占24.8%，与避让和绘制是不同的调用范围。两个XML解析埋点合计16.658秒、1,012,388次，已经包含在绘制等阶段中；它们没有包含 `outerHTML` 序列化与SVG DOM创建，不能代表完整往返成本。

每候选平均2.25次间距试排，规划／刻绘各3,133次，系统绘制及避让各33,868次。规划需要行中、行首两种模型，绘制再构建一次，全库共370,123次小节模型构建。窄版分片会使这个比例略有变化。

文字度量请求2,841,932次，实际Canvas调用103,560次；后者包含VexFlow自己的调用，不能简单以二者相减当作文字缓存命中数。现有文字度量复用范围主要在单个候选，五线谱内部也有自身测量；这里只统计调用，没有增加跨任务缓存。

## CPU采样与优化顺序

在基本功、Flower Dance、《慢慢喜欢你》、《美丽的神话》、K545五首上单独以1ms间隔采样，共65个候选、44,845个样本、采样时间54.530秒。采样候选与正常基线逐项一致。以下为该子集的CPU样本占比，不是全库耗时百分比，也不与诊断分段直接相加。

| 函数或操作 | 自耗时占比 | 含子调用占比 |
| --- | ---: | ---: |
| `hasClass` | 8.06% | 8.83% |
| `SvgGeometry.pieces` | 6.44% | 22.27% |
| VexFlow `getGlyphProps` | 6.25% | 7.01% |
| 垃圾回收 | 4.57% | 4.57% |
| 原生 `setAttributeNS` | 3.53% | 3.53% |
| 墨迹 `transform` | 3.04% | 3.53% |
| `findAll` | 2.56% | 5.86% |
| VexFlow `createVexMeasure` | 1.10% | 25.59% |
| `filtered`（复制筛选后的SVG树） | 0.70% | 6.08% |

原生 `setAttribute` 和 `createElementNS` 的自耗时另为1.96%和1.83%。几何遍历反复解析class、transform和样式、复制树、建立数组；不仅是最终两两碰撞比较。模型构建内部还有符头、符干方向、连桁与字形查询，不能只看构建函数本身的1.10%。

建议按以下顺序实施，每步独立重跑全库正常计时并核对全部候选：

1. **减少避让几何的重复工作。** 同一谱行建立一次节点分类／索引，避免每次 `hasClass` 分割class字符串、每个附件重复 `findAll`，用带筛选条件的遍历替代 `filtered` 的整树复制。保留音乐主体的局部墨迹，在附件平移时只更新受影响部分；变换矩阵和样式计算也应共用。此方向对应全库38.0%的避让／几何整理阶段，CPU采样亦直接支持。缓存若用于节点数据，限定本次任务并正确处理节点移动、样式修改和新增边框，不能读取变换前的陈旧边界。
2. **任务内共用不可变的小节度量，减少模型重建。** `planStaffLines` 每次为行中／行首各构建完整VexFlow模型；这些小节最小度量在同一间距档、语义、谱表设置下通常不随候选宽度变化。先复用数值、字形／节奏列和文字度量，按间距、行首状态、声部及分片身份区分；窄版分片需独立计算。绘制对象会被格式化及移动，不可直接跨候选共用可变对象。该方向对应全库24.8%的规划及绘制模型构建；VexFlow字形查询的热点也能随重建减少而下降。
3. **减少SVG DOM、字符串和XML的往返。** 当前每个候选试排都完整绘制，VexFlow创建真实SVG DOM，读取 `outerHTML` 后重新解析内部树，再计算几何。可探索把绘图命令直接收集为内部节点及墨迹，并让最终SVG消费同一结构。单独XML解析已有约100万次、16.7秒，但更大的成本还在DOM创建、属性写入和对象分配。此项改动范围大，需对照SVG、字形、附件避让及PDF输出，不能用近似测量跳过真实避让。
4. **再评估跨候选的任务内文字度量复用和间距试排共用。** 字体准备完成后，按完整字体样式与文字共用度量，不复用跨任务结果。先减少上述模型／几何调用，重新采样后再判断文字是否仍是热点。不同间距档可以共用不变的事件与局部音乐几何，但必须保持当前试排次序、分页和评分。

存在较大的优化空间，主要来自重复处理的消除，而不是微调循环或关闭避让。阶段占比表示优化作用范围，不等于可实现的收益，不能承诺把38%或25%的阶段全部消除。字体准备、谱头、投影和分页合计占比较小，不作为下一轮首要工作。保留480～720、20px网格、综合质量评分和内部避让；独立越界／碰撞审计继续作为单独验收。基线阶段仅增加测量及分析工具；后续实现及收益见下节顺序优化记录。

## 验证

两轮生产报告同源、同渲染包，所有1,391个候选及最终选宽一致；全库诊断和五首CPU采样也通过逐候选一致性检查。三个新工具均通过 `node --check` 和定向oxlint，文档及代码通过 `git diff --check`。包构建通过；未改乐谱、字体或排版依赖，不需要重生成乐谱产物。

## 顺序优化记录

继续固定107首／1,391个候选、480～720px／20px档，正常轮不安装埋点。每轮独立执行全库搜索，使用 `--compare-implementations` 允许渲染包发生变化，同时严格核对谱源摘要、全部候选指标和最终选宽。

| 实现 | 全库选宽耗时 | 比前一轮减少 | 比原基线减少 |
| --- | ---: | ---: | ---: |
| 原基线 | 336.871秒 | — | — |
| 第一轮：几何遍历 | 289.528秒 | 14.05% | 14.05% |
| 第二轮：任务内不可变度量共用 | 253.024秒 | 12.61% | 24.89% |

第一轮将class分词改为不分配数组的完整token匹配，递归查询使用同一收集数组，矩形四角变换直接计算，变换矩阵按原字符串在单个 `SvgGeometry` 实例内复用；修改transform后会读取新字符串，不保留过期墨迹。附件排除由直接跳过子树代替复制整棵SVG树。未关闭任何避让步骤。

首次尝试的测量因同机多浏览器任务导致内存压力而中止：机器4GB内存、1GB交换空间接近耗尽，《虫儿飞》640px候选停顿125.617秒。该不完整报告保留为 `.tmp/staff-optimization/round-1-contended.json`，不纳入收益对照。上表为内存压力恢复后重新完成的全库正常测量；依然属于同机单次运行观测，不代表固定收益承诺。

逐轮数据位于 `.tmp/staff-optimization/round-N.json`，候选对照位于 `comparison-round-N.json`。最终SVG另用 `tools/compare-staff-rendering.mjs` 对照固定的原版包，逐首新浏览器、两个独立页面，在原版选中的宽度核对最终SVG逐字节一致；绘制对照时间不计入选宽耗时。

第一轮验证：渲染器227项测试通过，1,391个候选指标和最终选宽一致，107首最终SVG逐字节一致；定向lint、构建、乐谱产物校验通过。

第二轮由页面与本地测量共用 `prepareStaffMeasurementTask`，字体准备后只投影一次，任务内共用完整文字样式的度量；小节最小占宽按小节对象身份、间距档和行首状态保存。窄版分片独立处理，段名缩进仍按候选宽度计算；绘制模型不共用，投影设置不匹配时拒绝复用。没有跨任务缓存、整曲布局或选宽结果复用。

第二轮验证：渲染器230项测试、前端类型检查、定向lint及乐谱产物校验通过；1,391个候选与所有最终选宽与原版一致。
