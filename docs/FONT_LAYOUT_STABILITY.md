# 字号扰动下的布局稳定性试验

本轮仅验证《过火》，不改变全曲库的最佳宽度选择算法。

## 规则与复现

运行 `node tools/check-score-font-stability.mjs --score=guo_huo_01.m3n`，不需要开发服务器。

在640～800px范围以10px为步长，分别使用21、22、23px音乐基准字号试排。标题、署名、调号、拍号及显式字号按相同比例调整，歌词跟随音乐字号的原生比例；页面尺寸、谱内11px边距、谱行24px间隔和音符间距策略保持不变。试验修改投影后的字号参数，再调用原有编译和SVG输出；不通过缩放已完成的SVG模拟字号变化，也不修改原始谱面内容。该辅助工具用于本轮字号试验，尚未接入合页选择或全量谱集构建。

稳定要求三种字号的小节、音符在每行和每页的归属完全一致；允许坐标和字形尺寸变化。检查完整音符身份，避免把总行数一致误判成分行一致。沿用谱集的墨迹越界和歌词／数字重叠检查，三种字号均须通过。选择顺序为正式22px页数最少、宽度最小。每个候选的22px输出还须与正常网页渲染器的SVG逐字一致。

输出保存在 `.tmp/font-stability/guo_huo_01/`：`report.json` 包含全部候选的页数、谱行、小节／音符归属及几何检查，`index.html` 对比原650px与最窄稳定候选，`trial.pdf` 为该候选在22px下的A4单曲试排，纸张四边12mm。试验使用本机Chromium和系统serif字体，不等同于已完成Windows跨系统验收。

## 《过火》结果

2026-11-17，本机51组试排全部通过墨迹检查，所有22px候选与正常网页输出一致。

| 宽度 | 21px | 22px | 23px | 完整分行／分页一致 |
| --- | --- | --- | --- | --- |
| 640 | 1页10行 | 2页，9＋2行 | 2页，9＋2行 | 否 |
| 650 | 1页9行 | 1页10行 | 2页，9＋2行 | 否 |
| 660 | 1页9行 | 1页10行 | 2页，9＋2行 | 否 |
| 670 | 1页9行 | 1页10行 | 2页，10＋1行 | 否 |
| 680～690 | 1页9行 | 1页9行 | 1页10行 | 否 |
| **700** | **1页9行** | **1页9行** | **1页9行** | **是** |
| 710～760 | 1页9行 | 1页9行 | 1页9行 | 否，行内小节／音符分配不同 |
| 770～780 | 1页9行 | 1页9行 | 1页9行 | 是 |
| 790～800 | 1页8行 | 1页9行 | 1页9行 | 否 |

最窄稳定候选为700px。正式22px在A4的正文音乐字号约16.57pt，原650px约17.85pt。700px仅作为本次试验结果，不回写谱头；《过火》的 `preferred-width` 保持650。后续试验也不自动回写，须先讨论验证规则和结果。本轮未重新生成整本谱集，已有整本PDF与其布局报告仍对应650px结果。

稳定性并不随宽度单调变化；不能只找到第一个稳定候选后，便假定所有更宽候选都稳定。后续全量接入时，应对每个候选分别验证，并让同页合并的曲目在三种字号下保留共同宽度和相同组合。21／23px试验是约±4.5%的字号压力测试，不能覆盖系统字体字形比例或字距的所有差异。
