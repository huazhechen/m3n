# 当前简谱完整选宽性能（v40）

测量日期：2026-11-27；代码版本：`13059ada329fbc4091ed63c512fefef79d15b965`。全部117首简谱，使用当前谱源及归档的真实TTF设计轮廓。完整搜索与旧局部搜索各运行一次完整批次，仅切换`--local-refine`；字体、评分、逐元素几何、分页求解与源文件摘要逐一相同。完整模式117首选宽和页数全部符合当前回归基线；局部模式有3首选宽不同，页数相同。

环境为Linux WSL2、Intel Core i5-8400 @ 2.80GHz、Chromium 158.0.8127.88。两批串行，各使用一个新浏览器／页面，批内复用字体与文字度量，每首新建排版任务；不增加预热轮次、不启动profiler、不进行SVG像素审计。下表选宽耗时不包括浏览器启动、打包、字体准备和最终SVG绘制。

“完整搜索”覆盖528～768px的全部6px网格，但启用生产安全剪枝；不是强制每首都完整计算41档。P90/P95使用nearest-rank统计。单次批次中的小差值含JIT及GC波动，不能据此判断单首的小幅加速。

当前自动搜索范围已经按后续要求收窄为528～720px（33个6px候选），字体代价同步绑定新上限。以下检查点及原始表格均为收窄前的528～768px实测；新配置见[720px范围测量](WIDTH_SEARCH_720_PERFORMANCE.md)。

## 首轮优化检查点（2026-11-27）

修复简谱行几何适配器：局部渐强、渐弱和连音组的端点均在行内时，可按该行实际横向位置解析完整几何；只有跨行端点才保留外部依赖。解析非段尾行后显式保存全宽几何并增加版本，避免共享求解器反复使用过松下界进入前缀枚举。分页、评分、候选范围和精确曲线均未修改。

同一谱源、TTF与生产安全剪枝口径，全117首重测累计34.052秒，中位数161.6ms，最慢为基本功1817.4ms，仍有14首超过600ms。基本功单独新浏览器测量2064.5ms；这两个数字不是600ms达标结果。基本功分页代价调用从28006次降至27次，退回前缀枚举的问题已消除。原始记录为优化工作树`.tmp/opt-first-full.json`与`.tmp/opt-first.json`。

逐一比较117首的全部返回候选，候选覆盖、页数、行数与全部评分字段保持一致（浮点容差1e-8），所有赢家均相同。全量RSS峰值1446MiB。后续目标扩展至全部乐曲的两种谱式低于600ms；本检查点仅完成简谱首轮提速。

## 基本功瓶颈

《半音阶口琴基本功》占完整批次累计选宽的56.4%。两模式均约41秒，扩大6px搜索范围不是这项长延迟的主要来源。

未采样的完整批次中，分页代价求解累计28.36秒，分页约束DP相关计时22.46秒；这些是嵌套计时，不可相加。记录到28006次分页代价调用、21218次分页约束DP求解、1487432个生成状态。

另一次CPU采样和宽度跟踪将主要慢点定位在600px候选：该轮600px耗时47.90秒；720px赢家约97ms。该轮开启profiler和诊断输出，只用于定位，不参与前面的性能对比。主要热点为共享`page-cost-breaking.ts`中的分页代价求解、`horizontalSuffixPlans`及其后缀分组／凸包处理，同时存在较多垃圾回收。此结论不等于字体轮廓计算是主耗时。

后续优化应优先减少该分页约束求解中的重复后缀统计和分支工作，并保持精确几何、完整搜索和当前赢家；单纯恢复局部选宽对这个极端慢项帮助很小。
