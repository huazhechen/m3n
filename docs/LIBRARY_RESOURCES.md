# 乐谱库共享资源

进入 `/scores` 后并行下载全量谱源包和三字体 TTF 包；直接打开 `/scores/<slug>` 时也使用相同入口。乐谱列表不等待下载，阅读器在字体安装完毕后排版。下载失败可在打开曲目或重试导出时重新请求失败的包，成功的包保留。开发服务器使用同样的包；普通语料单元测试继续读取本地谱源。

谱源包为 gzip JSON，保存文件名到原始 `.m3n` 文本的映射。仅解析当前阅读的曲目，导出整册时才解析全部谱源。字体包为 gzip 二进制：前4字节为小端 JSON 索引字节数，随后为 UTF-8 索引和连续 TTF 字节；索引记录文件名、字符覆盖、字重、字形样式、偏移和长度。它包含思源黑体全库子集、Barlow Semi Condensed Medium、Bravura。中文覆盖曲库、独立作品、首页谱例以及封面、目录、页码和网站地址；沿用原始 TrueType 轮廓和度量，音乐字体保留偶数字节字形边界。

两个包由 Vite 构建时分别压缩，名称包含内容 SHA-256 摘要，地址和压缩字节数写入 `score-catalog.json`，不写进应用 JS。目录按 `no-cache` 重新验证，包沿用 `assets/v2/` 的一年 immutable HTTP 缓存及72小时旧资源保留。新增谱源或字体变化无需修改应用代码 hash。字体包索引也会占用少量空间，因此生产字体包大小与此前仅包含文件的 tar.gz 试验值不同。

包以原始 gzip 文件提供，**不设置 `Content-Encoding: gzip`**；浏览器通过 `DecompressionStream('gzip')` 解压，避免静态托管配置差异。页面内去重并缓存下载、谱源文本、TTF 字节和 FontFace 安装；PDF 和 PNG 复用同一份字节，不再请求单曲字体。刷新页面后重新解包、安装字体，但可复用浏览器 HTTP 缓存。浏览器清理缓存后会重新下载。首页文档谱例与独立作品继续使用原有按需字体策略。编辑器读取曲库、本地或分享谱源时也复用共享包，超出共享子集的文字仍可选择完整中文字体。

PDF 导出分为三个阶段，单根进度条在阶段切换时重置：下载乐谱与字体按两个包的已收字节计量，字体安装显示等待状态；排版按解析曲目、逐曲选宽候选及最终绘制工作量推进，章节合页搜索显示等待状态；PDF 按已生成页数推进，字体嵌入及最终打包显示等待状态，文件实际生成后才可下载。取消导出只取消该任务的等待和进度订阅，不中断阅读器共用的下载。

## 生成与归档

运行 `npm run prepare:library-fonts` 重建三份 TTF 和 `tools/fonts/library/manifest.json`。使用 `M3N_FONT_PYTHON`、已有的 `.tmp/font-subset-env/bin/python` 或系统 Python，需要 `tools/requirements-fonts.txt` 中锁定的工具版本。生成器从仓库已有的完整中文 TrueType 源、Barlow 内嵌源和 Bravura WOFF2 生成，不下载字体。清单记录谱源、装订配置、生成器和上游字体输入摘要，以及输出字符覆盖、长度和 SHA-256。

2026-11-25，同机串行两次无输出缓存重建三份 TTF，生成器内总耗时分别为1.302秒、1.286秒；中文子集分别为0.927秒、0.908秒，Barlow约0.003秒，Bravura约0.33秒。共有109份输入谱源，中文 TTF 442,656字节、Barlow 105,560字节、Bravura 174,516字节。计时包括输入摘要、字体生成、字符覆盖检查与清单写出，不含 Python 启动或生成上游完整中文 TrueType 源；后者已在仓库归档。这是单机观测值，不是构建耗时保证。

三份 TTF 和清单提交 Git，普通网页构建只验证输入／输出摘要并压缩打包，不要求部署环境安装 Python/fonttools。虽生成只需约1.3秒，但保留现有提交前生成惯例可避免增加部署依赖。`npm run prepare:scores` 和提交钩子会自动刷新共享字体；`npm run check:score-artifacts` 和生产构建拒绝过期结果。已有单曲子集继续用于离线工具及未进入曲库的页面，不进入曲库的下载流程。

## 验证记录

当前107首曲库的生产乐谱包54,000字节、字体包441,631字节，合计495,631字节。完整浏览器验证依次进入列表、阅读曲目、返回列表并刷新，再生成整册PDF；两个包的服务器请求均只有一次，刷新命中HTTP缓存，没有单曲TTF／WOFF2请求。PDF共94页、1,546,030字节，嵌入思源黑体、Barlow和Bravura，无栅格图片，三个进度阶段均出现。整册生成单轮约58.23秒，不作为性能保证。

先构建到 `.tmp/playwright-dist-4173`，再运行 `M3N_MEMORY_LIMIT_MB=1700 python3 tools/run-low-memory.py node tools/verify-library-resources.mjs` 可复现这项审计。该工具只启动临时静态测试服务器；使用单进程Chromium控制聚合RSS，并在读取PDF前关闭浏览器。本轮聚合RSS峰值1,220 MiB。PDF和报告位于忽略的 `.tmp/library-resources-audit/`。常规端到端测试另覆盖共享资源复用、取消导出、单曲PDF与字体；单元测试覆盖并行下载、字节进度、共享取消、失败重试与截断包拒绝。
