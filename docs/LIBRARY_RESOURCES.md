# 乐谱库共享资源

进入 `/scores` 后并行下载全量谱源包和三字体 TTF 包；直接打开 `/scores/<slug>` 时也使用相同入口。乐谱列表不等待下载，右上角导出谱集按钮在下载和字体安装期间显示旋转加载图标并禁用，全部完成后恢复打印图标。加载失败时按钮允许重试，仅重新请求失败的包，成功的包保留；打开曲目也可重试。阅读器在字体安装完毕后排版。开发服务器使用同样的包；普通语料单元测试继续读取本地谱源。

谱源包为 gzip JSON，保存文件名到原始 `.m3n` 文本的映射。仅解析当前阅读的曲目，导出整册时才解析全部谱源。字体包为 gzip 二进制：前4字节为小端 JSON 索引字节数，随后为 UTF-8 索引和连续 TTF 字节；索引记录文件名、字符覆盖、字重、字形样式、偏移和长度。它包含思源黑体全库子集、Barlow Semi Condensed Medium、Bravura。中文覆盖曲库、独立作品、首页谱例以及封面、目录、页码和网站地址；沿用原始 TrueType 轮廓和度量，音乐字体保留偶数字节字形边界。

两个包由 Vite 构建时分别压缩，名称包含内容 SHA-256 摘要，地址和压缩字节数写入 `score-catalog.json`，不写进应用 JS。目录按 `no-cache` 重新验证，包沿用 `assets/` 的一年 immutable HTTP 缓存及72小时旧资源保留。新增谱源或字体变化无需修改应用代码 hash。

包以原始 gzip 文件提供，**不设置 `Content-Encoding: gzip`**；浏览器通过 `DecompressionStream('gzip')` 解压，避免静态托管配置差异。页面内去重并缓存下载、谱源文本、TTF 字节和 FontFace 安装；PDF 和 PNG 复用同一份字节，不再请求单曲字体。刷新页面后重新解包、安装字体，但可复用浏览器 HTTP 缓存。浏览器清理缓存后会重新下载。首页文档谱例与独立作品继续使用原有按需字体策略。编辑器读取内置曲目时只下载谱源包，不等待或下载共享字体包；本地及分享谱源也不触发曲库资源下载。编辑预览的简谱与五线谱中文统一采用系统字体（包括在阅读页已安装中文字体后进入编辑器的情况），仅按需安装 Barlow 西文字体和 Bravura 音乐字体，不因输入新中文字下载完整中文字体。阅读及 PNG／PDF 导出继续使用思源黑体。独立作品在编辑入口跳过中文字体预加载。

PDF 导出分为三个阶段，单根进度条在阶段切换时重置：下载乐谱与字体按两个包的已收字节计量，字体安装显示等待状态；排版按解析曲目、逐曲选宽候选及最终绘制工作量推进，章节合页搜索显示等待状态；PDF 按已生成页数推进，字体嵌入及最终打包显示等待状态，文件实际生成后才可下载。取消导出只取消该任务的等待和进度订阅，不中断阅读器共用的下载。

标题栏按钮恢复打印图标表示共享谱源和字体已就绪，尚未生成整册PDF。此时打开弹窗直接显示加载排版模块，复用资源时跳过下载阶段；随后仍需解析全册、搜索版宽、合页与生成PDF。PDF模块在后台预加载，不阻塞排版启动；只有实际下载或安装共享资源时才显示第一阶段。

## 生成与归档

运行 `npm run prepare:library-fonts` 重建三份 TTF 和 `tools/fonts/library/manifest.json`。使用 `M3N_FONT_PYTHON`、已有的 `.tmp/font-subset-env/bin/python` 或系统 Python，需要 `tools/requirements-fonts.txt` 中锁定的工具版本。生成器从仓库已有的完整中文 TrueType 源、Barlow 内嵌源和 Bravura WOFF2 生成，不下载字体。清单记录谱源、装订配置、生成器和上游字体输入摘要，以及输出字符覆盖、长度和 SHA-256。


三份 TTF 和清单提交 Git，普通网页构建只验证输入／输出摘要并压缩打包，不要求部署环境安装 Python/fonttools。`npm run prepare:scores` 和提交钩子会自动刷新共享字体；`npm run check:score-artifacts` 和生产构建拒绝过期结果。已有单曲子集继续用于离线工具及未进入曲库的页面，不进入曲库的下载流程。

## 导出与验证



整册 PDF 的封面和目录不添加导出页脚；正文保留网站页脚。封面显示版本号，下载文件名为 `<谱集标题>-<short hash>.pdf`，版本号取应用构建时最后一次 Git 提交的 `git rev-parse --short HEAD`。本地谱集工具在生成排版时读取同样的版本号并记录到布局报告，后续 PDF 打包沿用该版本及文件名。

## 统一加载反馈

谱源、字体、简谱及五线谱模块、首次音色下载和谱集导出模块通过 `ResourceLoadingDialog` 注册加载任务，应用级 `ResourceLoadingHost` 统一显示一个模态框。等待超过350ms才显示，缓存及快速加载不闪框；已显示的框延续到准备／排版完成，谱源到渲染的交接保留150ms。点击“后台加载”或 Escape 后，本轮连续任务不重新弹出。曲库列表预取保留顶部按钮状态，路由与文档加载保留页面提示，乐谱渲染（包括正在排版及动态切换简谱／五线谱）立即显示同一个对话框，排版前留出绘制机会，完成后关闭；播放初始化仍保留按钮忙碌状态。

打印预览、PNG、单曲PDF和整册PDF在原有弹窗内复用 `ResourceLoadingProgress` 的状态文字和进度条，保留任务自身的取消、失败与重试，不叠加资源对话框。共享资源只取消调用方等待，不中断其他页面共用的下载。

简谱阅读器同时解析共享TTF的设计轮廓与字距，用于确定性排版；浏览器像素墨迹只参与独立绘制验收。小节号显隐始终使用相同布局边界。实现与跨引擎验证见[字体设计度量](FONT_DESIGN_LAYOUT.md)。
