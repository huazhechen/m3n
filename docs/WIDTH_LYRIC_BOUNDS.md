# 歌词下界和精确基线查询

独立分支 `perf/lossless-width-v2`，基于 `5e6887f2`。保持单线程、528～720px完整6px网格、三档断行、原有评分和最终曲线／字形；新候选调度仍由基准 `--prepared-search` 启用，尚未接入阅读器。全曲库双谱式600ms目标未完成。

## 为什么歌词可以提供安全下界

原单向界限只包含音乐子集及部分附件，忽略了歌词。单谱表的精确流程在整理其他附件前，先从谱线底边和与歌词横向重叠的音乐底边求基线，然后按歌词行号排序，将每行放在上一行底边加歌词间距的位置。

柔性符梁试算不改变横向占宽、歌词文本、字号或行号。因此用方向不变的音乐子集执行相同的基线规则，所得基线不会低于实际基线。每行歌词的初始整体高度固定；按原规则依次累加该高度与歌词间距，得到每行安全的下沿。

证明中仅把这些下沿加入 `bottomInk`，不把其上沿用于上一行的避让；真实音乐仍可让歌词整体向下。标量高度沿用原64倍机器精度余量，横向与通道坐标仍放松1e-7px。空白和占位歌词沿用精确流程的可见内容判断；不连续行号按实际存在的行排序，初始纵坐标不保留。双谱表继续使用原界限，不套用此单谱表证明。

## 哪些符梁试算可以省略

没有歌词偏好时仍需证明不能改善超过原1e-7px阈值。歌词旁的近似等高结果偏好向上符干，所以仍完整试算向上候选。向下候选只有高度改善严格超过近等高窗口、同时超过严格改善阈值时才可能被选中；若安全下界证明它不能达到这个改善幅度，即省略该次试算。

只复用已经为预检查建立的行界限。普通完整行仍运行原始的逐组试算，不额外计算界限，也可作为回归对照。

## 基线查询共用同一实现

`inkBottomAlongX` 同时服务精确歌词布局与上述下界。少于8个歌词边界时直接扫描；更多时复用 `InkRangeIndex` 的排序和右边界前缀最大值，以无结果数组的存在性查询判断重叠。图元底边数值已经小于当前最大值时，不再查询它。

严格条件仍是 `music.right + gap > lyric.left` 且 `lyric.right + gap > music.left`，包括点状墨迹、接触边缘和横向净空。最终只按原 `Math.max` 规则累计底边，不引入间距或几何近似。

## 证据

- 已完成的连音组标记跳过完整整理的试验，全库55478.9→55465.2ms，没有证明收益，已撤回；报告 `v113-all-staff.json`。
- 仅加入歌词下界及向下试算证明的v114，全库五线谱55478.9→53117.4ms，117首赢家／页数／行数及共同完成候选评分保持一致，仍未达到600ms目标。
- 回归检查五组柔性符梁的全部32种方向组合、多行歌词、空白占位、不连续行号、不同初始纵坐标；逐个检查下沿约束在精确墨迹中有对应图元。与无预检查的原算法对比完整SVG及数值几何，并确认确实省略了试算。
- 基线查询与穷举图元对逐项对比，覆盖索引阈值、严格边缘、零宽墨迹、不同净空、输入逆序和追加图元。

v115合并后五线谱全库累计52762.6ms，比v112减少4.9%；117首赢家／页数／行数及249个共同候选评分在1e-8内一致，仍37首超过600ms。《风》1734.1→865.5ms，《星星点灯》1907.6→1287.7ms；基本功1567.7→1632.7ms，未证明本项能加速无歌词曲目。与v114单项的差异很小，不能单独声称索引查询带来稳定的全库提速。

简谱117首累计36322.2ms、10首超过600ms；117首赢家／页数／行数及341个共同候选评分保持一致，本项未修改简谱算法，不把计时差异解释为简谱提速。

273个文件2291项全套离线测试、工具／字体检查、23项浏览器回归、密度回归、类型、lint和架构边界检查通过，聚合RSS峰值1116MiB。随后把空歌词容器判定与精确布局统一：即使缓存文字非空，无子节点的容器也不建立歌词行；重新生成产物、25项针对性回归、类型、lint和边界检查通过，峰值607MiB。该补充仅收紧证明适用条件，不改变最终排版。
