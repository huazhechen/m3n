# 全量谱集导出性能与内存

本轮在独立 worktree 中，以当前112首曲库验证真实浏览器的在线全量导出。计时从点击“导出全量谱集”开始，包含选模式、解析、全部候选选宽、合页、最终SVG、字体嵌入、PDF打包及实际下载。曲库共享资源已加载并可命中浏览器HTTP缓存；不包含首次网络下载耗时。每轮新建浏览器，不复用上轮候选或排版结果。

环境：Intel Core i5-8400 2.80GHz、Chromium 158.0.8127.88、Node v26.13.1。以下为本机单次观测，不是任意设备或网络的耗时保证。

| 模式 | 曲目／PDF页数 | 上轮实际下载 | 当前PDF可下载 | 当前实际下载完成 | 当前进程合计RSS峰值 |
| --- | --- | ---: | ---: | ---: | ---: |
| 简谱 | 112／98 | 52.57秒 | 28.39秒 | 28.44秒 | 1037 MiB |
| 五线谱 | 112／109 | 58.52秒 | 33.73秒 | 33.81秒 | 1440 MiB |

简谱达到30秒目标，五线谱尚未达到。各阶段按真实导出状态切换计时（单位：秒，单次观测、四舍五入）：

| 阶段 | 简谱 | 五线谱 |
| --- | ---: | ---: |
| 启动、模块及解析准备 | 1.65 | 1.91 |
| 选宽与排版测量 | 12.14 | 15.09 |
| 章节与合页 | 2.98 | 2.04 |
| 最终SVG绘制 | 2.75 | 5.69 |
| PDF字体准备 | 0.18 | 0.17 |
| PDF页面转换 | 7.77 | 7.88 |
| PDF打包 | 0.94 | 0.94 |
| 下载收尾 | 0.06 | 0.08 |

不能用单独排版计时代替完整导出计时。五线谱的分页下界剪枝在不含PDF的整库比较中将测量阶段14.27→13.31秒，但完整导出34.01→33.81秒，端到端收益较小，不能宣称达到30秒。

简谱也做了只读下界试验：在真实共享字体下逐曲投影，取最小音乐墨迹高度，再以最大每页容量检查原有候选。112首没有新增可排除的候选，因而未启用该路径。这里使用最终候选行数，已经比所有间距试排的最小行数更容易排除候选，仍为0。不能改用30px小节线高度替代现有核心高度：简谱核心按音符及延音墨迹计算，合法核心可以低于30px；直接抬高它可能改变原分页与选宽。

五线谱优化前同机实际下载122.23秒、进程合计RSS峰值1388 MiB。原简谱实现保留所有候选的完整布局，在384 MiB浏览器堆限制下无法完成；放宽堆限制的诊断运行在进程合计1703 MiB时被监控终止。修复候选持有后可在384 MiB堆限制下完成，不需要继续放宽堆。

新旧PDF的98页简谱、109页五线谱逐页解码绘图指令并比较，全部相同，三份嵌入字体也逐字节相同；忽略PDF时间戳。112首简谱的1715个离线候选结果逐项一致，包括页数、谱行数、连续高度、评分及最终选宽；无跨任务复用的逐曲测量墙钟合计从71.28秒降为27.37秒，减少61.60%，不包含最终PDF生成。本轮搜索保留原档位和排名规则，使用有证明上界的剪枝。移动调简谱、固定调简谱、五线谱的112首独立选宽、合页分组及全部最终SVG摘要均与完整搜索一致，实际测量次数分别为1982→1244、1976→1288、1946→1300，详见[选宽策略](WIDTH_SEARCH.md)。

## 内存来源与处理

- 候选宽度保留评分、尺寸和重建所需输入，避免数千个候选的全部谱行常驻。五线谱额外保留每首当前最优的一份完整排版，单曲选宽完成后固定，最终取用即释放；合页需要其他宽度时重建。
- 不设整册最优排版的固定行数预算。112首五线谱中命中88首，24首因合页改变宽度而未命中；峰值保留991行，结束保留0行。对照768行软预算，命中67→88，最终重复排版约425→96毫秒，整库进程合计RSS峰值约1390→1434 MiB。这组对照只隔离缓存容量，不代表当前所有优化的端到端差异。
- 横向评分已经无法胜出的音符间距试排，不再构建连线、歌词及纵向碰撞几何。基线及每个可能替换当前结果的试排仍完成原有排版与校验。
- 简谱同一横向布局复用归一化墨迹及谱行间约束；五线谱合页的不同行距复用已生成谱行，只重算纵向摆放。五线谱SVG缓存按分页模式各保留最后一个行距，避免缓存随拟合次数增长。
- 五线谱普通文字先批量读取字符位置，再统一替换节点；已知音乐字形直接生成与拆字后等价的节点。SVG逐页摘要与原结果一致。PDF坐标仍由浏览器提供，重复字形、样式和路径复用相同绘图指令。
- 全量导出没有页面预览消费者，通过 `consumePages` 转交原SVG，省去整页DOM复制；PDF转换完成一页后即清空其子节点。字体收集已在转换前完成，页面绘图指令及链接也已复制。其他PDF调用默认复制页面。

RSS包含浏览器本身、DOM、字体、PDF数据及校验进程，不能与JavaScript堆等同。阶段采样也不是精确堆峰值。导出后额外强制GC诊断，简谱／五线谱的JavaScript堆均约20 MiB；GC诊断不计入导出耗时。浏览器可保留已申请的内存页供后续复用，因此不能只凭RSS未立即下降判断泄漏。

## 复现

先按[托管说明](HOSTING.md)使用隔离目录构建，避免覆盖正在服务的 `dist/`。重任务串行运行，单测试worker、Node堆384 MiB、浏览器堆384 MiB。当前工作区遵守更严格的2 GB进程合计限制，以1700 MiB监控阈值预留停止余量；其他工作区也在测试时，应等待其完整驱动进程结束。

```sh
M3N_MEMORY_LIMIT_MB=1700 python3 tools/run-low-memory.py \
  npm run build -- --outDir .tmp/export-final-dist

M3N_EXPORT_MEMORY_AUDIT=1 M3N_EXPORT_MAX_MS=30000 \
M3N_EXPORT_AUDIT_OUTPUT=.tmp/export-audit-movable \
M3N_MEMORY_LIMIT_MB=1700 python3 tools/run-low-memory.py \
  node tools/verify-library-resources.mjs .tmp/export-final-dist movable
```

五线谱将最后一个参数改为 `staff`，并设置独立输出目录；当前版本尚不能通过30秒阈值，可临时设置60000只验证输出。工具保存PDF及包含阶段时间、环境、堆采样的 `report.json`，验证112首逐曲链接、A4页面、三字体嵌入、无栅格图片，再检查实际下载耗时阈值。RSS峰值由外层监控输出，应同时保存日志。CPU采样使用 `M3N_EXPORT_CPU_PROFILE=1`，会影响耗时，另行运行。

使用 `node tools/compare-scorebook-pdfs.mjs before.pdf after.pdf [report.json]` 比较解码后的每页绘图指令和嵌入字体；链接、纸张及图片对象由上述全量导出工具独立校验。候选测量使用 `tools/build-scorebook.mjs --probe-only --force-measure --timing-report=...`，再由 `tools/compare-scorebook-measurements.mjs` 比较前后探测与计时报告。
