# 无损选宽与主线伸展规则整合

本轮将 `perf/lossless-width-v2` 的精确搜索及几何复用与主线 `bc63cd94` 合并。阅读器两种谱式均使用 `exactScoreWidthPolicy`：完整528～720px的6px网格，只允许具有安全下界证明的剪枝。此前有损策略的代理不再作为阅读器默认策略。候选预准备调度仍仅由基准 `--prepared-search` 启用，不将其耗时当作阅读器实测。

主线的抵扣式弹簧伸展是分段线性的。原简谱核心下界用两个宽度端点约束加权核心，要求整个区间内横坐标为仿射函数；有抵扣量的弹簧不满足这一前提。现在检查实际约束链，只在所有可伸展弹簧均无抵扣量时使用端点增强，否则采用原宽度无关的浅层音乐／歌词安全界。等宽小节按每个实际子链及左右填充规则检查。最终排版、评分和精确曲线不变，允许剪枝变弱，不能为了性能沿用不成立的证明。

整合验证还发现主线英文歌词的渲染／布局度量不一致：默认SVG文本可使用像素取整后的字符推进，设计度量保留小数。大谱表夹具的 `summer/autumn` 与 `winter/mountain` 因此被实际墨迹门禁判为相交。两种谱式的设计字体SVG现在声明 `text-rendering="geometricPrecision"`，浏览器审核的Canvas使用对应计算样式。仍由设计字体决定布局，不引入设备度量反馈，不增加歌词间距或放宽碰撞阈值。该渲染提示减少像素取整差异，不保证不同系统的抗锯齿像素完全相同。

主线谱源测试同步：黑色幽默仅更新已批准删去四个尾休止后的合同数据，保留音符及歌词检查。土耳其进行曲的8va写法改变了倚音后缀表示，但与改写前谱源编译得到的实际音符、速度、拍号和总拍数逐项相等；演奏基线采用改写前独立捕获的编译输出摘要，避免将源表示变化误判为演奏变化。

验证：275文件2315项离线用例、97项工具、5项字体检查、23项浏览器回归、密度门禁、类型、lint、包边界及生成物检查通过。端到端共24项通过；其中无障碍读谱的小节计数由59更新为删除尾休止后的58，单独补跑通过。整体验证脚本的non-e2e阶段耗时125.95s，超过其120s预算，故聚合命令仍报告失败；没有降低预算或略过断言。整合批次RSS峰值1206MiB，E2E峰值1555MiB，均低于2GB。

两种谱式穷举各117首、每首33个宽度，共7722个候选，无生成错误。预准备剪枝与穷举的117首赢家／页数／行数均相同，简谱341、五线谱250个共同完成候选全部评分在1e-8内一致；这一批RSS峰值873MiB。阅读器精确剪枝路径同样全部一致，简谱280、五线谱291个共同完成候选评分通过相同容差；RSS峰值816MiB。简谱累计41011.4ms，20首超过600ms，基本功1255.8ms；五线谱累计41928.8ms，22首超过600ms，基本功1505.7ms。当前选宽统计见[全库对比](CURRENT_NOTATION_PAGE_COMPARISON.md)。

600ms目标仍未达到。
