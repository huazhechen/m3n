# M3N 前端架构

## 目标

本项目的核心资产不是页面，而是 M3N 语法、转换正确性和乐谱交互。架构以纯领域逻辑为中心，React 页面只负责组合功能和管理界面状态。

依赖方向必须保持单向：

```text
web app -> @m3n/score-renderer -> @m3n/notation
       \-> @m3n/numbered-notation（自研排版）
       |                       \-> @m3n/notation
       \-> @m3n/notation
       \-> React / routing / application services
```

`@m3n/notation` 不得依赖 React、DOM、具体页面或 `@m3n/score-renderer`。转换函数应保持确定性：相同输入总是产生相同输出与诊断。
同一编辑操作的派生计算应复用已解析的领域文档，避免各模块重新扫描相同源码。

领域层明确使用两个模型：

- `M3NSyntaxTree` 是无损且可容错的语法模型，保留原始行、token 与绝对源码范围，服务格式化、诊断和编辑器定位。
- `ScoreDocument` 是规范化音乐语义模型，不承载排版空白等文本细节，服务校验、简谱排版与演奏编译。

交互调用方通过 `analyzeM3N` 建立一次分析会话并消费其派生结果，不应在同一次编辑更新中自行重复解析。

格式化器将乐谱中指令值以外的连续空白规范为一个空格，删除音乐行开头或连续小节线产生的空音乐小节，并依据旋律对位目标重建歌词小节线；没有歌词目标的小节仍保留为空歌词小节，例如 `甲乙 | | 丙丁`。格式化保留逐个音符、延音、休止符与手动换行，按等价括号分组、布局和歌词对齐分阶段执行，模块职责与规则见[格式化器](FORMATTING.md)。此为编辑器格式化行为，原始输入的语法与校验规则见[手册](MANUAL.md)。

分析会话直接提供 `score`、`diagnostics`、`invalidMeasureIds` 和 `interaction`。交互数据包含源码映射与歌词分配，元数据从领域文档提取。初始设置从语法树首音之前的状态指令建立，信息字段仅来自文档首部，注释不参与解析。

结构投影、领域 builder 与源码规则复用语法树中的原始 token，保留绝对位置和 CRLF 偏移，不拼接正文后重新分词。`analyzeM3N` 返回完整且可结构化克隆的数据，Worker结果直接交给页面。可编辑页面通过 `useM3NAnalysis` 在模块 Worker 中分析后续输入，一次只运行一个请求并保留最新待处理编辑；过时响应不能替换当前结果。中文组合输入期间保留原预览并暂停分析，等待更新时禁用播放，线程错误有重试入口；只读文档谱例使用同步分析，不为每个示例创建线程。

## Workspace 边界

- `packages/notation`（`@m3n/notation`）：无平台依赖的语法、领域模型、诊断、格式化、分析及演奏编译；可独立生成 JavaScript 与类型声明。
- `packages/score-renderer`（`@m3n/score-renderer`）：浏览器渲染、播放、导出与资源调度；只通过 `@m3n/notation` 的公共入口访问领域类型。
- `packages/numbered-notation`：从领域文档完成自研测量、排版、分页、歌词遍次与交互SVG绘制。
- `src`：React Web 应用、路由、曲库装载及分享服务；通过包名消费子包，不跨入其内部目录。
- `worker`：部署边缘入口，不依赖 Web UI。

包依赖为 `score-renderer -> notation`、`numbered-notation -> notation / txml`。根应用可以组合这些包，但子包不得反向导入根应用。每个包在自身 `package.json` 中声明运行依赖，并提供独立的 `build`、`test`、`typecheck` 命令；根脚本显式按依赖顺序执行。

## 内部职责

- `packages/notation/src/notation/syntax-tree.ts`：无损容错语法树、行节点与源码范围。
- `packages/notation/src/notation/syntax-rules.ts`：直接消费 directive AST 节点的区间闭合与指令值规则。
- `packages/notation/src/notation/score-document.ts`：规范化乐谱、声部、小节、事件、歌词和演奏区间契约。
- `packages/notation/src/notation/analysis.ts`：交互调用方的统一分析入口。
- `packages/notation/src/notation/diagnostics.ts`：结构化诊断契约；规则在产生诊断的位置直接提供稳定 code、严重级别和源码范围，不保留字符串诊断模式。
- `packages/notation/src/notation/m3n-primitives.ts`：调号、音符和时值等最小语法内核。
- `packages/notation/src/notation/repeats.ts`：反复次数、跳房子及 D.S./D.C. 的纯播放计划；演奏编译和歌词对位共享其语义。
- `packages/notation/src/notation/score-rules.ts`：只消费 `ScoreDocument` 的音乐语义规则；负责小节时值、延音目标和双谱表对齐。
- `packages/notation/src/m3n-direct.ts`：从源码构造 `ScoreDocument`；领域消费者统一使用 `Score*` 类型，不再暴露旧 `Direct*` 类型。
- `packages/notation/src/m3n-lyric-alignment.ts`：以已解析文档为输入的书写小节歌词目标和强制延音目标语义，供格式化与校验共享。
- `packages/notation/src/m3n-validate.ts`：语义校验，只依赖最小语法内核。
- `packages/score-renderer/src`：自研 MIDI 写入、时间索引、音频播放和导出文档。
- `packages/numbered-notation/src`：`ScoreDocument` 的自研投影、横纵布局、实绘测量、分页与SVG交互；公共入口导出`native-score.ts`。旧引擎、适配器及跨引擎对照工具已删除。
- `packages/notation/src/notation/section-order.ts`：校验显式乐段顺序；ScoreDocument 保存分段范围与局部访问次数，演奏展开、歌词映射和简谱排版共用该模型。
- `packages/score-renderer/src/native-playback-score.ts`：仅提供 MIDI 生成和时间映射，按播放操作动态加载。
- `packages/score-renderer/src/spessa-player.ts`：SpessaSynth 播放，默认使用原有柔和FM合成音色；五种乐器按需加载FluidR3 q3采样SF3。
- `packages/score-renderer/src/playback-tones.ts`：轻量音色目录、下载去重、取消、字节进度、浏览器 Cache Storage 持久缓存与失败重试；不初始化合成器。
- `packages/score-renderer/src/playback-coordinator.ts`：显式管理多个乐谱实例间的播放互斥。
- `lib/render-score.ts`：屏幕、打印预览和最终导出的统一排版入口，负责引擎选择、串行调度、取消、分页和 SVG 后处理。
- `components/ScoreRenderer.tsx`：独立管理布局、播放和光标生命周期；改变版宽或谱式不销毁播放器，更新音乐文档时释放旧播放资源。播放高亮只同步音符和源码选区，不滚动页面或源码编辑器；点击音符、诊断等显式定位操作仍可滚动。简谱小节高亮按当前谱行内的小节边界覆盖：同一谱行中，后一小节的交互范围从前一小节结束线开始，包含结束线到首音之间的伸缩留白；若边界是归属后一小节的共用前反复线，则保留该线的左边界，不回扩至前一小节末音；换行及分页后重新计算本行边界，不移动音乐图元。
- `components/ScoreControls.tsx`：阅读页、编辑页与转换页使用固定在窗口底部的悬浮播放条，从左到右为播放／暂停、进度滑条和节拍器开关；旁边的设置悬浮按钮打开原生非模态 popover。设置弹层含速度、宽度两条滑条及音色、分页、记谱方式、小节号、调号五个按钮；两条滑条的还原按钮只显示图标，保留可访问名称和悬停提示。弹层内外使用同一个界面缩放基准，按钮基础高度统一采用 `clamp(var(--ui-control-min), 100vmin / 16, var(--ui-control-max))`，图标为该高度的80%。弹层明确使用自动高度、零最小高度及内容尺寸网格行，内容向顶部对齐，防止 Safari 默认弹层高度和网格拉伸把按钮撑满窗口；空间不足时弹层内部滚动。五个功能按钮采用紧凑的上下图文布局，沿用统一的图标与字号比例；文字行高为1，图文间距为常规间距的1/4，上下内边距为常规间距的1/2，高度按内容计算且不低于基础按钮高度，不再额外叠加文字最小高度；调号以当前调性为图标，附“调号”文字。点击空白或 Escape 关闭设置，五度圈作为设置内的模态对话框，关闭后回到调号按钮。弹层不占文档流，开关不改变谱面尺寸或播放实例；悬浮条通过 portal 放到 body，避免渲染容器截断或改变固定定位，页面底部按播放条尺寸动态预留空间及设备安全区。文档谱例沿用同款播放条（播放／进度／节拍器），不显示设置按钮，在各自乐谱渲染区域顶部吸附，滚出该谱例后随之离开。界面只使用按钮基础高度这一缩放基准：`clamp(var(--ui-control-min), 100vmin / 16, var(--ui-control-max))`（视口窄边的1/16，默认范围36～48px；可悬停且主要输入为精细指针时范围24～36px），纯图标按钮采用同样的宽度；顶部导航、品牌标志、编辑操作、播放和设置图标统一采用按钮基础高度的80%，默认28.8～38.4px、鼠标设备19.2～28.8px。纯图标按钮不加内边距，图文按钮按图标及文字实际尺寸预留空间。顶部栏高为按钮基础高度的1.25倍；间距为按钮高度的1/8，界面基础字号为按钮高度的3/8（默认13.5～18px、鼠标设备9～13.5px），页面和控件文字按同一字号使用相对比例，主内容区最大宽度也随字号增长，关闭 Safari 的额外文字自动放大。滑条交互区与按钮等高、轨道高为按钮高度的1/16；设置功能按钮通过收紧行高、图文间距和留白容纳文字，播放条和设置面板的宽度随大尺寸按钮扩展，底部留白和设置弹层位置随控件尺寸变化。渲染器与原控制区均无卡片边框及内边距。顶部操作直接在栏内展开，不使用折叠菜单。乐谱阅读页从左到右为上一曲、下一曲、打印、编辑、乐谱库；桌面端使用图标与文字，移动端（≤720px，或主要输入为粗指针且不支持悬停）只显示按统一尺寸基准派生的等宽图标按钮，保留可访问名称与悬停提示。首页、指南和手册顶部只显示乐谱库；页面顶部留白统一为按钮高度的1/8，桌面不再使用固定18px留白，导航栏按统一尺寸基准派生。三个数值只读，均通过滑条调整；BPM支持10–240整数。默认保留原有合成音色且无需下载采样；钢琴、口琴、吉他、小提琴、长笛首次播放时按需下载FluidR3 q3独立SF3并缓存。音色按钮显示当前选择的图标及名称，打开六选一模态对话框；完成选择后关闭并返回按钮。未知旧设置回退到合成音色，旧钢琴与口琴设置直接使用对应新音色。音色通过 `hooks/usePlaybackTone.ts` 同步阅读页、编辑页、文档谱例与同源标签页，长期保存在localStorage；记谱方式（三选一：首调简谱、固定调简谱、五线谱）、小节号与节拍器也保存到本地。非文档谱例默认开启节拍器与分页，已保存的手动选择优先。移调、速度和宽度只在当前乐曲页面内调整，切换乐曲或重新打开时恢复原调、该曲原速及谱集默认版宽，不读取旧的全局移调／速度／宽度缓存。小节号默认关闭，开启后按书写顺序在每行主旋律末尾小节线上方显示，不改变MIDI或播放顺序。文档谱例提供播放／暂停、进度滑条与节拍器，节拍器默认关闭且仅在该谱例临时切换；固定使用合成音色和谱面原速，关闭移调、小节号及分页，不读取这些个人偏好；文档谱例的目标音符字号采用同一按钮基础高度的1/2（默认18～24px、鼠标设备12～18px），由界面根字号反算，避免另设视口缩放公式或独立上限；再根据文档可用宽度与引擎原始22px字号反算排版宽度（引擎最小版宽320px）；所有谱例先按该宽度重新排版，再缩放至容器全宽；窄屏不提供横向滚动，播放栏按同一界面尺寸基准独立布局，不缩放整个DOM；正文尺寸不参与谱面缩放。
- `components/ScoreExportDialog.tsx`：预览与PNG下载状态；PDF与全量谱集共用 `PdfDownloadPanel`，立即显示加载／分页／字体／逐页生成／打包进度，支持取消及失败重试；复用阅读页当前版宽、速度、移调、固定调、小节号与分页，只提供横排PNG与PDF两个按钮，不再单独设置宽度或低音谱表。
- `packages/score-renderer/src/score-pdf.ts`：单曲与全量谱集共用的矢量PDF生成器，将原生SVG图形及逐字坐标直接写入PDF，嵌入Barlow音乐数字字体子集；普通文字先检查预置字体覆盖，全覆盖时嵌入子集，缺字时由 `pdf-system-font.ts` 提供整份PDF未嵌入的文字字体声明与字符映射。
- `components/NotationEditor.tsx`：顶部仅保留格式化、保存、分享三个操作，桌面显示图标与文字，移动端显示按统一尺寸基准派生的等宽图标按钮并保留可访问名称；不显示浏览器保存提示、文件导入／下载入口，草稿恢复与自动保存继续生效。
- `components/SourceEditor.tsx`：CodeMirror 编辑适配，提供高亮、行号、括号匹配、指令补全、历史与范围诊断；领域层不依赖编辑器。
- `components/EditorSplit.tsx`：手机源码／预览标签切换，桌面拖动及方向键调整分栏，切换保留输入与分析。
- `pages`：路由级组合，不承载领域算法。
- `scores/*.m3n`：曲库正文的唯一来源；`tools/score-catalog-plugin.ts` 在构建时生成排序后的虚拟索引，`lib/samples.ts` 消费目录并按曲目异步加载正文；生产目录独立发布为 `score-catalog.json`，启动时重新验证，正文以内容摘要命名的静态文件发布，目录及正文不编译进应用JS（开发及语料测试仍使用虚拟索引），浏览器不逐首解析内置曲库。乐谱库默认按音乐类型展示，继续记住用户手动选择的排序方式；字母模式下先显示本地作品，按最近修改时间倒序排列（旧记录缺少修改时间时使用创建时间）；官方曲目随后，使用 `lib/score-order.ts` 按标题拼音或英文字母 A–Z 排序。字母和分类模式中本地作品保持独立置顶。曲库工具栏在搜索框后提供排序图标按钮，点击按字母顺序 → 分类展示 → 最后修改时间循环切换，无文字或选中高亮，使用 `m3n:library-view` 保存选择，存储不可用时仍可正常切换。分类元数据由构建插件读取 `config/scorebook/library-categories.json` 注入轻量索引，不在浏览器加载谱源或PDF配置。分类与谱集一致，按顺序分为基础练习曲、进阶练习曲、器乐小品、长篇器乐作品、经典歌曲、当代流行六类；各曲只归一类，分类模式按配置中的训练顺序排列，字母模式仍按标题排序，本地作品仍独立置顶；未配置的新曲暂归“其他曲目”。最后修改时间模式将本地作品和内置曲目合并按修改时间从新到旧排列，不显示分组标题或间隔线；搜索保留该顺序。本地作品使用修改时间（缺失时回退创建时间），内置曲目由构建插件注入谱源最近一次 Git 提交时间，未提交的修改或新曲使用文件修改时间；无 Git 的源码归档也回退文件修改时间。相同时间沿用原有顺序。
- `hooks/useScoreSource.ts`：编辑页、阅读页共用的来源加载与失效请求取消；缺失和失败有明确页面状态，不替换成默认谱。乐谱动态模块加载失败时提供“刷新页面”，重新获取当前构建的资源引用；普通加载错误仍提供“重试加载”。不自动刷新，以免打断编辑。
- `hooks/useScoreDraft.ts`：草稿恢复、延迟保存与离开页面时写入；本地正式保存更新原 ID，持久化失败不得返回成功。
- `hooks/useM3NAnalysis.ts` 与 `lib/analysis-client.ts`：编辑分析的合并、版本检查与线程生命周期；不把 Worker 通信逻辑放入领域包。
- `notation/harmony-syntax.ts`：和弦符号的共享定义；和弦行解析、校验与显示名称生成复用它，最长后缀优先匹配。

乐谱库顶部仅保留同一行的“乐谱库”标题和搜索框。搜索支持曲名与署名等文本，以及词／歌词、低／低音、本地、内置、调号和拍号；空格分隔的多个条件同时满足，调号与拍号精确匹配，避免 G 命中其他调性或英文曲名。乐谱库的网格列数始终按容器宽度自动计算，单列最小宽度为260px与16倍界面基础字号中的较大值，可用宽度足够时自动排多列，不因触屏或窄屏强制单列。移动端（≤720px，或主要输入为粗指针且不支持悬停）自动使用紧凑卡片，歌名与元信息居中并隐藏署名；桌面端使用普通卡片。词、低与调号、拍号、速度统一显示在歌名下方的标签区域，不提供下拉筛选或紧凑切换按钮。

## 渲染资源与切换

默认部署在 `/`；设置 `VITE_BASE_URL=/score/ npm run build` 可部署到子路径。React Router 的 `basename`、站点图标、导出字体和分享 API 均使用同一构建基路径，Vite 负责处理模块、WASM 和音源 URL。宿主应对该前缀下的页面路由返回 `index.html`，并把 `/score/api/*` 转给现有 Worker（转交前去掉 `/score` 前缀）；存储继续实现 `M3N_SCORES` 的 KV 接口。

默认 `synth` 音色继续由 `synthetic-soundfont.ts` 本地生成原有柔和FM电钢琴，保留原有明亮起音与柔和持续声，只保留强奏采样，不再分层力度。约345KB的SF2只在内存生成并缓存；不下载采样文件，沿用现有MIDI、速度、移调和节拍器。

`sampled-tone-assets.ts` 提供钢琴、口琴、吉他、小提琴、长笛的独立FluidR3 q3 SF3资源URL。五份合计1,932,998字节；仅导入URL不请求采样。保留原采样率、声道布局、音区、包络与循环点；发布时把各文件唯一预置映射为Program 0，沿用现有MIDI及音源优先级切换。默认合成音色仍在浏览器生成，不需要下载。

`playback-tones.ts` 仅下载所选音色。使用Fetch流读取真实字节进度，未知Content-Length时显示不定进度；完成后进入准备阶段。对话框支持后台加载、取消与失败重试。AbortController中止下载，同一音色的并发请求去重，交给AudioWorklet的缓冲区与内存缓存独立。

音源同时保存在页面内存和 `m3n-fluidr3-q3-v1` Cache Storage，缓存键使用Vite生成的资源哈希URL。刷新后优先读取缓存，离线可使用已缓存音色；缓存不可用或配额不足时仍可下载及内存复用，损坏缓存重新下载。不读取旧的算法生成音色缓存。localStorage选择与跨标签页同步保持原样；文档谱例固定使用默认合成音色。


播放统一使用力度127及通道音量127，旋律、低音、倚音和颤音均保持较高响度；谱面力度标记仅显示，不改变播放响度。默认合成音色只保留强奏采样，采样以首秒RMS 0.40校准线性增益并限制PCM峰值为0.90。FluidR3保留原音区与力度范围，在固定力度127时使用相应原始采样。已取消各音色的额外增益补偿，`tone-levels.ts` 中六种音色的输入增益均为1，保留原采样电平及自然衰减。SpessaSynth输出经过25Hz高通滤波、Web Audio压缩器（阈值−12dB、压缩比4:1、软拐点9dB、起音3ms、释放120ms），不再额外施加+6dB增益补偿，再进入独立AudioWorklet峰值限幅器。限幅器使用3ms前瞻及80ms释放，左右声道共用增益，输出采样峰值不超过0.94（约−0.54dBFS），控制和弦叠加峰值；不使用硬削波或波形整形。原生压缩器另有约6ms前瞻，节拍同步由浏览器测试验证。回归测试通过实际SpessaSynth渲染检查六种音色在C3/C4/C5的音体及持续声，并在浏览器最终输出端测量六种单音乐器和密集和弦。测量使用PCM RMS及采样峰值，并非原唱录音的LUFS匹配。

播放中下载时继续使用当前音色，下载并解码完成后切换音源优先级，后续音符使用新音色，已发声音符自然结束；不重建播放器、不暂停或跳转。移调继续通过系统调音更新当前与后续旋律音符，旧异步请求不能覆盖更新后的选择。所有音源均暴露Program 0，继续与现有MIDI及旋律／低音播放兼容。

`tools/measure-fluidr3-tones.mts` 提取并编码原版PCM SF2，`tools/prepare-fluidr3-playback.mts` 直接复用q3压缩数据并映射Program 0，不进行二次编码。体积、来源与复现方式见 `docs/FLUIDR3-SIZES.md`；许可证与署名随站点发布于 `public/licenses/fluidr3/`。旧单声道钢琴压缩脚本只作历史参考，不参与构建。

生产资源必须随本站发布，禁止使用第三方 CDN 或远程渲染资源 URL。演奏编译和 MIDI 写入为项目内 TypeScript 实现，不加载 Verovio 或音乐引擎 WASM。简谱采用项目内自研排版，旧引擎和依赖已删除；实现见[自研引擎](NATIVE_ENGINES.md)。字体、音源和 AudioWorklet 来自本站构建产物。

`ScoreRenderer` 在编辑或布局参数变化时更新简谱排版。播放实例按需加载并独立销毁。

首页以浏览、看谱、播放、打印与在线编辑的使用过程介绍功能。首屏说明网站用途，提供浏览乐谱库（唯一绿色高亮入口）和打开编辑器两个入口；下方五个功能段落依次介绍曲库、阅读设置（移调、固定调、分页、小节号、页面宽度）、播放设置（音色、节拍器、速度）、PNG长图／A4 PDF下载及在线编辑。段落文案结合练习场景，在句内嵌入与实际按钮共用的曲库、编辑、打印、播放、设置、钢琴、分页、固定调、小节号和节拍器图标，用“设置 → 调号”等路径指引操作；静态图示不作为按钮或焦点目标。播放与设置图标统一由 `components/ScoreControlIcon.tsx` 提供，导航图标复用 `NavActionIcon`。移调集中在阅读段落介绍，并说明同步影响谱面与播放、导出沿用当前谱面设置；编辑段落提供编辑器、指南和手册入口。桌面端每段左右排列标题与正文，移动端纵向排列。功能介绍之后展示完整的带低音《欢乐颂》，谱源独立保存在 `src/examples/huan_le_song.m3n`，不进入曲库或谱集；曲库的 `src/scores/huan_le_song_01.m3n` 仅保留高音旋律，首页《欢乐颂》使用与阅读页相同的完整播放控件和该曲谱集默认版宽，提供限制在播放器卡片内部、随卡片滚动的底部吸附播放条及设置入口，可直接试用音色、节拍器、速度、移调、分页、固定调、小节号与宽度；不显示源码。指南和手册通过 `/?doc=guide`、`/?doc=manual` 打开，按需加载 `HomeDocumentation`，直接从内容开始，不显示首页介绍、功能段落、谱例或返回首页链接。独立文档简介页和顶部文档入口已删除，旧 `/docs` 链接重定向到首页并保留指南／手册查询及章节定位。指南和手册的所有谱例均使用简谱。加载状态分为渲染库、字体准备与排版。

布局通过视口宽度和主要输入能力判断：`(max-width: 720px), (pointer: coarse) and (hover: none)` 使用移动端规则，覆盖手机及 iPad 等触屏平板的横竖屏；其余使用桌面规则，不读取 User-Agent，也不按横竖屏识别设备。CSS 与 `lib/responsive-layout.ts` 共用这一约定；窗口尺寸或主要输入能力变化时自动重新匹配。

阅读默认开启分页与节拍器，采用该曲谱集默认版宽；用户手动关闭后沿用已保存的选择，切曲时重置，保留可读字号；桌面阅读页（>720px 且不满足触屏布局条件）分页按顶部栏下方、底部悬浮播放条上方的剩余窗口高度等比缩放整页，多页居中并排，超出一行时自动换行并使用页面纵向滚动，不产生内层滚动条；窗口尺寸或控制面板高度变化时重新适配，仅改变屏幕显示尺寸，不改变排版版宽、分页结果或导出尺寸。移动端（≤720px，或主要输入为粗指针且不支持悬停）分页始终按可用宽度显示并纵向滚动，不按窗口高度缩小整页；移除渲染卡片边框、内边距和分页纸张阴影；阅读页保留屏幕两侧9px留白，谱内保留默认32px页边距；白底分页之间以16px透明间隔露出页面底色，保留分页及宽度设置。阅读宽度通过设置弹层中的滑条调整，打印版宽直接沿用当前阅读宽度，不读取旧的 `m3n:print-width`。共享排版入口将每页内层 SVG 的尺寸明确为外层 viewBox 的坐标尺寸，避免 PDF 转换器把后续页的默认百分比尺寸解释为打印视口而二次缩放。

播放设置不再提供选中小节播放、A–B 循环、声部静音和播放跟随，播放器同步移除循环和声部静音接口。速度以滑条在10–240整数BPM之间逐一调整；一拍与谱面拍速和节拍器一致，按初始拍号分母计拍。例如 6/8、80 qpm 的原速为 160 BPM。播放器按目标 BPM 与 MIDI 初始拍速的比率调整时间轴，保留谱中变速的相对关系，首次起奏及暂停后继续播放时，独立按当前 BPM 提示三拍：从头播放在首个音符（含开头休止符）上依次显示红、黄、绿矩形背景，背景严格贴合音符数字的实际文字包围盒，不加外边距或描边，避免行首零谱内边距时被画布裁切，续播在当前位置之后的下一个旋律音符上显示；保留原暂停位置，三拍结束后恢复正文。预备期间再次暂停立即取消提示；重排谱面后保留同一续播位置与遍次的提示；不再按拍号或弱起长度计算预备拍。每次打开或切换乐曲采用谱面原速（超出范围时截到边界），手动速度仅保留在当前页面，不读取旧速度缓存。速度还原清除当前覆盖值，不改变其他开关。

首次播放按需加载自研演奏编译和 MIDI 模块，并初始化 AudioWorklet；合成音色仅免去音源采样下载。MIDI 准备和音频播放器模块加载并行执行；同一乐谱的播放器与渲染工具在页面内复用。 音色选择在暂停时仅保存偏好，不下载采样；点击播放后才检查并加载所选音色。点击播放后，所选音色未命中内存或持久缓存、需要下载采样时显示加载对话框；该次下载完成后继续显示“正在准备”进度，直到音色安装与播放器初始化完成，在预备拍开始前关闭。以本次是否发生下载记录弹窗条件，不随进度从 download 切到 ready 提前关闭，避免快速下载时漏显。内存或持久缓存命中、页面打开及普通播放初始化均不弹窗。播放中切换音色继续后台加载并保留播放位置。

为兼容 iPhone/iPad 的音频手势限制，播放及进度拖动入口在用户操作的同步调用栈中创建并恢复 AudioContext，再开始模块及音源加载；SpessaPlayer 接收并复用该上下文。暂停后继续播放同样先恢复上下文，避免 iOS 中断音频后无法续播。更换乐谱或离开页面时释放上下文，包括尚未完成播放器初始化的情况。

网页、预览和PNG使用设备已安装的系统文字字体，不请求中文字体文件；仅保留小体积内嵌音乐数字字体。单曲导出入口使用打印机图标和“打印”文字，弹窗仅提供 PNG、PDF 两个按钮。PNG 与 PDF：PNG 自动按连续模式生成带外侧白色画布的长图；单曲与全量谱集共用 `createScorePdf`，按需加载 `pdf-lib` 和音乐字体子集处理模块，统一直接下载A4文件，不依赖浏览器打印窗口。PDF直接写入原生SVG的路径、线段、矩形、圆和文字，不经过画布或嵌入整页图片。音乐数字从谱面已有的Barlow字体中嵌入所需字形；所有PDF（内置、本地、分享单曲和全谱集）仅在开始PDF生成时按需下载 `src/assets/builtin-pdf-text.ttf`。先检查整份文档的普通文字字符：全部覆盖时，Noto宋体按文档进一步裁子集并嵌入，粗体模拟加粗；任一字符缺失、字体下载失败或解析失败时，整份文档回退到原有方案：普通中文声明 `STSong-Light`，英文及普通标点声明 `Times-Roman` 及其粗体／斜体变体，不嵌入普通文字字体。回退时由阅读器替换字体，不保证跨设备的字形和罕见字符覆盖。字体仅交给PDF生成器，不注册FontFace，不用于网页、预览或PNG。逐字使用浏览器实测起点与基线，避免替代字体的累计字宽改变歌词位置；PDF保留Unicode映射，可搜索及复制文字。Adobe GB1字符映射只是编码元数据，按文档所用字符写入PDF，不包含字体或字形；来源与许可证见 `public/licenses/adobe-cmap/`，离线再生成入口为 `tools/prepare-gb1-cmap.mjs`。单曲按12mm纸张边距等比放置，谱集页面包含已有A4留白，传入 `fullPage` 不再添加第二层边距。保留SVG内网站链接为PDF链接注释。逐页生成、显示进度并让出主线程；谱集离开页面会中止下载并清理临时容器。打开预览或开始谱集排版时预加载PDF模块；两类导出共用 `PdfDownloadPanel` 和相同对话框样式，在计算前先绘制进度界面，逐批让出主线程并检查取消。重复音符与普通文字在单次生成中缓存编码，避免反复字形排布及中文WinAnsi编码异常。下载链接挂载到文档，Blob URL延迟60秒释放，兼容手机异步下载。预览继续沿用外部当前分页设置；单次打开对话框创建一个 `PreparedNumberedNotationScore`，预览与不同导出模式共用已测量谱行，只切换分页生成SVG，保留版宽及其他显示设置；关闭或设置变化后释放。连续模式预览与PNG共用宽度6%的外侧白色画布。乐谱库提供“导出谱集”入口，`ScorebookExportDialog` 显示逐曲进度、取消及错误重试；按需加载 `lib/online-scorebook.ts`，以谱源建议版宽排版独立曲目，额外测量固定640px合页容量。在线版与独立脚本共用 `tools/scorebook-layout.mjs` 的几何测量、合页渲染和A4放置，以及 `tools/scorebook-packing.mjs` 的章内分组算法与 `config/scorebook/editorial-plan.json` 装订配置，生成同规则的合页、封面和目录，完成后复用同一矢量PDF生成和直接下载入口。在线生成不做候选版宽搜索或±5px稳定性检查，不写入谱源或本地设置；重新选宽、稳定性检查与版宽回写由独立脚本负责。完整字体仅保存在 `tools/fonts/` 供独立发布工具使用；网站仅发布约590KiB的预置子集，来源与SIL OFL许可证见 `public/licenses/noto-serif/`。

`tests/e2e/render-resources.spec.ts` 在阻断所有外站 HTTP 请求的条件下验证显示、切换和播放，检查播放不请求 Verovio 或 WASM、谱例节点保留，以及编辑和版宽变化后的缓存失效。生产构建使用 Vite 默认的按需分包。端到端测试使用 `.tmp/playwright-dist-<port>` 独立构建，避免常规 `dist` 重建中断测试。`M3N_E2E_PORT` 可覆盖预览端口。设置 `M3N_E2E_BROWSER=webkit` 可用 WebKit 执行同一套端到端测试（需安装 Playwright WebKit 浏览器及其系统依赖），覆盖 iPad 设置弹层高度与按钮尺寸；默认仍为 Chromium。测试附件记录本机冷启动与切换耗时，性能数字不作为设备或网络的固定门槛。

## 质量门禁

提交前执行 `npm run check`，依次完成 AST 导入边界检查、lint、各包严格类型检查、包级与应用级测试、生产构建和端到端测试。测试分三层：

1. 基础语法单元测试，覆盖音符、时值、调号和行式歌词、低音对位。
2. 转换契约测试，覆盖往返、诊断和源码映射。
3. 全量内置乐谱语料测试，防止真实乐谱在重构后无法转换。

`tools/check-boundaries.mjs` 检查静态／动态 import 的包边界、依赖声明与公共入口；notation 类型检查不引入 DOM 库。已修复的回归必须先有失败测试。第三方库细节应封装在 feature 或 component 边界，不得渗入 notation 内核。

## 继续维护时的约束

- 新语法同时验证领域、自研演奏与简谱投影。
- 原文只在分析边界分词；元数据、诊断、格式化和交互消费已有模型。不要在界面组件中追加指令正则解释器。
- 播放顺序及遍次使用 `notation/repeats`；谱式特有的歌词行视觉标签由各适配器维护。
- 不将 SVG 坐标或具体编辑器对象放进领域模型，不为缩短文件制造单行转发层。

乐谱库在列表顶部、首个分组或曲目前用小字显示当前排序方式：“首字母”“音乐类型”或“编辑时间”，切换排序时同步更新，搜索无结果时也保留提示。乐谱库在字母顺序模式下按与排序相同的拼音／英文首字母分组，组头横线吸附于页面顶部，每组独立排列响应式卡片。本地作品独立列为最前面的“本地作品”组，保留最近修改顺序；右侧“☆”定位该组。至少12首且至少3组时显示右侧首字母索引，只列当前搜索结果中存在的组；支持点击、键盘按钮及指针捕获后的上下滑动定位，拖动显示大字母提示。索引为独立触摸区域并在内容右侧预留空间，普通页面滚动同步高亮当前组；非字母标题归“#”组。分类展示和最后修改时间模式完全隐藏右侧索引及其预留空间，搜索仅显示仍有匹配曲目的分类。

阅读页“上一曲／下一曲”固定使用曲库分类顺序：先按分类顺序，再按分类内曲目顺序，未分类曲目排在最后并按标题排序；不受曲库页面当前展示方式影响。顺序来自 `config/scorebook/library-categories.json`。

独立作品另存 `src/works/`，使用仅通过链接访问的 `/works` 列表和 `/works/:slug` 阅读页，不增加公共入口。`worksCatalogPlugin` 生成独立的 `works-catalog.json` 和按内容摘要命名的源文件，只在作品路由中请求；公共曲库及整册谱集不消费这个目录。阅读器和编辑器通过显式集合参数加载源文件，避免同名作品串入公共曲库，草稿和播放状态也区分集合。归档及链接规则见 [独立作品](WORKS.md)。

可选五线谱通过 `@m3n/score-renderer/staff` 独立入口按需加载；只读取 `ScoreDocument`，播放继续使用当前演奏编译器。屏幕与单曲PNG／PDF共用五线谱输出，全量谱集仍固定使用简谱。独立模块、引擎来源与验证见[五线谱显示](STAFF_NOTATION.md)。
