# 五线谱与简谱排版规则审计

历史记录：本文描述旧引擎及当时仓库内的源码。当前实现已迁移至VexFlow，原构建与音乐XML链路已删除；见[五线谱显示](STAFF_NOTATION.md)。文中的历史文件可通过Git历史查阅。

审计日期：2026-11-20。本文保留实施前的差异与统一建议；用户随后授权逐项实施，最新已实现规则见 [五线谱显示](STAFF_NOTATION.md#统一排版策略)。下表及最小案例均描述实施前行为。依据为本地文档、两个渲染器的实现，以及随项目分发的 Verovio 6.2.0 源码和 WASM 实测。

## 实施结果

所有建议统一的规则均已实现：作者硬边界与段名语义、多小节编号、共用动态规划分行、按A4容量选择横向弹性、逐页有限纵向弹性、`leading`、末行继承、等宽小节、安全小节分片、实际文字测量与避让、歌词净空与空槽、实测谱头及长文字折行、仅首页谱头容量、连续与分页横向一致。实际宽度和大谱表歌词净空不足时，反馈引擎重排；不拉伸音乐字形。

保留的差异是审计中判定合理的谱式特征：谱号、调号、符干、加线、大谱表、关系符号的具体画法、独立建议版宽，以及绝对音高表示所需的变调访问展开。两种谱式不承诺同宽同断点或同页数。验证入口及实现说明见上述最新文档。

## 结论

适合统一的是作者指令的含义、音乐结构、安全要求和页面容量策略；具体字形占位、节奏间距公式、谱表结构应保留各谱式特点。统一不应要求相同版宽下具有相同的每行小节、横坐标或页数。

当前五线谱并非完全没有弹性行距或碰撞避让：项目按页数在 `spacingSystem=3/4` 中选择，Verovio 负责谱内排版；但它没有简谱的逐页核心净空拟合，也没有本项目同等级的实际笔画碰撞检查。已有全库选宽通过边界与谱行包围框检查，不能推导出行内所有图元均无碰撞。

## 差异与统一判断

| 规则 | 简谱现状 | 五线谱现状 | 建议与实现判断 |
| --- | --- | --- | --- |
| 显式 `{br}` | 强制边界，自动分行不跨过 | 投影为 `<sb/>`，但 `breaks=smart` 默认只采用行宽使用率超过0.66的标记 | 应统一为硬约束；优先修复。可以先验证 `breaksSmartSb=0` 配合 smart 自动分行；不能直接改成只按编码换行而丢失自动分行 |
| 具名乐段起行 | 段名事件触发起行，并有段间留白 | 只生成 `<reh>` 标记，未依据段名增加 `<sb/>` | 应统一起行和结构留白；方框与具体位置可遵循谱式习惯 |
| 段名后的 `{br}` | `sectionLabelBreakAfter` 控制段名独占上方位置，且与音乐保持同页 | 该字段未被五线谱投影消费，与普通段名生成相同标记 | 应统一排版意图；需要标题占位和与首行绑定，不应生成一个空五线谱行来模拟 |
| 横向弹性 | 0.4em基准，依次试0.60/0.55/0.50/0.45，不增加A4基准页数时取最大参数 | 沿用引擎节奏间距参数，未做横向容量候选搜索 | 适合统一“不增加基准页数时尽量舒展”；候选参数须按五线谱校准，不能把0.4～0.6直接当作引擎参数 |
| 纵向弹性 | 最小核心净空分页后，逐页拟合至32px上限，保持分页 | 整曲选择3或4单位；未启用引擎默认关闭的 `justifyVertically` | 适合统一先定分页再逐页有限放宽；须区分系统间距和同系统上下谱表间距，不能把所有空白均摊或直接套用32px |
| `{leading}` | 消费 `minimumCoreGapEm`，影响最小净空及自动横向选距 | 未消费该字段 | 文档当前明确限定简谱，属于能力差异；若扩展为通用参数，应定义五线谱音乐尺度及下限，或增设独立参数，不能将em数值直接赋给 `spacingSystem` |
| 自动分行与疏密平衡 | 强制边界内用动态规划，包含相邻行密度差；只对整曲短末行放宽部分代价 | 使用引擎按小节宽度与溢出推进的分行，没有项目这套密度评分 | 适合统一避免短尾和疏密突变的目标；严格复用算法需要取得五线谱小节最小占宽、行首调号谱号成本和续接成本，再把选出的断点交给引擎 |
| 末行收尾 | 继承上一行单位伸展量，试排不超过可用宽度60%才留白；仅整曲末行 | 默认 `minLastJustification=0.8`，以引擎未撑满宽度决定是否撑满 | 可统一“短末行留白、避免突然疏松”；60%与80%的判断量不同，单改阈值不等价，精确统一需要前行间距信息 |
| 等宽小节 | 消费 `{equal-measures=true}`，按行内最密小节决定格宽和容量 | 未消费 `equalMeasures` | 可以作为显式选项统一，适合练习谱；不建议设为五线谱默认。`evenNoteSpacing` 是音符等距，不是小节等宽，不能替代 |
| 超宽单小节 | 可在时间列拆分，保留连音组完整及整拍断点偏好 | 项目未提供同等拆分逻辑，自动分行以完整MEI小节为单位 | 宜统一“不裁切、不挤压到不可读”的底线；五线谱小节中途断行需要处理小节身份、跨行小节线和连音，不能直接照搬简谱片段 |
| 碰撞与占位 | 实际文字墨迹、描边与曲线极值；按真实笔画避让；关系有明确层次 | 引擎内部布局后再转换SVG文字；中文通过零宽字符补偿；未按浏览器最终字体重新排版 | 应统一实际墨迹安全标准；不必共享同一避让算法。中文歌词、段名、长文字优先补实测校验，必要时反馈占宽重排 |
| 歌词层高与空槽 | 22px音乐字号下歌词16px，首层净空6px、层间4px；尾部空槽不新增墨迹层 | 使用引擎歌词字号、行高和MEI verse；空槽仍投影为不可见字符，中文空槽带额外补偿 | 应统一语义对位、空槽无额外可见占位及可读性；具体比例可不同。不可见字符是否造成额外层高需单独浏览器测量，不能由无可见文字认定无占位 |
| 谱头与长文字 | 标题、副标题、调拍速、署名按实际占位共享高度；长顺序折行 | 标题、副标题、顺序、署名逐行居中，固定高度；顺序为一条文字，无宽度驱动折行 | 可以统一，且不受五线谱记谱习惯限制。适合提取通用谱头测量和绘制，不必复用简谱音乐布局 |
| 首页与后续页容量 | 谱头作为实际页面内容参与分页 | 所有分页的引擎页高都减去 `headerHeight`，但只在第一页添加谱头 | 宜统一仅首页为谱头预留容量；当前后续页容量偏保守，会浪费空间，实际页数收益须重排验证 |
| 多小节休止编号 | 书写编号按 `multiRest` 累计 | 每个MEI measure仅 `measureNumber += 1` | 应统一，属于编号语义遗漏。四小节休止后的普通小节应是第5小节；不能只修显示文字而不修编号来源 |
| 上下声部组织 | 使用简谱声部及其局部墨迹组织高度 | 存在低音时建立双五线谱，使用大括号和贯穿小节线，默认谱表最小间距12单位 | 不应照搬简谱几何；应统一同时刻对齐和碰撞安全，保留大谱表结构 |
| 关系与符号表现 | 八度点、增时线、简谱器乐括号；明确安排弧线与渐变线层次 | 使用符干符尾、加线、延音线、八度线等五线谱符号；交给引擎安排层次与跨行续接 | 音乐区间及续接完整性应统一，具体符号、上下位置和曲线形状保留谱式惯例 |
| 宽度选择 | 浏览器按简谱分页页数自动搜索 | 浏览器按五线谱分页页数自动搜索 | 两种谱式分别测量，不在谱源保存版宽 |

## 已复现的最小案例

用项目当前WASM、Leipzig字体、720px对应版宽、`scale=38`、`breaks=smart`，直接执行 `scoreToMei` 后排版。以下案例解析诊断均为空。

```m3n
{4/4}
N: 1 2 3 4 | {br}5 6 7 1e |||
```

生成1个 `<sb/>`，最终SVG只有1个 `g.system`。本地引擎源码 `CastOffSystemsFunctor::VisitSb` 确认 smart 模式受 `breaksSmartSb` 门槛控制，实际默认值0.66。单独将门槛设为0后，该例得到2个系统，说明存在配置层面的修复入口；尚需覆盖其他换行情形。这里是作者硬换行被软化，不只是两种谱式自动断点不同。

```m3n
{4/4}
===A
N: 1 2 3 4 |
===B
N: 5 6 7 1e |||
```

生成0个 `<sb/>`，最终只有1个系统。把两个段名分别改成 `===A{br}` 与 `===B{br}`，结果仍为0个换行标记、1个系统，验证段名后的特殊字段未被消费。

```m3n
{4/4}
N: {rest=4} | 1 2 3 4 |||
```

当前MEI的两个 measure 编号是1、2；按实际书写小节应为1、5。当前行尾小节号从MEI编号派生，因此受到影响。

作为对照，把第二个案例的两个具名乐段改为普通 `---` 乐句边界，同样只生成一个系统。这符合手册“`---` 不强制换行”的语义，不应为了统一段落而把所有乐句都强制分行。

上述实测针对引擎结构和MEI编号；本次未新增浏览器截图、全库排版或碰撞通过声明。

## 已有共同规则与核验边界

- 二者消费同一个 `ScoreDocument`，共享事件身份、播放和源码定位。
- 普通反复保持紧凑，按访问换调时五线谱展开；这是绝对音高表示的合理需要，接近固定调简谱，不能强求与首调简谱相同布局。
- 调号入口都依据实际演奏前序判断；小节号的产品规则都是每行末尾显示。
- 屏幕与单曲导出使用同一谱式入口；外层A4与导出容器已有共享能力。
- 简谱连续／分页复用横向排版；五线谱两种模式共享选定的系统间距，但会分别调用引擎排版。严格保证每行内容与横坐标一致还需要对照实测，不能仅由共享参数推导。
- 两套选宽都考虑最少页数、实际候选宽度；宽度扰动检测已删除；几何检查粒度不同。五线谱当前主要检查整页墨迹边界及相邻系统矩形，无行内逐对象碰撞审计。

## 实施顺序与成本

1. **先修语义遗漏**：硬换行、段名起行与独占位置、多小节休止编号。编号改动小；换行需覆盖短行、自动溢出、房子、Coda与展开访问。段名独占位置还需测量及分页绑定。
2. **统一通用页面规则**：实测谱头、长顺序换行、仅首页谱头容量、中文字形边界与歌词安全。以实际SVG检查作为重排验收条件。
3. **统一弹性策略**：定义五线谱可读的紧凑基准和候选范围，先试横向间距，再在不增加基准页数的条件下选择舒展程度，最后固定分页逐页放宽纵距。新增策略基准可先沿用现有紧凑排版；硬换行及安全修复本身可能增加页数，不能因追求旧页数而撤销这些约束。
4. **最后评估高成本精确规则**：全局疏密平衡、前行继承式末行、等宽小节、超宽小节拆分。前几项需要引擎测量或布局控制，不是改几个配置即可完整实现；必要时才修改本地Verovio源码并重建WASM。

不建议在SVG生成后直接拉伸整幅图来模拟弹性：会改变五线间距、符头比例、歌词及线宽。移动完整系统实现纵向拟合可以评估，但需同步调整跨系统对象、页面边界和交互范围；横向重排应由音乐布局阶段完成。

## 主要实现依据

- `packages/numbered-notation/src/native-model.ts`：段名强制起行、段间距、多小节编号。
- `packages/numbered-notation/src/native-layout.ts`、`native-horizontal.ts`：横向候选、分行、末行与纵向布局。
- `packages/score-renderer/src/staff/score-mei.ts`：换行、段名、编号和关系投影。
- `packages/score-renderer/src/staff/staff-score.ts`：引擎参数、系统间距候选、固定谱头及页高。
- `packages/score-renderer/src/staff/mei-lyrics.ts`、`svg-text.ts`：歌词补偿和布局后的文字转换。
- `tools/staff-width-layout.mjs`：当前五线谱几何验收范围。
- `public/licenses/verovio/verovio-6.2.0-source.tar.gz` 中 `src/options.cpp`、`src/castofffunctor.cpp`、`src/doc.cpp`：引擎默认参数和分行流程。
