# 五线谱字形墨迹追加与缩放复用

2026-11-27，独立工作树 `perf/single-worker-600`，基于 `dc44d215`。五线谱规则仍冻结为已合并的 `a5a4c30b`：6px谱间、0.6／1.8谱间双档。单Worker、528～720px全部33个6px档位及安全剪枝保持不变；不将主线之后的设计规则变化计作提速。

候选音符原先为每个字形建立临时墨迹数组，再展开追加到音符数组；每次重复字符查找、字符迭代及四边缩放。现在已知字形名直接向目标数组追加，按字形和字号复用缩放后的轮廓框。普通字形节点和SVG回读也共用此度量。每个字形最多保留8个字号；超过时清空该字形的字号缓存，避免交互字号形成无界历史。

缓存中的框不向外暴露；每次放置创建私有坐标，外部修改候选不能污染后续布局。乘法和坐标相加的顺序、全部设计轮廓框及其顺序均保持不变，不合并框、不近似曲线，也不改变任何搜索、分行、分页或评分算法。

## 全量测量

117首，真实归档TTF，每批一个新Chromium，批内共享字体和文字度量；无预热、profiler、最终SVG。各批串行，Node堆384MiB、浏览器堆256MiB，聚合RSS守卫1700MiB。基线使用此前符杠优化后的重复全量报告。

| 五线谱 | 基线 | 本次 | 本次复测 |
|---|---:|---:|---:|
| 累计选宽 | 38.578秒 | 37.979秒 | 38.246秒 |
| 基本功 | 1808.9ms | 1779.1ms | 1802.5ms |
| 超600ms | 18/117 | 18/117 | 18/117 |
| 聚合RSS峰值 | 1446MiB | 1338MiB | 1340MiB |

累计耗时下降约0.9%～1.6%，仅是小幅改进。基本功变化不足以证明其主要瓶颈得到解决，超600ms曲目数没有减少。此前其他实验也曾观测到约1348MiB峰值，因此这里的峰值差异不能单独归因于该缓存。**所有乐曲、所有谱式600ms目标仍未达到。**逐曲数据见[CSV](WIDTH_GLYPH_APPEND_PERFORMANCE.csv)。

两轮报告各有1733组赢家／候选与基线一致，包含宽度、页数、行数、物理间距及全部评分分量，绝对误差阈值1e-8；逐曲谱源和字体摘要相同。五线谱24个测试文件239项通过，包构建通过。新增回归遍历全部字形及超过缓存容量的字号序列，与原始分发数据直接运算的结果严格相等，并验证修改返回坐标不会污染后续追加、字符回读或绘制节点。

原始报告为 `.tmp/numeric-beams-repeat/staff.json`、`.tmp/glyph-append/staff.json` 和 `.tmp/glyph-append-repeat/staff.json`。另一次单曲冷启动基本功基线为2176.8ms，不能与批内测量混作同口径提速证据。复现先构建包，再运行：
