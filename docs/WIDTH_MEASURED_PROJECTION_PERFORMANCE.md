# 简谱未放置度量投影复用

2026-11-27，独立工作树 `perf/single-worker-600`。沿用 `1960a42f` 的排版规则，保持单Worker与528～720px全部33个6px档位，仅使用有证明的安全剪枝。五线谱规则冻结在本分支已合并的 `a5a4c30b`，后续主线谱间试验不计入此次性能对照。

此前每个候选先复制原始投影，再逐小节、逐音符列回填已测量的横向跨度。现在按基础间距、间距下限和等宽小节设置保存尚未分行、尚未放置的度量投影；下一候选从它复制私有的放置状态，同时复制横向度量。器乐括号的端点留白也随该间距设置保留。换字体、度量器或谱源设置仍重建任务准备；已返回布局不能改变共享准备。

该修改删除独立的横向跨度快照类型和二次回填遍历，不增加搜索或分页算法。简谱原有跨宽度不变的度量、关系拓扑和横向约束复用仍保留。

## 全量测量

117首，真实归档TTF，每批一个新Chromium、批内共享字体及文字度量，无预热、profiler或最终SVG。各批串行，Node堆384MiB、浏览器堆256MiB，聚合RSS守卫1700MiB。

| 简谱 | 原缓存生命周期版本 | 本次 | 本次复测 |
|---|---:|---:|---:|
| 累计选宽 | 24.756秒 | 24.352秒 | 24.363秒 |
| 基本功 | 1402.8ms | 1355.9ms | 1367.4ms |
| 超600ms | 7/117 | 7/117 | 7/117 |
| 聚合RSS峰值 | 1352MiB | 1345MiB | 1356MiB |

两批累计耗时均降低约1.6%。基本功仍远超600ms，且内存峰值没有明确改善，不能据此认定主要瓶颈已解决。逐曲数据见[CSV](WIDTH_MEASURED_PROJECTION_PERFORMANCE.csv)。**所有乐曲、所有谱式600ms目标仍未达成。**

两次全量测量各有892组赢家／共同候选与基线一致，包括宽度、页数、行数、逐间隔统计和全部评分分量，绝对误差阈值1e-8；谱源和字体摘要相同。简谱任务、数值行几何、双档、间距选择与横向布局共5个文件60项测试通过。新增回归组合切换宽度、基础间距、间距下限和等宽设置，再回访原设置；器乐括号与测量跨度的候选侧修改不影响后续布局。

## 未保留的五线谱实验

另试过将墨迹分类从对象身份改为输出序号，从而允许内部不可变查询复用图元，省去区分类别所需的一次整批复制。序号迭代器版本两批累计38.190／38.931秒；去掉序号对数组分配后为38.766秒。与原版本38.910／38.578秒相比，没有明确、稳定的提速，因此撤回实现及对应测试改动。

该实验最终聚合RSS峰值1348MiB，前两批1452／1460MiB；单次峰值下降不足以证明稳定改善，也不能代替选宽耗时目标。实验中五线谱238项测试通过，最终全量报告1733组赢家／共同候选仍与原版本一致。报告保留在 `.tmp/partition-indices/staff.json`、`.tmp/preparation-repeat/staff.json`、`.tmp/partition-indices-final/staff.json`；这些不是已提交实现的性能数据。
