# 五线谱显示

五线谱通过 `@m3n/score-renderer/staff` 独立入口按需加载。默认仍为首调简谱，设置中可选择首调、固定调或五线谱。简谱、播放与整本谱集不加载五线谱模块。五线谱支持源码定位、播放高亮、移调、连续／A4分页及单曲PNG／矢量PDF导出。

五线谱与简谱均由阅读器在480～640逻辑px之间按10px档自动选择分页页数最少的宽度；手动调整只影响当前阅读会话。

## 直接领域投影

```text
ScoreDocument → projectStaffDocument → VexFlow局部测量及绘制
                                    → planScoreLines共享分行
                                    → 实际墨迹避让与A4分页 → SVG
```

不序列化音乐中间格式，不重新解析源码，不修改领域文档。`staff-document.ts` 保留音符、和弦、休止符、连音组子音符、歌词、临时变音、谱号所需音高、调拍速、反复和分行意图；沿用 `scoreEventIds`。普通反复保持紧凑；分遍调号和带调性／八度基准的访问由现有 `staffDisplayScore` 展开，保留源码ID、歌词遍次与演奏身份。

播放仍由项目的演奏编译器与SpessaSynth完成，不使用绘谱库的演奏模型。五线谱模块不请求WASM，资源下载失败仍可切回简谱。

## 引擎边界

固定使用 `vexflow@4.2.5` 的 `vexflow/bravura` 入口。此版本直接携带Bravura矢量轮廓，音乐绘制不依赖浏览器音乐文字的字体测量和后续路径转换。只载入Bravura音乐数据；文字仍使用项目的Barlow Semi Condensed与思源黑体。依赖及素材全部随本站发布，无CDN。

- `staff-document.ts`：纯领域显示投影、绝对音高、歌词和身份，以及共有事件边界处的小节分片。
- `vexflow-engine.ts`：VexFlow对象、谱号调拍号成本、音符／和弦／倚音／符杠／连音组、时间列测量与SVG绘制。
- `line-layout.ts`：读取真实音乐占宽与文字墨迹，调用共享动态规划，分配小节宽度。
- `staff-system.ts`：系统组织、大谱表、歌词、反复房子、跨行关系和附属记号。
- `system-layout.ts`：文字、关系、实际笔画碰撞、核心净空和分页。
- `staff-score.ts`：字体准备、横向选距、布局缓存、连续／分页及导出公共入口。

引擎代码不进入 `@m3n/notation`。VexFlow仅负责局部雕版，项目控制分行、页面、文字、事件身份和交互。旧引擎的npm依赖、WASM、C++构建与补丁、音乐XML投影已删除。VexFlow许可证见 `public/licenses/vexflow/`；独立Bravura字体、原始字形和OFL声明见 `public/licenses/bravura/`。

## 排版策略

`{br}` 为硬换行，具名乐段另起系统；普通 `---` 仅划分乐句。段名用方框，段名后的 `{br}` 或超过半行的长段名使段名独占上方位置并与首个系统保持同页。长段名、演奏说明与谱头按实测宽度折行。谱头和简谱共用内容及文字折行策略。

每小节以VexFlow格式化后的时间列为基础，考虑符头、临时记号、倚音、调拍号、符干／符尾、歌词和和弦文字占宽。相同时刻上下谱表共用横坐标。行首单独测量谱号和调号成本。空歌词槽保留ID而无可见占位。超宽小节只在所有声部共有的事件边界分片，优先整拍，连音组不可拆分；原小节号、事件ID和歌词保持不变，内部小节线隐藏。

多小节休止虽然没有普通音符时间列，仍为横杠及计数预留完整宽度和两侧净空；横杠居中于谱号、调拍号之后及末尾小节线之前的可用区域，并扣除结束反复记号的占位。计数使用粗体，居中于横杠上方，按数字实际墨迹与最上方谱线保持2px净空。

共享 `planScoreLines` 在强制边界内按密度与相邻行密度差选择全局组合。`{equal-measures=true}` 按行内最密小节分配相同格宽，保留小节内节奏布局。末行（包括独立的短尾段）继承前行的单位伸展量，等宽模式继承格宽；继承宽度不超过整行60%时留白，仍保留段名与硬换行。只移动时间列，不缩放字形或五线。

横向以0.25为紧凑间距基准，再依次尝试0.375、0.34375、0.3125、0.28125；选择不增加基准A4页数的最大间距。参数控制时间列间的附加空隙，不直接对应旧引擎参数。每档重新测量、分行、避让和分页，不假定页数单调。

歌词设计字号16px，音乐设计尺度22px。歌词首层与音乐净空6px，层间实际墨迹净空4px。多层歌词需要更大低音谱表间距时，整套系统重新绘制，使大括号、低音谱表、贯穿小节线和关系一致。关系与文字按实际墨迹避让，符杠和延音线参与歌词占位。

速度标记按其横向范围内的音乐墨迹贴近谱面，初始净空6px，再避让连线和表情文字；高音和符干会相应抬高标记，不再保留固定的顶部空白。独占行的段名仍位于速度标记与谱面之间。

Fine、D.C.、D.S. 及 Coda 等导航记号按局部音乐墨迹放置，净空4px，遇到房子线、休止计数及其他文字时向上避让。

`{leading}` 指定22px设计尺度的em，默认1.2（26.4px）。核心为最上、最下谱线之间的区域（大谱表取整组外边界），不把歌词或局部突出音符计入核心。纵向取核心最小净空与横向重叠的实际笔画避让要求的最大值，不重复累加附件高度；普通笔画碰撞净空为核心参数的一半，段间另加12px。先按最小净空确定分页，再逐页（含末页）将净空放宽至32px内能容纳的最大值；原下限超过32px时维持下限。连续模式采用最小净空。两种模式共用系统、字形和横坐标，分页只平移完整系统。页数和旧引擎结果不要求一致。

应用默认谱内边距0，纸张和图片留白由外层提供。`pageMargin` 可显式设置；`coreGap` 仅影响最后纵排，横向选距仍以谱头行距为虚拟A4基准。谱头与首系统或单个系统无法放入A4时，连续模式保留紧凑布局，分页明确报错。

开启小节号后，仅显示每系统最后一小节的编号，并右对齐末尾小节线；与房子横向重叠时移至房子上方。多小节休止按实际书写小节数累计。房子与行尾编号参与系统间的实际碰撞检查，房子保留2px、行尾编号保留4px笔画净空，避免把普通附属文字的半核心净空叠加到这些边缘标记上。编号右对齐在碰撞测量前完成，输出阶段不再移动。屏幕、PNG和PDF消费相同SVG；字符位置按浏览器实际测量展开，音乐保持矢量路径。

## 验证与选宽

- `npm run test -w @m3n/score-renderer`：领域投影、完整曲库身份和不变性、临界版宽、共有断点、分页容量和缓存一致性。
- `npm run test:staff-layout`：真实浏览器检查全库最终SVG边界、A4容量、系统间及系统内的实际像素碰撞，包含房子挂钩、行内调号及独立音符／和弦／休止符；符杠与符干的有意连接不算碰撞。`node tools/verify-staff-layout.mjs --score=文件名片段` 可定向运行；加 `--measure-numbers` 检查开启小节号的版面。
- `tests/e2e/staff-layout.spec.ts`：硬换行、实际可见五线、连续／分页横坐标一致、等宽小节、字形尺寸、大谱表歌词和超高谱头。
- `tests/e2e/staff-notation.spec.ts`：无WASM请求、三态选择、定位、高亮、移调、资源失败恢复、反复房子、PNG／矢量PDF。

阅读器每次打开五线谱时都会重新选宽，不保存或复用上一次结果。搜索只比较分页页数，不对候选宽度执行越界、碰撞或稳定性检查；旧离线选宽报告仅作为历史记录。
