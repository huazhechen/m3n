# Sparks NMN 对照审视：口琴制谱功能与文档

审视日期：2026-11-16。对象为 Sparks NMN 公开指南（首页标明文档版本 1.15.1—1.15.9），以及 M3N 当前工作区的文档和应用实现。

## 范围与结论

已读取对方指南、教程和速查表共 39 个非目录文档页；先阅读本项目 `docs/`，再核对编辑、播放、文件、导出与文档组件。此次没有运行两站的交互式浏览器验收，不能据此断言排版质量或演奏音效谁更好。对方写明“计划”“即将到来”的功能不算已实现。

M3N 的基础旋律记谱已经较完整。对于口琴制谱，优先事项应当是：口琴演奏信息、适配音域、实用打印控制，以及从写谱到保存和练习的操作说明。多声部、鼓谱、微分音、音乐剧念白和复杂条件反复不宜成为追赶指标。

下面区分三件事：对方文档已展示而我们缺少的能力、我们已有但用户文档未充分介绍的能力、基于口琴场景提出的独立产品建议。优先级是本次建议，不是既有开发承诺。

## 功能建议：按口琴场景排序

| 优先级 | 建议 | 差距性质、必要性与最小范围 |
| --- | --- | --- |
| P1 | 口琴教学标注 | 口琴场景独立建议。已有换气和位置文字，但未见专门的孔位、吹吸、推键、压音标注模型。先明确首要琴种；若以半音阶为主，先支持手工逐音标注孔位/吹吸/推键及谱面图例，再考虑自动生成。十孔压音等另做琴种规则，不能混为通用指法。 |
| P1 | 音域检查与升降八度 | 口琴场景独立建议。已有选调和固定调显示，但未见按琴种/调律检查可奏范围的入口。先提供琴型、最低/最高音与超界音符定位，再提供明确的整体八度调整。不要自动截断音高，也不要把选调等同于音域适配。 |
| P1 | 打印的少量实用控制 | 对方提供每行小节数、局部宽度、缩放、纸张比例、页脚/页码、双面边距等。我们已有自动分行、`{br}`、等宽小节和 A4 分页；行距/页边距等还存在于引擎选项中，用户导出入口主要暴露格式。先补字号/密度、行距/边距、分页预览与必要的手动分页；多页作品再补曲名和页码。保留自动避碰，避免要求用户逐处调坐标。 |
| P1 | 局部循环练习 | 口琴场景独立建议，对方文档不能证明已有同等 A/B 循环。我们已有进度定位和变速，未见选择起止小节并循环的用户入口。先支持指定小节范围、慢速循环和循环前预备拍；已有全曲预备拍无需重做。明确范围按书写小节还是实际演奏遍次解释。 |
| P2 | 滑音、后倚音与部分装饰符号 | 对方有上/下滑音、前/后倚音、上下波音、回音等。M3N 已有长/短倚音和上波音，但未见同等独立后倚音、滑音等表达。按真实口琴曲谱样本选取，优先区分装饰音、滑音和压音；先定义谱面语义，再定义试听行为，避免以任意固定音效冒充演奏技法。 |
| P2 | 复拍子拍感与 Swing | 对方可指定附点拍速、八分/十六分 Swing；我们速度输入为 qpm，谱面按拍号分母换算。建议优先允许 6/8 等选择附点四分音符拍速显示和大拍/细分节拍，降低录谱和跟练时的换算负担。Swing 在爵士/布鲁斯曲目需求明确后加入；显式三连音只能作为局部写法。 |
| P2 | 演奏顺序检查视图 | 对方试听窗口能按反复迭代数显示所含小节。我们已有统一顺序语义和播放高亮，可加轻量“实际演奏小节/乐段顺序”供校对。比增加一套复杂条件反复规则更切合旋律制谱。 |
| P3 | 外部乐谱互通 | 不是本次对方文档证明的差距。现有普通文件导入面向 M3N，另有 Happi123 转换页；不等于具备 MusicXML/MIDI 导入。仅在用户有大量现成电子谱时优先考虑，并显示歌词、装饰和结构等转换损失。MIDI 下载也要区分内部 MIDI 生成与公开下载入口。 |

P1 项之间也有先后：先做打印和可手填的口琴标注；确认琴种后做音域检查；练习功能随后接入。若产品主要面向熟练读简谱的半音阶口琴演奏者，孔位显示应是可关闭的教学层，不应强占主谱。

自动孔位生成必须允许人工修改：同音可能存在多个孔位/吹吸/推键组合，“能发出这个音”与“适合这个乐句”是不同问题。仅检查音域也不能宣称整首可奏；十孔缺音、和音可奏性、连续吹吸和技法难度须另评估。

不建议近期追齐：任意多声部、鼓点声部、24 平均律微分音、自由念白、整本教材排版、全量字体系统、复杂全局条件反复和桌面客户端。已有低音/和弦可继续维护，不必扩张成通用合奏编辑器。若未来明确服务口琴重奏或乐团，再重新评估多声部。

## 文档差距与改进

### 1. 缺少产品使用流程

我们的指南直接从 `N:` 开始，主要教语言；对方引入页说明用途、如何开始和学习路径，并在教程中穿插编辑器定位、刷新、结构检查等操作。

建议在指南开头新增“十分钟完成第一份口琴谱”：打开编辑器 → 改写一个短例 → 试听校验 → 保存 → 下载 M3N → 导出 PDF。每一步写明操作位置、预期结果和常见失败原因。现有语法内容继续保留。

本地保存、草稿和临时分享的区别必须进入用户指南：作品存于当前浏览器；清理浏览器数据会丢失；临时链接保留 15 天；跨设备保管需下载源文件。这些信息目前主要在开发 README 中。

### 2. 缺少口琴定位与专门教程

首页称“面向旋律制谱”，指南也多为通用记谱，用户难以看出为什么适合口琴。

补充：如何选调与读首调、何时用固定 C 调、如何处理超过琴音域的旋律、连奏/同音延续/吐音的区别、何处加换气。先讲已实现的方法；未实现的孔位和压音等不能写成现有能力。

### 3. 复杂概念讲了规则，缺少决策过程

对方经常采用“实际谱例 → 遇到问题 → 修改 → 比较结果 → 练习”的叙述，并专门解释奏法之间的区别及反复遍次的由来。我们的手册规则较清楚，但初学者仍可能不知道什么时候使用它们。

优先补三个完整场景：跨小节延音与连奏的区别；一首歌的主副歌如何选择反复/跳房子/`order`/`Ns`；歌词错位如何逐小节排查。每个场景配少量修改前后例子，保留可试听和试改能力。

### 4. 有排版能力，缺少排版与导出教程

对方用一整章说明分行、间距、字体、分页和打印，也解释为什么某种布局会产生重叠。我们的用户文档只集中说明 `{br}`、段名和等宽小节，缺少导出流程；一些实现能力只在内部渲染文档中出现。

先写已有功能的操作说明：屏幕宽度与打印版宽、连续/分页模式、如何选择 SVG/PNG/PDF、中文字体首次下载与失败重试、密集小节和多行歌词如何调整。新增 UI 控件后同步加例子，不把内部 TypeScript 参数当成用户已可用的设置。

### 5. 需要面向症状的排错与语义说明

现有手册 §11 按错误类别归纳，适合查约束。再补一张“症状 → 原因 → 最小修正”表：小节不满拍、歌词数量不符、`---` 没换行、第二遍结尾不同、点了固定调但声音未变化、文件未保存到另一设备等。

特别解释三组区别：源码 `{key=...}` 与阅读界面移调；界面移调与固定 C 调显示；打印符号与实际试听效果。不要用“有这个符号”暗示播放器一定模拟了相应口琴技法。

还应明确小调唱名约定：M3N 当前手册把数字解释为当前调式音级，`{key=Am}` 下的 `1` 是 A；对方教程采用常见的“小调主音记为 6”思路。移植曲谱时不能直接替换调号。这是需要实例解释的产品约定，不应悄悄当作两者完全兼容。

### 6. 导航已有基础，下一步是缩短查找路径

我们已有指南/手册分层、目录和锚点，不能概括为“没有文档导航”。对方有细分主题页、上一页/下一页和独立记号速查表；我们当前主要是两篇长文，也未见文档全文搜索入口。

建议先加一页按需求分组的速查表，例如“写高音”“少半拍”“第二遍改结尾”“加换气”“导出打印”，每项连到现有章节；再加入上一主题/下一主题与文档全文检索。使用量增长后再按主题拆页，保留旧锚点或重定向。搜索 UI 本身不应被误认为已经具备的能力。

### 7. 保留已有优势，并清楚标注版本与限制

现有谱例可试听、可试改，而且 `src/lib/m3n-docs.test.ts` 校验指南/手册示例与章节链接，应继续保留。未来新增教程和速查表时扩展检查覆盖；推荐补充语义测试证明文档承诺的音高、反复顺序和移调结果，避免只验证“语法能通过”。

对方标注版本、新增/移除特性、常见错误和限制，这种透明度值得借鉴。但其文档也有待整理内容，例如“请输入文本”的占位、“即将到来”与现状并列，以及需要手工避碰的限制。我们宜采用稳定的“当前可用/仅谱面/试听限制”说明，保持文字准确简洁。

## 建议的实施批次

1. **文档优先**：在现有指南中补完整上手流程、口琴使用专题、保存/分享说明、导出教程和常见错误；手册继续承担精确语法查阅。
2. **制谱优先**：增加少量打印设置、逐音口琴标注和明确的谱面图例；以真实口琴短曲验证，随后增加琴型音域检查。
3. **练习与细节**：局部循环、复拍子显示/节拍选择、按需求加入滑音/后倚音，以及实际演奏顺序检查。

口琴新功能的验收应贯穿：源码保存 → 谱面显示 → 手机阅读 → 打印导出；涉及声音时再加试听验证。不要只证明新增指令被解析。
